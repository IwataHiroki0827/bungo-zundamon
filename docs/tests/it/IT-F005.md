# 結合試験仕様書 F005（夏目漱石3作品追加）

## 試験方針

承認snapshot、専用candidate、v0.4.0 baseline、原典・review・音声、ETW容量、作品受入、Catalog/UI、画像、releaseを実moduleとcanonical artifactで接続する。失敗時は公開済みv0.4.0と第三者変更を保護し、手動確認を必須条件にしない。

- 原典結合は固定raw SHA＋fake resolver＋pinned socket/TLS adapterで再現し、live originはQT predeployで再確認する。
- 順位結合は固定2022 raw/拡充CSV SHA、deploy結合はfake DeploymentAdapterを使う。実hosted試験はQT-F005-020だけで行う。
- Git commit試験は固定clock/author/parentの一時bare repo＋worktreeで行い、作業repoを変更しない。
- ETW異常は署名済みraw trace replayと実Windows正常contractを分離し、両方を必要証跡にする。

IT-F005-005のhosted Windows正常系では、root収容後に固定native `--write-through-once` helperを専用Job childとして起動し、書込み前にexact temporary path・active phase・Job producer identityを容量guardへ予約する。`CREATE_NEW | FILE_FLAG_WRITE_THROUGH | FILE_FLAG_DELETE_ON_CLOSE`、同一handle write、`FlushFileBuffers`、length/readback/SHA検証後もchildとhandleを保持する。System SetInfoがJob Createより先着した場合は到着時identity・容量・空き容量・ETW連番を封印し、同一FileObject・path・process世代・identity・QPC順序の後着Createでだけ保留解除して観測へ再投入する。Cleanup後pointer再利用または未一致は停止する。create noticeのETW認証後、delete-on-closeを維持した同一handleで最終名へrenameし、rename noticeの認証後だけ`FileDispositionInfoEx(ON_CLOSE)`で解除してcommitする。helper終了・ETW drain・same identity再照合後に予約を閉じる。callback前にhelperが正常終了した場合は保持handleのsignaled状態と固定process identityで遅延eventを認可する。応答前kill、rename後EOF、notice失敗は同じnative identityだけをclose時回収し、commit済みartifactの後続失敗は返却identityを期待値にしたsame-handle deleteだけを許す。staging rootのpathname再帰削除は禁止し、置換root・第三者entryはfail-closedで残す。

同じhosted正常系では、同一handle renameの直前にcurrent pathとexact target pathをguardへ予約する。target不在と結合済みproducer generation・FileObject・identityを確認し、予約後QPCのtarget System SetInfoだけを許可する。rename通知が予約済みfrom/toと一致した後だけlease pathを更新し、target予約QPCを新current pathの下限へ昇格する。通知後に遅延到着した予約前event、別target、target既存、二重予約、未消費予約でのcompleteは停止する。

hosted停止時はnative helper固定replyを6カテゴリの`causeCode`へ分類し、Win32番号・path・自由文をannotationへ含めない。分類不能値はprotocolへ集約し、失敗時のcandidate保存と公開を実行しない。

hosted正常系はworkspace内で再現buildしたnative binaryをevidence SHA照合後にRUNNER_TEMPのGUID付き新規directoryへ複製し、outside、reparse、hardlink数、copy後SHAを再確認してから容量guard、write helper、directory flush、acceptance clientの全経路へ同じexplicit executableを渡す。各processのhello self hashも固定pinへ一致させる。tooling startup metadataはworkspace ETW対象外、candidate/audio/stagingは対象内であることを確認する。

上記全native経路はexternal executable parentをcwdとして起動し、hello cwd一致booleanを検証する。容量phase中のwrite helper spawnでworkspace rootにtooling由来mutationが発生せず、artifact operationへ渡すworkspace rootとETW監視rootは不変であることを確認する。

hosted安全停止時のunknown System SetInfoは固定bucket codeだけを公開し、raw pathをworkflow log/annotation/summaryへ出さない。診断追加前後でcandidate保存、public/data差分、ETW認可結果が不変であることを確認する。

予約済みwrite path認識後の相関不一致は固定12段階の`causeCode`だけを公開し、相関対象のpath、FileObject、identity、sequence、QPCを出力しない。診断追加前後でcandidate保存、public/data差分、認可結果が不変であることを確認する。

voice phase中のleaseなしCACHE WAV System SetInfoは、完了済みwrite台帳とのidentity関係を固定3状態だけで公開する。別path、同名差替え、欠落を区別しつつraw値を出さず、診断追加前後でcandidate保存、public/data差分、認可結果が不変であることを確認する。

完了済みCACHE WAVと同一identityの遅延System SetInfoは、同一phase/path、予約後かつwrite完了以下のQPC、互換FileObject binding、System PID、setinfo、元worker sequenceを完全照合してETW観測へ再投入する。別tupleは固定診断で停止し、候補を保存しない。再投入直前にもidentityを照合し、容量・ETW sequence・notice完結を通常経路と同じ規則で検証する。

次active leaseがclosed状態でも、前完了write pathの遅延eventはactive reservation tuple不一致として完了write fallbackへ流す。当該active pathの一致eventだけは`LEASE_CLOSED`で停止し、異なるleaseへPID/sequenceを誤結合しない。

完了write fallbackで安全停止する場合は固定10 stageの1つだけをworkflow annotationへ公開し、raw path/identity/FileObject/QPCを出さない。診断追加前後で再結合認可、容量、候補保存結果が不変であることを確認する。

完了後stageは固定5時間差bucketの1つだけをnativeからrunnerまで保持する。未知bucketをgenericへ閉じ、完了QPC上限、first-poison、容量、候補保存結果を変更しない。

hosted実測済み500ms以内のSystem SetInfoだけを完全tupleへ再結合し、500ms超、別path/identity/FileObject、TOCTOU差替えは固定codeで停止する。認可eventは容量actualへ算入し、候補保存前のidentity検証を維持する。

hostedで追加観測した2秒以内の完全tupleだけを再結合する。2秒+1 tick、別tuple、identity差替えは停止し、時間上限変更前後で容量actualと候補identityの意味を維持する。

active lease closed停止は固定5 stageだけをnativeからrunnerまで保持し、raw値を公開しない。診断追加後もclosed eventを容量actualへ算入せず候補保存へ進めない。

closed lease完全候補はsnapshot identityを認可時と容量観測直前に二重照合し、元helper世代へ再結合して容量actualへ算入する。他4 stageとTOCTOU差替えは停止し、候補保存へ進めない。
