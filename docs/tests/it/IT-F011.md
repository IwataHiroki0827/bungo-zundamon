# 結合試験仕様書 F011（新美南吉3作品追加、10人目・最終）

## 1. 試験方針

F011の結合試験は、既存の汎用結合フロー（IT-F003〜IT-F010の該当シナリオ）がgeneric batch pipelineとして既に検証済みである範囲は簡潔に引用し、F011固有の結合シナリオ（新規作者・3作品の順次atomic受入、v0.10.0固定baselineへのCatalog統合、既存9作者30作品との共存、gaiji要素検出の全文0件回帰、長大候補分割の非実装確認、作品固有注記UIの3作品全件不在確認、proofreader単一値/複数値混在の結合結線、新規5モジュールの結合、10作者到達・拡充directive完了記録）に絞って詳細化する。失敗時に旧公開（v0.10.0）と第三者変更を保護することを各シナリオの共通条件とし、手動確認を必須条件にしない。

F011はF010と3点で構造が異なり、いずれもF010の該当シナリオを単純転用しない。

- **IT-F011-006**は、notice表示の陽性ケースではなく、3作品全てで`official-content-warning`が表示されず`dialogue-excerpt-scope`のみが表示される**notice不在（陰性）ケース**として設計する（F010と同型の2度目の非該当バッチ）。authorId `000121`について、Catalog統合後の3作品route・全配置（work-list/work-detail/credits）のいずれにも`official-content-warning`のnotice要素が一切出現しないことを明示的にDOM走査で確認する。
- **IT-F011-003**は、分割発動ケースではなく、F011実candidate（最大228文字）に対し分割関数自体が存在せず候補が単一のまま不変であることを確認する**分割非実装ケース**として設計する。
- **IT-F011-004**は、F010までの単一値proofreaderの結合確認に加え、二ひきの蛙の複数値proofreader（もりみつじゅんじ・鈴木厚司）が原典固定からcredits表示までの結合経路で欠落なく保持されることを確認する**proofreader単一値/複数値混在の結合確認**を含む点でF010の該当シナリオより一段詳細化する。
