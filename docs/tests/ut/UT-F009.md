# 単体試験仕様書 F009（夢野久作3作品追加）

## 試験方針

- `DD-F009.md`の`FUN-F009-001`〜`FUN-F009-017`を1件ずつ網羅する。
- DD-F009.mdの各FUN本文を実際に精査した結果、17件中7件（FUN-F009-001/007/008/009/013/016/017）は「新規コードなし」と明記され既存関数をそのまま呼び出す設計であり、既存のUT-F002〜F008が同一関数を汎用入力（feature非依存の値）で既に網羅している。これら7件は本書で新規UTケースを追加せず、対応する既存テストファイルを引用して「既存テストでカバー済み」と明記する。F009固有の値（authorId `000096`・workId `002381`/`046694`/`002380`）での結合確認はIT-F009側で行うため、本書のUTレベルでは重複させない。
- 残る10件（FUN-F009-002/003/004/005/006/010/011/012/014/015）はfeature固有のexact値・新規モジュール（`f009-baseline.ts`・`f009-source.ts`・`f009-acceptance.ts`・`f009-catalog.ts`・`f009-artwork.ts`）であるため、UT-F007/F008の粒度（正常・境界同値・異常系）を踏まえつつ過剰に複雑化しない範囲で新規UTケースを作成する。ETW常時監視・native guard起因の複雑な境界（F005系）はF009では不採用のため対象外。
- caller供給のPASSや自己申告identityを信用せず、canonical原artifact・Approved文書・実体hashからoracleを再計算する。手動・目視・聴取を正式PASS条件に含めない。
- **gaiji要素検出（FUN-F009-006、DES-F009-005の新規論点）**: F005〜F008の採用9作品では`<img class="gaiji">`要素が一度も検出されなかったのに対し、F009は瓶詰地獄（4件）・死後の恋（2件）の地の文に実在するgaiji要素を検出経路へ初めて実データとして流す。`detectF009GaijiElements`（byte offset集合の全件収集）と`verifyNoGaijiWithinCandidates`（候補`rawTokenRange`との区間重なり判定）を、gaiji候補外・gaiji候補内混入・gaiji0件（既存作品相当の回帰baseline）の3パターンで新規UTケース化する。
- **長大候補分割の実発動（FUN-F009-006、DES-F009-015）**: UT-F007-006・UT-F008-006ではいずれも合成fixtureの600/601文字境界でしか分割ロジックを検証できなかった（実candidateで分割が発動した例が過去に一度もない）。F009は死後の恋の1候補が選定時実測で正規化前1,748文字（600文字閾値・1,335文字実測失敗境界のいずれも超過）であることが判明しており、実データに対して分割が実際に発動する初のケースである。UT-F009-006は合成600/601文字境界ケースに加え、実際に取得・永続化済みの死後の恋raw XHTML（またはその該当箇所を抽出した固定fixture）を用いた1,748文字実candidateの分割検証caseを追加し、複数piece生成・order 0..N-1再採番・`sourceAnchor`/`rawTokenRange`/`rawSourceSha256`の分割元同一性を実データで確認する。
