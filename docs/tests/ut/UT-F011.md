# 単体試験仕様書 F011（新美南吉3作品追加、10人目・最終）

## 試験方針

- `DD-F011.md`の`FUN-F011-001`〜`FUN-F011-018`を1件ずつ網羅する。
- DD-F011.mdの各FUN本文を実際に精査した結果、18件中8件（FUN-F011-001/007/008/009/013/016/017、および分割非実装を明示するFUN-F011-018本体の「新規コードなし」部分）は「新規コードなし」と明記され既存関数をそのまま呼び出す設計であり、既存のUT-F002〜F010が同一関数を汎用入力（feature非依存の値）で既に網羅している。これら8件は本書で新規UTケースを追加せず、対応する既存テストファイルを引用して「既存テストでカバー済み」と明記する。F011固有の値（authorId `000121`・workId `000637`/`000628`/`004718`）での結合確認はIT-F011側で行うため、本書のUTレベルでは重複させない。
- 残る10件（FUN-F011-002/003/004/005/006/010/011/012/014/015）はfeature固有のexact値・新規モジュール（`f011-baseline.ts`・`f011-source.ts`・`f011-acceptance.ts`・`f011-catalog.ts`・`f011-artwork.ts`）であるため、UT-F009/F010の粒度（正常・境界同値・異常系）を踏まえつつ過剰に複雑化しない範囲で新規UTケースを作成する。ETW常時監視・native guard起因の複雑な境界（F005系）はF011では不採用のため対象外。
- caller供給のPASSや自己申告identityを信用せず、canonical原artifact・Approved文書・実体hashからoracleを再計算する。手動・目視・聴取を正式PASS条件に含めない。
- **F011はF010と3点で構造が異なる。以下の3ケースはF010の該当ケースを単純に転用せず、F011固有の実データ・スキーマ拡張に合わせて設計し直した**（DD-F011.md §0・§1・§6明記）。
  - **notice（作品固有注記UI）は3作品とも`official-content-warning`が0件**（F010と同型、2度目の非該当バッチ）。UT-F011-011は`official-content-warning`が**表示される**ケースではなく、3作品全てで**表示されない**（`dialogue-excerpt-scope`のみ保持する）ことを確認するnotice不在ケースとする。
  - **長大候補分割（`splitOverlongF00NCandidates`型）はF011では複製・実装しない**（DES-F011-005・DES-F011-015、実測最大候補長228文字＜600文字閾値）。UT-F011-006は「分割が実際に発動する」ケースではなく、`extractF011DialogueCandidates`が分割ロジックを持たないことおよび実測最大候補228文字・合成600文字超fixtureのいずれを与えても分割せず単一candidateのまま扱われる（後段の単一候補上限判定で拒否される想定）ことを確認する**分割ロジック不在（no-op）ケース**とする。
  - **`proofreader`が初めて複数値を取り得る（配列schema拡張）**。UT-F011-005は、手袋を買いに（校正=伊藤祥、単一値）・ごん狐（校正=浜野智、単一値）・二ひきの蛙（校正=もりみつじゅんじ・鈴木厚司、複数値併記）の3ケースを同一canonical schemaで正しく保持できることを確認する**単一値/複数値混在ケース**とする。
- **gaiji要素検出（FUN-F011-006、DES-F011-005）**: F011は3作品とも全文走査でgaiji要素0件・未定義entity0件という初めての「全件無検出」ケース（F009=2作品、F010=1作品で実在確認と異なる）。UT-F011-006は3作品の0件回帰ケースを含みつつ、検出関数自体が無条件で常時適用されること（実測0件を理由に検出手順自体をスキップしないこと）を確認する。
