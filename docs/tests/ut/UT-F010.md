# 単体試験仕様書 F010（梶井基次郎3作品追加）

## 試験方針

- `DD-F010.md`の`FUN-F010-001`〜`FUN-F010-018`を1件ずつ網羅する。
- DD-F010.mdの各FUN本文を実際に精査した結果、18件中7件（FUN-F010-001/007/008/009/013/016/017）は「新規コードなし」と明記され既存関数をそのまま呼び出す設計であり、既存のUT-F002〜F009が同一関数を汎用入力（feature非依存の値）で既に網羅している。これら7件は本書で新規UTケースを追加せず、対応する既存テストファイルを引用して「既存テストでカバー済み」と明記する。F010固有の値（authorId `000074`・workId `000424`/`000419`/`000411`）での結合確認はIT-F010側で行うため、本書のUTレベルでは重複させない。
- 残る11件（FUN-F010-002/003/004/005/006/010/011/012/014/015/018）はfeature固有のexact値・新規モジュール（`f010-baseline.ts`・`f010-source.ts`・`f010-acceptance.ts`・`f010-catalog.ts`・`f010-artwork.ts`）であるため、UT-F008/F009の粒度（正常・境界同値・異常系）を踏まえつつ過剰に複雑化しない範囲で新規UTケースを作成する。ETW常時監視・native guard起因の複雑な境界（F005系）はF010では不採用のため対象外。
- caller供給のPASSや自己申告identityを信用せず、canonical原artifact・Approved文書・実体hashからoracleを再計算する。手動・目視・聴取を正式PASS条件に含めない。
- **F010はF009と2点で構造が異なる。以下の2ケースはF009の該当ケースを単純に転用せず、F010固有の実データ・非発動方針に合わせて設計し直した**（DD-F010.md §0・§6明記）。
  - **notice（作品固有注記UI）は3作品とも`official-content-warning`が0件**（F009はきのこ会議1作品のみ0件・瓶詰地獄/死後の恋2作品はwarningあり）。UT-F010-011は`official-content-warning`が**表示される**ケースではなく、3作品全てで**表示されない**（`dialogue-excerpt-scope`のみ保持する）ことを確認するnotice不在ケースとする。
  - **長大候補分割（`splitOverlongF009Candidates`型）はF010では複製・実装しない**（DES-F010-015、実測最大候補長133文字＜600文字閾値）。UT-F010-006は「分割が実際に発動する」ケースではなく、`extractF010DialogueCandidates`が分割ロジックを持たないことおよび合成600文字超fixtureを与えても分割せず単一candidateのまま扱われる（後段の単一候補上限判定で拒否される）ことを確認する**分割非発動（防御的no-op）ケース**とする。
- **gaiji要素検出（FUN-F010-006、DES-F010-005）**: 檸檬の地の文には`<img class="gaiji">`要素が実測で1件存在する（「闊」の異体字、DOMAIN-F010.md §5）。UT-F010-006はこの実データを用いた回帰ケース（候補外1件検出、work非block）と、Ｋの昇天・愛撫の0件回帰ケース（既存作品相当のbaseline、F009のきのこ会議0件回帰ケースと同型）を含む。
