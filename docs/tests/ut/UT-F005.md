# 単体試験仕様書 F005（夏目漱石3作品追加）

## 試験方針

- `FUN-F005-001`〜`FUN-F005-048`を各1ケース以上で直接網羅する。
- 上限同値/+1、欠落・重複・改変、SSRF、entity/PNG decode、Windows reparse、journal停止、commit差分混入を固定fixtureで自動検証する。
- caller供給の承認・SHA・PASS・容量値・pathを信用せず、Git object、canonical artifact、ETW、実体hashからoracleを再計算する。
- 手動・目視・聴取を正式PASS条件に含めない。
- 各表行のサブケースは独立TestResultを持ち、未実施・PASS・FAILを個別記録する。拒否系の共通oracleは固定error code、外部request 0、before/after tree SHA一致、journal state/seal、canary SHA、再試行回数を記録する。

## 決定的テストハーネス

- ETWのloss/gap/process generation/Job異常は、production buildへexport・注入できないtest-only replay decoderへ署名済みraw ETW fixtureを入力し、native guardと同じparser/state machineを検査する。実Windows contract試験では実Job Object、System IO Provider、Microsoft-Windows-Kernel-Processの`ProcessSequenceNumber`と同一QPC境界、root実動probe、kill-on-close、保持handleのProcessTelemetryIdInformation/file identity取得、任意event key照合、正常buildを確認する。replay試験と実contract試験の両方がPASSしなければ正式PASSにしない。
- Git migrationは作業repoではなく、一時ディレクトリに作る固定clock・author・parent・file modeのbare repo＋worktreeで行う。各case後にhandleを閉じて一時repoだけを削除し、作業repo HEAD/index/worktree SHAが前後一致することを確認する。
- transportは固定raw fixture、fake resolver、pinned socket/TLS adapterで攻撃matrixを再現し、live公式originの再確認はQT predeployへ分離する。
