# CHG-F003-004: F003公開5 routeのpublished遷移を受理

| 項目 | 内容 |
|---|---|
| 発生日 | 2026-07-26 |
| 起票契機 | v0.3.0公開成功後、F003 manifestのpublished遷移前検査がF002の4 routeへ固定されていることを検出 |
| レベル | implementation |
| 状態 | done |

## 変更理由

公開サイトと公開後スモークは5 routeでPASSしたが、`recordPublishedBatch`のroute集合検査がF002の4 routeだけを許可していた。このままではF003 manifestを`accepted`から`published`へ遷移できず、次batchの前提が閉じない。

## tm.jsonによる影響範囲

起点は`DES-F003-009`、`DES-F003-012`、`FUN-F003-022`、`FUN-F003-029`、`UT-F003-022`、`UT-F003-029`である。直接影響は`src/content/batch.ts`、`src/content/batch.test.ts`、`src/content/f003-catalog.ts`、`src/content/f003-catalog.test.ts`、`src/content/batch-runtime.test.ts`、F003リリースタスク`T-044/T-048`である。要求・設計・公開サイトの内容は変更しない。

## 変更内容

- release featureごとに許可する公開route集合を明示し、F002の4 routeとF003の5 routeを区別する。
- F003の正確な5 routeだけを受理するpublished transaction試験を追加する。
- 未知feature、欠落、余剰、重複、別作者routeは従来どおりfail-closedで拒否する。
- 公開後のcanonical `published` manifestを、固定Catalog復元処理がaccepted済み入力として受理する。
- 実manifestを再利用するrights-stage fixtureからpublish専用項目を除き、公開後もdraft状態を正しく再構成する。
