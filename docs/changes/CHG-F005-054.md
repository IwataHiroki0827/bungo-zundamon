# CHG-F005-054 T-112決定的hosted相関検証

## 変更理由

Q-043で、後続fail-closed guardを含む現行Program pinによるT-112 follow-up productionを3 attempt実行しても、前段handoff多重固定codeで安全停止し、不変binding proof・retained identity再生後段へ到達しなかった。自然なETW配送順への追加依存では有限回のhosted影響確認を保証できない。

プロジェクトオーナーの継続指示を安全側へ限定し、T-112のproof、retained identity、認可、capacity、semantic state、候補保存、公開条件を変更せず、同じproduction assemblyの既存ledger/replay規則を直接実行する決定的hosted相関試験へ置き換える。

## 変更内容

### 1. production共有規則を使うT-112 target suite

ProjectReference生成されたproduction assemblyの`WriteCompletionCallbackAdmission`、`ImmutableBindingProof`、`WriteCompletionBindingLedger`、`WriteCompletionReplayStore`、`WriteCompletionAtomicBatchRules`を直接使うtarget `CHG-F005-038/T-112`を追加する。production規則の複製、test-only production分岐、条件付きコンパイル、guardのIPC・環境変数・command line入口追加は禁止する。

現在private nestedの`RetainedFileIdentity`と`RetainIdentity`のhandle open/初回検査を、production-owned internal `CapacityGuardSession.RetainedFileIdentityLease.OpenVerified`へ抽出する。productionは従来と同じroot containmentとlive handle上限確認後にこのfactoryだけを呼ぶ。factoryはdesired access 0、share read/write/delete、`OPEN_EXISTING`、`BACKUP_SEMANTICS | OPEN_REPARSE_POINT`でactual handleをexact 1件開き、実handleのreparse属性・hardlink数1・volume/FileId128とexpected identityを検査してから所有権を返す。失敗・部分取得はfactory内でdisposeし、`Reinspect`とidempotent `Dispose`をproductionとtargetが共有する。固定例外は既存`EVENT_IDENTITY_FAILED`とし、capacity、認可、proof、semantic stateは変更しない。

固定manifestは、admissionのread→writer待機→新read遮断と解放、baseline generation 0/1・cursor 0、sealed-current/parent、other-bound bootstrap/rebind/rename、delete→Cleanup/Cleanup→delete、duplicate、FileObject再利用後Cleanup拒否、proof欠落・重複・順序逆転・generation gap・canonical改変を個別caseにする。replayはproof順、preflight後のatomic apply/commit、cursor/head収束を固定する。

atomic失敗matrixは後半proof、retained handle identity、producer process、capacity、notice、apply、ledger commitを各1件失敗させる。各caseでadmission head、applied cursor、ledger generation/state、queue/cleanup、generation handles、`filesByObject`/`filesByPath`、notice、Observation、allocated/peak/free、seal、leaseの全checkpointが不変で、取得handleだけが所有者規則どおり解放されることを要求する。

上限はledger entries、admitted proofs、pending snapshots、tracked cleanups、generation handlesを各8,192/8,193、sealを128/129、seal handlesを256/257、live retained handlesを8,448/8,449で個別に固定する。`proofSequence`、generation、normal/cleanup relevant/accounted counterのchecked overflowを別caseにする。baseline/partial handle取得失敗、prepare poison、seal release、phase release、session abort/close、admission/store disposeを各所有者でexactly onceかつ二重dispose安全として検査する。

targetは共有`RetainedFileIdentityLease.OpenVerified`をRUNNER_TEMPの実file/directoryで直接実行する。open flags、安定identity、rename/delete後の同一handle再inspection、path差替え後も元handle identity保持、hardlink/reparse拒否、expected identity差、closed handle、初回失敗・通常解放・二重disposeを固定する。private Job fixtureのalive/signaled/別generation/Job外も結合する。

構造試験はproductionのprepareがcallback admission writer→gateでbaselineを作り、callback/Cleanupが同じledger/storeへproofを入れることを検査する。T-112の検査閉包を`ReplayWriteCompletionQueueLocked`、normal/post-request completionの`PreflightCallbackSnapshotLocked`、`PreflightImmutableRejoinLocked`、`RecheckSealedCallbackLocked`、`ApplyCallbackSnapshotLocked`、`ApplyPreflightedCallbackSnapshotLocked`、`ApplyCallbackSnapshotCoreLocked`のbinding proof/retained generation branch、`CompleteWrite`、`EndPhase`へ限定する。この閉包で`TryInspect(path)`や`filesByObject`/`filesByPath`の読取りを認可・proof・identityの入力へ再導入しないこと、semantic map書込みはproof/retained identity通過後だけであること、proof→identity→process→capacity→notice順でfail-closedすることを固定する。

CHG-F005-035/036の`TryAuthorizeBoundLeaseDirectoryWriteLocked`、`RecheckBoundLeaseDirectoryTupleLocked`、`TryAuthorizeAfterLeaseReservationDirectoryWriteLocked`、`RecheckAfterLeaseDirectoryRejoinLocked`はT-109/T-110固有の承認済みtuple再照合allowlistとする。これらがdirectory/lease/pending targetの`TryInspect`とsemantic bindingを既存回数・順序で使用する契約は変更しない。`ApplyCallbackSnapshotCoreLocked`内の既存`AfterLeaseDirectoryRejoinContext` guarded branchから`RecheckAfterLeaseDirectoryRejoinLocked`をexact 1回、既存`BoundLeaseDirectoryRejoinContext` guarded branchから`RecheckBoundLeaseDirectoryTupleLocked`をexact 1回呼ぶ経路だけはT-112 replay閉包内の明示allowlistとし、guard外呼出、回数・順序変更、他methodからの新規呼出・拡散を拒否する。各allowlist method内部へT-112の可変再認可禁止assertは適用しない。

### 2. read-only hosted evidence契約

既存target selectorへT-112を追加し、今回の`.github/workflows/f005-hosted-native-probe.yml` self-pathではT-112だけを選択する。T-110 57 caseとT-122 43 caseのselector経路・local無縮退試験を維持する。workflow全体`actions: read`/`contents: read`、checkout credentialなし、push・artifact uploadなし、RUNNER_TEMP raw stdout/stderr各65,536 bytes上限、未知・重複・欠落marker拒否を維持する。

canonical evidenceはCHG-F005-053と同じschema、source/build/selector/manifest、実load production/test assembly SHA・MVID、test executable、SDK/runtime、kernel ETW、runner、件数、Pages tupleを縮退なく維持する。固定`pages.yml`、`event=push`、同一head SHAのexact 1 terminal run/attempt、deploy exact 1件`skipped`をbounded pollし、欠落・多重・timeout・head差・job異常は固定codeでFAILする。PID、path、FileObject、generation、identity、handle、stack、自由文はcanonical evidenceへ含めない。

### 3. T-112 hosted影響判定

次を全て満たす単一source commitのcanonical evidenceでT-112のhosted影響をPASSとする。

1. pinned native guard buildとkernel ETW preflightがPASSする。
2. 固定manifest SHA、期待件数、PASS件数が一致し、実load production/test assembly SHA/MVIDをsource/build/runner tupleへ結合する。
3. admission、ledger generation/state、Cleanup再利用拒否、proof検証、atomic replay/rollback、上限・overflow・disposeがproduction共有規則で期待結果へ排他的に収束する。
4. production構造が不変proof/retained handleを正本とし、可変path/map再認可、test-only入口、後段fall-throughを持たない。
5. raw値非公開、tracked出力差分0、candidate branch不存在、同一SHA Pages deploy `skipped`を確認する。
6. workflowがread-onlyでcredential、push、artifact uploadを行わず、T-110/T-122 selector経路もlocalで無縮退である。

この証跡はT-112不変binding proof・retained identity再生のhosted影響確認にだけ使用し、production end-to-end成功、候補受入、capacity actual、公開判定の代用にはしない。

## 試験方針

- manifestのcase ID、順序、件数、SHAを固定し、欠落・余分・重複・順序差・偽PASS markerを拒否する。
- ledger/admission/replay/atomic batch、production-owned retained identity lease、各上限・overflow・ownershipの全境界と失敗時state非変更をproduction assemblyへ直接投入する。
- production構造、外部固定code、raw非公開、read-only権限、candidate/Pages非公開を検査する。
- local native通常suite、T-110/T-122/T-112 target、関連Vitest、typecheck、ESLint、trace_check、同一SHA再現build2回、独立受入後にhosted targetを実施する。

## 承認

既承認の要求・proof・retained identity・認可・capacity・semantic state・候補保存・公開条件を変更せず、hosted影響確認の試験方法だけを決定化するdesign-level変更である。要求承認ゲートは設けず、独立レビュー、T-128実装、local/hosted影響試験完了まで`in-review`を維持する。

## 独立設計レビュー

初回レビューはHigh 1 / Medium 3 / Low 0であった。production privateのretained handleを汎用fixtureで代用していた点、replay構造検査のmethod閉包不足、atomic失敗matrixの縮退、上限・overflow・ownership軸の曖昧さを修正した。production-owned internal retained identity lease、全checkpoint rollback、軸別上限・解放経路を設計へ追加した。

再レビューではT-109/T-110固有の承認済みtuple再照合とT-112可変再認可禁止の範囲矛盾を検出した。T-112閉包をnormal/post-request replayへ限定し、`ApplyPreflightedCallbackSnapshotLocked`と`ApplyCallbackSnapshotCoreLocked`を含め、Core内の既存2 context guarded branchから各recheck exact 1回だけをallowlist化した。最終再レビューはHigh 0 / Medium 0 / Low 0でPASSし、trace_checkは`対応漏れなし: OK`である。
