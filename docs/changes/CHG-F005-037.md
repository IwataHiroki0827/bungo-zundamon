# CHG-F005-037 write completion drainのevent-time sealed tuple決定化

## 変更理由

commit `e4fb086fdc1da4cbafd81221086b832938eb4047`のActions run `31042915405`は、同一source SHAの3 attemptで`SYSTEM_DIRECTORY_ACTIVE_LEASE_WRITE_REJOIN_LEASE_CLOSED`、`SYSTEM_PROCESS_BOUND_FILE_OBJECT_REJOIN_LEASE_MISSING`、`SYSTEM_DIRECTORY_BOUND_LEASE_WRITE_REJOIN_LEASE_BINDING_MISMATCH`へ分岐した。native probeとlocal完全tuple試験はPASSしているため、同じFileIOがETW callbackへ配送された時点のmutable lease状態により異なる既存診断へ入るhosted raceである。個別診断の認可追加を続けず、write completion前後の状態とevent-time tupleを封印して決定的にdrainする。

## 予定変更

`MutationNotice(rename)`がmatchedになった後、helperの`write-commit`より前に、認証済みroot clientだけが呼べるprivate IPC `prepareWriteCompletion`を追加する。次の完全tupleを同一lock内で順に検証し、一回限りの`WriteCompletionDrainSeal`を作成する。

1. active phaseが`voice`でwork ID/phase instanceが一致し、root clientが同じ保持handleでaliveかつJob memberである。
2. active leaseが同一参照、同一phase、target current path、open、pending rename path/予約なしである。
3. lease snapshot/current native identity、lease FileObject binding path/identity、target parent directoryのsnapshot/current identityと同一phase root owner/activityが一致する。
4. retained producer handleのPID、`ProcessStartKey`、`ProcessSequenceNumber`がlease保存値と一致し、identity→wait→Jobの順で非signaledかつJob memberである。
5. sealにはphase/work/lease参照、current path/parent bucket、snapshot/current/binding identity、lease FileObject、producer tuple、`CurrentPathReservedAtQpc`、`PreparedAtQpc`、作成時`etwRelevantEventCount`だけを内部保持する。`PreparedDeadlineQpc = PreparedAtQpc + Stopwatch.Frequency * 10`をchecked演算で固定する。`completeWrite`要求を受けた同一lock内で、helper正常exit後の`CompletionRequestedAtQpc`と`DrainDeadlineQpc = CompletionRequestedAtQpc + Stopwatch.Frequency * 10`を一度だけ追加封印する。raw値はjournal、IPC reply、annotationへ出さず、replyのexact key集合は`ok`、`state`、`sealSequence`、値は`true`、`completion-drain-prepared`、phase内で単調増加するopaque正整数だけにする。requestのexact key集合は既存認証付与後の`authToken`、`op`、`path`、`phase`、`phaseInstanceId`、`producerPid`、`sessionNonce`、`workId`とする。

voice phaseは直列writeごとにsealを作り、phase内で最大128 seal、1 sealあたり最大64 event、phase全体で最大8,192 eventへ固定する。次writeの`CurrentPathReservedAtQpc`は直前sealの`CompletionRequestedAtQpc`より大きいことを必須とし、各epochを`CurrentPathReservedAtQpc < event QPC <= CompletionRequestedAtQpc`の非重複半開区間にする。seal状態は`prepared → completion-requested → completed-retained → released`の一方向だけとし、各遷移は一回限りにする。完了済みsealはphase終了まで保持するが、`prepared`または`completion-requested`は同時に1件だけとする。二重prepare、`prepared`以外からのcomplete、二重complete、完了後complete、epoch重複は`F005_ETW_WRITE_COMPLETION_DRAIN_STATE_CHANGED`で停止する。phase/seal/event上限超過は`F005_ETW_WRITE_COMPLETION_DRAIN_BUFFER_LIMIT`で停止する。

timeout判定には壁時計を使わずStopwatch QPCだけを使う。`prepared`では各関連callback、`completeWrite`、`endPhase`のlock取得直後に現在QPCを検査し、`now <= PreparedDeadlineQpc`だけを継続可、+1 tickを`F005_ETW_WRITE_COMPLETION_DRAIN_TIMEOUT`とする。`completeWrite`が境界内なら同一lockで`completion-requested`へ遷移し、以後は各関連callback、drain各反復、`endPhase`で`now <= DrainDeadlineQpc`だけを継続可、+1 tickを同じtimeout codeとする。consumer fenceとreplayを含む完了処理はDrainDeadline内で終える。`completed-retained`はどちらのdeadline対象にもせず、phase終了fenceだけで解放する。checked加算overflowもtimeoutとしてfail-closedにする。

sealが`prepared`または`completion-requested`の間、対象leaseに関連するSystem PID 0/4の遅延FileIOを即時認可・容量算入・poisonせず、次の全条件一致時だけbounded deferへ封印する。`completed-retained`の単独late eventは未解決queueがない場合に限り、同じseal/identity/process再照合後へ即時適用する。active sealまたは既存queueがある場合は全体順queueへ加える。これにより完了済みlate eventだけで次writeのcreate/renameを不必要にqueueへ持ち越さない。

- authorization failureが`BIRTH_MISSING`、operationが既存で許可された`write`または`setinfo`、event QPCが`CurrentPathReservedAtQpc`より後である。upper boundはhelper正常exit後に封印する`CompletionRequestedAtQpc`とし、replay時に`event QPC <= CompletionRequestedAtQpc`を必須とする。upper bound封印後に到着したeventもevent-timeが同値以下なら同じsealへ戻し、+1 tickは拒否する。
- pathはsealed current pathまたはその既知parent directory、FileObjectは非zeroでsealed lease FileObject/bindingとの既存互換関係を満たす。
- callback時に取得したcurrent native identity、length、allocated length、free bytes、ETW sequenceと、sealed phase/producer tupleの関係が一致する。
- defer上限は1 sealあたり64件、同時active sealは1件、phase全体は128 seal/8,192 event、各active状態のtimeoutは10秒とし、上限超過、未知operation/path、identity取得失敗、不一致、buffer lossは固定codeでjournalをpoisonする。

seal lookupは次の3段階で固定する。第1段のbroad eligibilityは、authorization failureが`BIRTH_MISSING`、PIDが0/4、operationが`write`/`setinfo`、FileObjectが非zero、active voice phaseにsealがあり、pathがいずれかのsealed current pathまたはsealed parent directoryであることだけを判定する。broad候補が0件ならseal処理をせず既存認可・診断へ流す。第2段でbroad候補からevent QPCが各非重複epoch内の候補を選ぶ。exact path/FileObject/identityが同じsealの`CompletionRequestedAtQpc + 1`以後なら`F005_ETW_WRITE_COMPLETION_DRAIN_LATE_EVENT_AFTER_SEAL`、それ以外でepoch候補が0件なら`F005_ETW_WRITE_COMPLETION_DRAIN_EVENT_TUPLE_MISMATCH`とする。第3段でepoch候補へpath/FileObject/current identity/operation/sealed producer tupleを照合し、exact一致が1件だけならqueueへ入れ、0件または2件以上なら`F005_ETW_WRITE_COMPLETION_DRAIN_EVENT_TUPLE_MISMATCH`とする。これにより真に無関係なpathは既存分類を保ち、sealed family内の不一致だけを新規固定codeで拒否する。

TypeScriptのcommit順序を`prepareWriteCompletion → write-commit → helper正常exit → completeWrite`へ固定する。normalize後に`etwRelevantEventCount`を増やした全callbackは、通常観測、bounded defer/reorder queue、固定拒否、process identity probe terminal、journal closed/already-poisoned terminalのいずれか1つへ必ず分類し、callbackの`finally`で`etwAccountedEventCount`をexactly onceだけ増やす。probe terminalとclosed/poisoned terminalは容量・Observationへ算入しない。例外経路は固定拒否へ分類してpoisonした後にaccountedする。最初のdefer発生後は、後続の通常認可eventもObservationへ先行追加せず、phase-wide reorder queueへ同じ上限8,192件の一部として未適用入力snapshotとETW sequenceを保存する。queue中はfiles map、allocated、peak/free、notice、Observationへ副作用を与えず、replay時にseal/epoch/FileObject/producer/retained handleとnative identityを再照合し、checked容量計算後にだけETW sequence順で適用する。

callback入口のnormalize前からaccounted完了までproduction共有`WriteCompletionCallbackAdmission`のread tokenを保持する。`completeWrite`と`endPhase`のfinal区間はgateを持たずにwrite tokenを先に取得し、その後gateを取得する。write token取得後にqueue空・`relevant == accounted`・counter snapshot不変を再確認し、不安定ならstate、pending lease、handle、active phaseを一切変更せず外側の2回flushへ戻る。条件成立後だけcompleteのseal遷移とpending解除、またはphase endのseal/handle解放とactive phase解除を行う。writer待機後は新callback read tokenを遮断するため、replay中到着分をqueue末尾へ入れて再fenceする区間とfinal state mutationの間にcallback admission raceを残さない。

`completeWrite`後もsealとsignaled producer handleをphase終了drainまで保持する。`CurrentPathReservedAtQpc < event QPC <= CompletionRequestedAtQpc`の遅延eventは非重複epochで一意なsealへ戻し、upper bound + 1 tick、別path/FileObject/identity/process世代はsealへ戻さない。phase終了時は全queue解決、追加flush後の`relevant == accounted`とcounter安定を確認し、各sealをstate、directory、current、binding、process identity、process wait、process tuple、signaledの順で再確認してからhandle/sealを破棄する。これによりcallback配送時のpending/closed/missing/binding状態ではなくevent QPCのsealed epochで一意に分類する。

既存のJob/ProcessSequenceNumber、capacity actual、candidate branch、公開条件、notice schemaを変更しない。private IPC以外のproduction APIは増やさず、test injectionや任意PID/path/seal作成APIをproduction buildへ公開しない。

## 実装結果
