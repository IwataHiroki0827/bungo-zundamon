# CHG-F005-076 作品横断で共有される音声をfragmentで一意化する

## 変更理由

最終Catalog統合が次で停止した。

```
F005CatalogError: fragment内IDまたはsource provenanceが重複しています
```

`projectF005CatalogFragment` は fragment 内の audio ID が作品をまたいで
一意であることを要求していた。しかし audio ID は台詞文と voice config から
決まる**内容アドレス**であり、別作品に同一台詞があれば同じ音声を共有する。

F005では倫敦塔の「なぜ」が夢十夜の「なぜ」と同一で、実際に1件共有している
（CHG-F005-073 で受理済み音声の再利用を実装した結果、再生成せず共有された）。

```
000799 62件 / 001076 55件 / 001104 83件
共有: 000799 ∩ 001076 = 1件 (a34ce6ac787a499c…)
```

これは異常ではない。公開済みCatalogにも既に作品横断の共有が1件あり、
`audioAssets` は 662件すべてグローバルに一意で、`candidateIds` に
複数作品の台詞IDが並ぶ形になっている。fragment側の要求だけが実態と
食い違っていた。

## 変更内容

fragmentの `audioAssets` を audio ID で一意化し、`candidateIds` を統合する。
重複時は実体（path・sha256・bytes・durationMs・configHash）の一致を要求し、
食い違えば `同一audio IDで実体が一致しません` として停止する。

```ts
const assetsById = new Map<string, CatalogAudioAssetV2>();
// 同一IDは実体一致を検証し、candidateIdsだけを統合する
```

作品ごとの `audioAssets`（`assertIncludedWork` が検証する範囲）は変更しない。
各作品は自分の台詞が参照する音声を引き続き完全に保持する。

## 影響範囲

- `src/content/f005-catalog.ts` — `projectF005CatalogFragment` の重複検査と集約
- `src/content/f005-catalog.test.ts` — 型キャストの修正のみ
- 受理済み成果物・公開済みCatalog — 変更しない
