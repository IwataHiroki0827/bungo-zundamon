# CHG-F005-063 post-upper binding proof失敗原因の固定診断

## 変更理由

CHG-F005-062のproduction run `31253654035` は、全broad sealがcompletion upperより後だがbinding proofを満たさない `EVENT_TUPLE_LOOKUP_EPOCH_EMPTY_POST_UPPER_PROOF_MISSING_ALL` で安全停止した。生値を公開せず、既存snapshotから不成立原因だけを固定する。

## 変更内容

post-upper sealごとにproduction共有の `LateProofResult` をexact 1回評価する。結果はsuccess、ledger unavailable、current FileObject mismatch、current binding mismatch、parent not unbound、invalidの排他的な値とする。helperは最初に入力整合性を検証し、normalized pathがcurrent/parentのexactly oneでない、current分岐で必要なlease FileObject/generation/identity/pathが欠落・範囲外、または必須参照・predicate入力が矛盾する場合は、ledger状態にかかわらずinvalidを返す。局所優先順をinvalid validation、ledger unavailable、current FileObject mismatch、current binding mismatch、parent not unbound、successとする。current binding mismatchは `MatchesGeneration(fileObject, generation, identity, path) == false` の観測結果全体を表し、generation単独とは断定しない。parent not unboundは `IsUnbound(fileObject) == false` の観測結果全体を表し、Bound/Retiredを区別・断定しない。proof判定を別経路で再評価せず、同じ結果をlate候補生成と原因集計に再利用して既存の二重評価を除去する。

epoch 0、late 0、post-upper proof missingがbroad全件の場合、全sealの原因が単一なら次の固定codeへ分離し、複数原因ならMIXEDへ固定する。

- `...EVENT_TUPLE_LOOKUP_EPOCH_EMPTY_POST_UPPER_PROOF_LEDGER_UNAVAILABLE_ALL`
- `...EVENT_TUPLE_LOOKUP_EPOCH_EMPTY_POST_UPPER_PROOF_CURRENT_FILE_OBJECT_MISMATCH_ALL`
- `...EVENT_TUPLE_LOOKUP_EPOCH_EMPTY_POST_UPPER_PROOF_CURRENT_BINDING_MISMATCH_ALL`
- `...EVENT_TUPLE_LOOKUP_EPOCH_EMPTY_POST_UPPER_PROOF_PARENT_NOT_UNBOUND_ALL`
- `...EVENT_TUPLE_LOOKUP_EPOCH_EMPTY_POST_UPPER_PROOF_MIXED`

invalidが1件でもあればsuccessや他causeとの混在を問わず、全後段分岐前にSTATE_CHANGEDを最優先する。旧 `POST_UPPER_PROOF_MISSING_ALL` は外部互換allowlistへ残すが、新production sourceからemitしない。path、QPC、FileObject、generation、identity、parent state、件数・比率は公開しない。path table再参照、wait、再lock、認可、state、handoff、候補保存条件は変更しない。completion-drain集合を64から69 codeへ同期し、runner/workflowはexact codeだけを伝播する。

## 影響範囲

`REQ-F005-012`、`REQ-F005-013`、`DES-F005-006`、`DES-F005-012`、`FUN-F005-017`、`FUN-F005-047`、`UT-F005-017`、`UT-F005-047`、`IT-F005-005`、`QT-F005-008`、`QT-F005-009`、`T-070`、`T-136`を対象とし、`T-137`を追加する。

## 試験方針

- 各単一原因、全組合せのmixed、proof成功、invalid inputをproduction共有fixtureで固定する。same-generationのwrong identity/path/state、parent Retiredを含め、code名が観測範囲を超えて断定しないことを検査する。
- post-upper sealごとの原因判定・ledger参照をexact 1回とし、at-or-beforeでは0回であることをcall-countで検査する。
- 原因優先順、候補順反転、1/2/128件、129件、overflow、path exactly-one違反・必須入力欠落/範囲外の各invalid軸とledger unavailable/successの組合せ、invalid+別cause混在が全後段前STATE_CHANGEDとなることを検査する。
- 旧code非emit、69 code共有、127文字以内、semantic fingerprint不変、非公開を検査する。
- 通常native、固定target、関連Vitest、typecheck、ESLint、trace_check、再現build2回、独立受け入れ、hosted productionを実施する。

## 承認

既存snapshotのbinding proof不成立原因を認可せず固定するdesign-level変更で、要求承認ゲートは設けない。独立設計レビューとlocal/hosted影響試験完了まで `in-review` を維持する。

## 独立設計レビュー

初回レビューのMedium 2件を受け、`MatchesGeneration`/`IsUnbound`の観測範囲を超えないcode名へ修正し、invalidのglobal優先を明記した。再レビューのMedium 1件を受け、helper局所順をinvalid validationから開始し、path exactly-oneと必須入力整合をledger状態より先に検証する設計へ固定した。最終レビューはHigh 0 / Medium 0 / Low 0でPASSし、排他的partition、exact 1回評価、非公開、69 code、認可・state・handoff非変更に残指摘はない。
