# CHG-F006-002 F006 work-preview構築(段階B2前半)を阻む4件の構造的ブロッカーを解消する

## 経緯

T-151段階B2（`scripts/f006-content-preview.ts`によるwork-preview構築）は前セッション
（commit `6d5d434`）で1件目のブロッカー（F005共有registry不変条件がappend-only運用と
非互換、`content/batch-candidates.json`）を`f005-context-internal.ts`の修正
（commit `3f859f6`）で解消済みだった。本セッションでは山月記(000624)を実際に
`node --experimental-transform-types scripts/f006-content-preview.ts`で実行し、
work-preview構築が最終的に成功することを確認する過程で、さらに3件の構造的ブロッカーと
1件のscriptバグを発見・解消した。いずれもF005導入時点の「作者・authorは有限個で
それ以上増えない」という暗黙の閉世界前提が、F006以降の新規author追加という
正当なappend-only運用と衝突したことに起因する。

## 決定（発見順）

1. **`runActualLoaderLogic`の共有registry全体hash不変条件**
   （`src/content/f005-context-internal.ts`）。`loadVerifiedF005RegistryControl`
   （build毎に再実行されるproduction検証経路）が`loadBatchCandidateRegistryProjection`
   の`registrySha256`（`content/batch-candidates.json`全体のbyte hash）を
   `integratedRegistrySha256`（F005 migration時点の固定値）と比較しており、F006以降が
   正当に追記するたびに必ず不一致となっていた。F004/F005は既存どおり独立経路
   （definition+policy verification／F005 dedicated registry）との一致で検証し、F003は
   `loadAndVerifyBatchCandidate`での再検証（承認chain全体のSRS doc SHA検証を巻き込み、
   ドキュメントの事後修正で無関係に失敗しうるため不採用）ではなく、implementation
   commit時点のregistry blobへpinした個別candidate比較へ差し替えた。
2. **`verifyF005ArtworkAgainstCatalog`の既存作者画像「3件固定」検証**
   （`src/content/f005-artwork.ts`）。F005時点の既存3作者（F001〜F003）固定を想定した
   `existingArtwork.length !== 3`が、F006の新規author追加後（既存4作者へ増加）に
   `F005_ARTWORK_EXISTING_INVALID`で拒否していた。近似重複検出は`existingArtwork`全件
   に対して行われる設計のため、「3件固定」を「3件以上」へ緩和しても検証の厳密さは
   損なわれない。
3. **`assertArtworkProvenanceMatches`のF006 identity nested schema非対応**
   （`src/notices/artwork-bundle.ts`、全feature共通の作者画像credit/notice統合
   ヘルパー）。F006の自己完結provenance schema（`f006-artwork.ts`の
   `ArtworkProvenanceF006`）は`authorId`/`batchId`を`identity.{authorId,batchId}`へ
   ネストして格納するが、`assertArtworkProvenanceMatches`はtop-level fieldを前提と
   しており`PUBLIC_AUTHOR_IDENTITY_CONFLICT`で拒否していた。top-level fieldが存在
   する場合を優先し、存在しない場合だけ`identity`側を照合するfallbackを追加した
   （F001〜F005の既存挙動は変更していない）。
4. **`assertV050Invariant`のcontent/artwork-provenances.json比較漏れ**
   （`scripts/f006-content-preview.ts`、script自体のバグ）。`content/catalog.json`
   だけをexact byte比較から除外していたが、`integrateArtworkProvenances`が集約する
   `content/artwork-provenances.json`（全作者の`ArtworkCreditManifest`配列）も
   F006の新規author追加により末尾へ1件増える。`catalog.json`と同じ「既存分がprefix
   として完全一致し末尾へ1件追加」canonical比較へ差し替えた（この除外パターン自体は
   `src/content/published-baseline.ts`の`verifyPublishedInvariant`に既存の前例あり）。
