# CHG-F005-071 event directory binding状態の固定診断

## 変更理由

CHG-F005-070 production run `31669864841` attempt 3は
`...POST_UPPER_PROOF_PARENT_BOUND_EVENT_FO_OTHER_EVENT_DIR` で安全停止した。
late eventのFileObjectは、eventのpathであるcache directory自身へBoundである。

ここで`Admit`の契約を確認すると、`SealedParent`種別の登録は
`before.State == Unbound` を要求し、登録後も`after = before`のままUnboundを維持する。
したがって**State Boundでpathがdirectoryのentryは`SealedParent`ではなく
`OtherBound`として登録されたもの**である。すなわちこのdirectory handleは、
登録時点ではどのsealのparentとも対応付かない「その他のbind先」として扱われている。

`OtherBound`のentryは`Reused` / `DeleteSeen` / `CleanupSeen`のフラグを持ち、
とくに`Reused`は`before.Generation != 0 || before.Reused`で設定される、
**FileObjectアドレスが以前の世代を持っていたこと（アドレス再利用）の記録**である。

現在の停止点はこのフラグ状態を示さないため、当該directory bindingが
生きた登録なのか、再利用・削除・cleanup後の残骸なのかを判別できない。
認可・handoff・候補保存条件を一切変更せず、この状態だけを固定分類する。

## 変更内容

`WriteCompletionBindingLedger` へ read-only の `MatchEventDirectoryBinding(fileObject,
eventDirectory)` を追加する。単一 `TryGetValue` exact 1回で判定し、
fileObject 0・event directory未指定・entry不在・State非Bound・pathがevent directoryと
不一致はいずれも `Invalid` とする。以降は次の優先順で確定する。

1. `Reused` — アドレス再利用の記録あり
2. `DeleteSeen` — delete観測済み
3. `CleanupSeen` — cleanup観測済み
4. `Live` — 上記いずれもなし

`ParentBoundActiveLeaseFailureCode` は評価順・既存分岐を変更せず、
`EventFileObjectBoundPathRelation.EventDirectory` の分岐だけを状態別の固定codeへ
差し替える。共通prefixは `...POST_UPPER_PROOF_PARENT_BOUND_EVENT_FO_DIR_` とし、
suffixは `REUSED` / `DELETE_SEEN` / `CLEANUP_SEEN` / `LIVE` / `STATE_INVALID` の5種とする。

lookupは relation が `EventDirectory` と確定した場合にだけ評価する。
引数がnullまたはenum未定義値の場合は後段前に `STATE_CHANGED` へ閉じる。
旧 `OTHER_EVENT_DIR` は互換・他経路のために残し、新5 code追加で外部code集合を
103から108へ同期する。raw path・raw FileObject・世代値・件数は返さない。

候補生成、handoff、OtherBound admission/apply、semantic map、auth fingerprint、
active lease、state、容量actual、候補保存条件、公開条件は変更しない。

## 認可への含意

本変更自体は認可を変えない。ただし結果は次の認可判断へ直結する。

- `LIVE` が観測された場合、当該eventは生きたdirectory bindingに対する
  正当な遅延メタデータ更新であり、file leaseのFileObject一致で評価している
  現在の評価順そのものが過剰であると判断できる。
- `REUSED` が観測された場合、directory handleのアドレス再利用であり、
  ledgerの世代管理側を是正する必要がある。
- `DELETE_SEEN` / `CLEANUP_SEEN` は、消えた実体のbindingが残っていることを示す。

いずれの場合も、認可条件の変更は本変更ではなく次の変更管理で扱う。

## 試験方針

- 5 codeそれぞれの単独到達と、CHG-F005-070までの既存validationが優先されることを固定する。
- 優先順（Invalid > Reused > DeleteSeen > CleanupSeen > Live）を複合フラグ込みで固定する。
- `Invalid` を返す全前提違反（fileObject 0、entry不在、State Bound以外、path不一致、
  event directory未指定）を実ledgerで固定する。
- relation が `EventDirectory` 以外のとき binding 引数に依存しないことを固定する。
- null・enum未定義値の `STATE_CHANGED` と後段への到達0を固定する。
- 2つのledger lookupがそれぞれ exact 1回であることを構造試験で回帰する。
- 108 code同期、raw値非公開、127文字上限、`public/`・`data/` 差分0を回帰する。
- native全件、固定target suite、Vitest、typecheck、ESLint、同一SHA再現build 2回、
  hosted影響試験を実施する。

## 承認

非破壊診断のみのdesign-level変更。認可条件・公開条件を変更しない。
オーナーより認可経路に触れる変更の事前承認を得ているが、本変更では行使していない。

### 自然経路のhosted試験

production run `31672315764` はattempt 1〜3のいずれも既知の
`...POST_UPPER_PROOF_PARENT_BOUND_CONTEXT_MISSING`（active lease/phase/snapshot欠落）で
安全停止し、retry_limit 3に達して本軸へ未到達だった。candidate branchは未作成、
候補保存・公開はいずれも発生していない。

CHG-F005-070で本軸へ到達したのは3 attempt中1回であり、hosted schedulingへの依存が大きい。
次サイクルではCHG-F005-052〜055・070と同じ型で、`MatchEventDirectoryBinding` と
directory binding分類だけを直接入力する決定的hosted相関suite（T-143相当）を追加し、
配送順に依存しない影響確認へ切り替える。
