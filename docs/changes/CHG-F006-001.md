# CHG-F006-001 F006作者画像provenance（FUN-F006-014/015）を実装し、integrateArtworkProvenancesへ結線する

## 経緯

T-150（中島敦作者identity・独自作者画像・Catalog新規author統合基盤）は、identity
registry（`f006-source.ts`）とCatalog統合・route導出（`f006-catalog.ts`）まで実装
済みだったが、作者画像生成（REQ-F006-016、FUN-F006-014/015）はComfyUI等の画像生成
ツールが利用できず未着手のまま残っていた。今回、ローカルComfyUI（FLUX.1 schnell）で
生成済みの中島敦ずんだもん画像（`content/batches/F006/generation-inputs/
nakajima-zundamon-original.png`、SHA-256 `9686d567837c60baaa611aa1779cb1052d3a37e0
46160c8cce77f26cc5328e4a`）が用意されたことを受け、DD-F006.md FUN-F006-014/015の
方式訂正（2026-08-22、`sealF006ArtworkProvenance(generation, inputs, finalImage)`
というcontext引数なしのF006専用軽量schema）に基づき実装を完了した。

## 決定

- 新規`src/content/f006-artwork.ts`に、F001〜F005共有の`src/notices/
  artwork-provenance.ts`（OpenAI内蔵image_genツール専用の固定検証）を一切変更・
  再利用しない、F006専用のself-contained schemaを実装した。PNG decode・dHash64
  計算だけは`f005-artwork.ts`のfeature非依存pure関数`computeDHash64V1`（内部で
  `verifyPngjsLockfileIntegrity`を実行）を再利用する。
  - `sealF006ArtworkProvenance(generation, inputs, finalImage)`: exact final
    image path・参照入力exact `[]`・実際の生成情報（generator/generatorVersion/
    model/workflow/prompt/negativePrompt/seed等、捏造せず実値のみ）を記録した
    `ArtworkProvenanceF006`をseal。`ArtworkManifestIdentity: {batchId:'F006',
    authorId:'000119', outputPath}`を含む。
  - `verifyF006ArtworkAgainstCatalog(provenance, finalImage, existingArtwork)`:
    既存4作者画像（`existingArtwork.length===4`固定）とのbyte一致・dHash64
    Hamming距離8以下を`F006_ARTWORK_NEAR_DUPLICATE`として拒否する。
  - `serializeF006ArtworkProvenance`/`parseAndRehydrateF006ArtworkProvenance`で
    runtime brandをJSONへ混ぜずcanonical serialize→再起動rehydrateを行う
    （F005実装と同型構造）。
- 実際に生成済みの画像を`content/batches/F006/public-files/artwork/
  nakajima-zundamon.png`へ配置し（F005の`public-files/`永続化パターンに倣う）、
  `sealF006ArtworkProvenance`を実データで実行して`content/batches/F006/
  artwork-provenance.json`を生成した（dHash64 `383820881363322b`）。
  `verifyF006ArtworkAgainstCatalog`で既存4作者画像（akutagawa/miyazawa/dazai/
  natsume、`public/artwork/*.png`）との実体比較を行い、最小Hamming距離24（実測
  範囲24〜36）で近似・衝突なしを確認した。
- `src/content/batch-public.ts`の`integrateArtworkProvenances`へF006分岐を追加
  した。既存のF001（legacy）・F002/F003（`validateArtworkProvenance`）・F005
  （`parseAndRehydrateF005ArtworkProvenance`/`verifyF005ArtworkAgainstCatalog`）
  の各分岐は一切変更していない。F006分岐は`f006-artwork.ts`の新規関数を
  `context`なしで呼び出す（F005分岐は`loadVerifiedF005Definition`でF005
  ApprovedBatchContextを取得するが、F006ではDES-F006-001の既定方針どおり
  三段階承認controlを新設していないため不要）。
- `src/content/f006-catalog.ts`の`mergeNewAuthorCatalog006`ヘッダコメントを、
  「画像未生成のためbindingは検証しない」という記述から実装完了後の状態へ
  更新し、実画像のexact SHA-256を`F006_ARTWORK_SHA256`定数としてexportした。
  `mergeNewAuthorCatalog006`自体はCatalog統合ロジックの単体テスト容易性を保つ
  ため、`authorArtwork`bindingをcaller供給オブジェクトとして受け取る既存の
  schema/format検証構造は変更していない（実運用のcallerが`F006_ARTWORK_PATH`／
  `F006_ARTWORK_SHA256`を結線する）。
