# CHG-F005-001 F005設計レビューに伴う信頼境界と受入契約の強化

## 変更理由

F005の整合性・セキュリティ・実現性レビューで、公開ゲートの循環、承認済みartifactのbinding不足、XML・画像・Windows pathの入力防御不足、`proofreader: null`の移行範囲不足、複数path受入をOS atomicとみなす曖昧さを検出した。要求の目的や収録作品は変えず、fail-closed受入条件を明確化する。

## 変更内容

- 公開準備はゲート①〜③、公開記録はゲート④と実デプロイ証跡を必須とし、循環を解消する。
- Approved control commitを信頼起点としたapproval binding、review principal分離、状態遷移CASを明記する。
- 原典snapshotへraw bytes/path、URL、取得時刻、SHAを同時保持し、XML外部実体とresource exhaustionを拒否する。
- `proofreader: null`を夢十夜だけに許し、sourceからcreditsまでの全層を後方互換移行する。
- 作品受入をjournalで回復可能な複数pathの論理transactionとして定義する。
- PNG decode、dHash表現、favorite ID、Windows path/reparse/hardlink、strict CSP、secret scanを境界試験可能な契約へ強化する。
- 容量停止境界は上限同値を許可し、+1 byteで停止する。
- 容量観測はETWを正本とし、notice-onlyは拒否する一方、登録Job PID・active phase・既知eventに一致するETW-only低レベルeventはactualへ算入して許可する。
- F005候補は承認スナップショット専用registryへ隔離し、Q-027〜Q-031、SRS、QT、CHGをapproval policyとbinding evidenceへ固定する。実装時はF005 policy/schema対応と共有registry統合を同一互換migrationとして適用し、F003/F004 loaderの回帰0を先に検証する。
- v0.4.0のpublicとdistの基準値を分離し、rollback routeをexact 6件とする。

## リスクと対策

- 既存12作品のcanonical JSON bytesをfixtureで固定し、nullable移行による回帰を防ぐ。
- XML parserはresolverを無効化し、DOCTYPE等をparse前に拒否する。
- pathはroot直下のregular fileだけをhandle identity付きで検証し、junction swapを拒否する。
- rollback artifactを公開前に検証し、deploy無効化journalを別process watchdogが閉じるまで`published`にしない。

## 承認

Q-028で、プロジェクトオーナーの本会話における「今回はすべてOK」「手動確認不要」「続けて」という包括承認を本変更へ結合した。設計レビューで検出したQT-F005-008の片側event曖昧性はQ-029、candidate登録不足はQ-030、既存loaderを保護するsnapshot専用registryへの隔離と互換migration契約はQ-031で承認した。設計・試験仕様・実装・再試験が完了するまで`in-review`とする。
