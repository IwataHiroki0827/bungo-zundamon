# CHG-F005-015 closed lease判定のtuple後段化

## 変更理由

GitHub Actions run `30513249202`は`ETW_SYSTEM_SETINFO_CORRELATION_LEASE_CLOSED`で安全停止した。active lease認可はphase/path/QPC一致を確認する前に`FileObjectClosed`を評価していたため、別pathの完了write遅延eventが存在するだけでも次のclosed leaseを誤って停止理由にできる。closed判定をactive lease tuple一致後へ移す必要がある。

## 変更内容

- active lease System `SetInfo`の対象判定を`MatchesReservation`へ分離する。
- `BIRTH_MISSING`、System PID 0/4、setinfo、非0 FileObject、同一phase/path、予約後QPC、process非escapeが一致しないeventはactive lease対象外として完了write fallbackまたは既存診断へ流す。
- active lease tupleが一致した場合だけ`FileObjectClosed`を評価し、closedなら従来の固定codeで停止する。
- 一致したopen leaseの相関条件と認可結果は変更しない。

## セキュリティ境界

closed leaseを許可する変更ではない。closed状態による停止対象を、当該leaseの完全tupleに一致するeventへ限定する。別path eventをactive leaseへ誤結合せず、完了write fallbackもCHG-F005-014のidentity/QPC/binding条件を維持する。

CHG-F005-015反映後のnative pinはProgram SHA-256 `7da3e008148d9299c8c8eddea06061392be0477116384e4fa8081d31693553fd`、output binary SHA-256 `d177df7023280c6da05fd9bd97c7942d0169c50bc572477546f19d370bd98d08`、75,024,220 bytesとする。

## 検証

- closed leaseで別path tupleは対象外、同一tupleは専用停止対象となるpure ruleを検査する。
- source上でreservation tuple判定が`FileObjectClosed`より前であることを固定する。
- native規則、対象回帰、型、ESLint、再現build、trace、独立レビュー後にhosted productionを再試験する。

2026-07-30に対象5 test file 124件、native規則66件、型検査、ESLint、再現build 2回、YAML、trace、差分検査がPASSした。reservation tupleの全条件、closed一致時の専用停止、別path対象外、open lease認可不変、tuple判定がclosed判定より前であることを自動試験した。Program SHA-256、binary SHA-256、bytesは上記pinへ一致し、`public/`と`data/`の差分は0件である。独立セキュリティレビューはHigh 0、Medium 0、Low 0でPASSした。
