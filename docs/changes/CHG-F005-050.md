# CHG-F005-050 active-directory handoff candidate多重性診断

## 変更理由

CHG-F005-049のProgram pin `95235ee661203e805e40234dc410c04d88d0e2f0f9ad2a7d29612490807ecd0f`によるhosted productionは、attempt 2/3で`F005_ETW_WRITE_COMPLETION_DRAIN_LATE_RETAINED_PARENT_OTHER_ACTIVE_SAME_PARENT_POST_RESERVATION_WRITE`へ安全停止した。

`AggregateLateEventFailureCode`は、複数のlate candidateのうち1件でもCompletedRetained parent・別active lease・same parent・active予約QPC後を満たすexact post-reservation write candidateがあれば、他candidateの原因より`LateRetainedParentWriteFailureCode`を優先する。一方、CHG-F005-044の既存`CanHandoffActiveDirectory`はlate candidate countがexact 1件の場合だけ評価を通過し得る。このためaggregateがtarget codeでも候補が2件以上なら既存active-directory handoffへ進まず、同じtarget codeで停止する。

認可・stateを変更せず、このactive-directory handoff candidate多重性だけを生値なしの固定codeへ分離する。候補1件時はCHG-F005-044の既存predicateを一切変更せず評価するが、predicateの全成立や認可PASSは本変更の保証としない。

## 変更内容

### 1. production共有cardinality純粋規則

production共有純粋規則`ActiveDirectoryHandoffCardinalityFailureCode`はlate candidate countと算出済みaggregate failure codeだけを受け取る。aggregateが`F005_ETW_WRITE_COMPLETION_DRAIN_LATE_RETAINED_PARENT_OTHER_ACTIVE_SAME_PARENT_POST_RESERVATION_WRITE`かつcountが2以上の場合だけ、次の固定codeをoverrideとして返す。

`F005_ETW_WRITE_COMPLETION_DRAIN_ACTIVE_DIRECTORY_HANDOFF_CANDIDATE_AMBIGUOUS`

code長は76文字である。countが`-1`、0、1、または別aggregateならoverrideを返さず、呼出元が保持する既存failure codeと既存分岐を維持する。count比較は加算・乗算を行わず、`int.MaxValue`でもoverflowしない。count 1かつtarget aggregateでは、CHG-F005-044の既存`CanHandoffActiveDirectory`とその全predicateをそのまま評価し、本規則による認可、追加再検査、成功保証を行わない。

候補の内容と列挙順はcardinality結果へ影響させない。exact post-reservation candidateが2件ある場合に加え、exact candidate 1件と別cause candidate 1件が混在する場合も、既存aggregateのexact優先によりtarget aggregateとなるため新codeへ分類する。両順序で結果は同一とする。exact candidateを含まない集合が別aggregateになる場合、本規則はoverrideしない。規則は候補配列、seal、phase、lease、ledger、proof、queue、generation handle、semantic map、capacity、notice、Observationを参照・変更しない。

### 2. same-gate線形化とterminal非fall-through

`lateCandidates`のarray snapshot作成、既存`AggregateLateEventFailureCode`によるaggregate算出、`ActiveDirectoryHandoffCardinalityFailureCode`の1回評価、ambiguous時の即時terminal throw、またはoverrideなし時の既存分岐継続までを、現在の`ObserveEtw`から取得した同一`gate` lock acquisition内で行う。この区間に`Monitor.Wait`、`Monitor.Exit`、lock解放・再取得、`writeCompletionSeals`再列挙を置かない。cardinality decisionはsnapshotの`Length`と算出済みaggregateだけを使用し、active lease、phase、seal、ledger等のmutable stateを再読込しない。

target aggregateかつcount 2以上では新codeを持つ`GuardException`を直ちにthrowする。既存completed-write handoff、completed no-lease handoff、post-request SetInfo、active-directory handoff、active-producer birth、known-directory認可、proof admission/replay、capacity、semantic apply、candidate保存へfall-throughしない。files、allocated、deferred、observations、notices、pending lease、peak、free、ledger、queue、generation handleを含む全semantic stateと内部証拠を変更しない。

count 1または別aggregateでは新規のstate更新、predicate、mutable rereadを追加せず、CHG-F005-041/042/044/045/047/049を含む既存の分岐順序と拒否codeを維持する。特にtarget aggregateかつcount 1は既存active-directory handoff predicateへ進み得るだけであり、既存predicateがfalseなら従来どおり停止する。

別threadがsnapshot直後にseal/phase/lease/ledgerを変更しようとしてもgate外で待機し、cardinality decisionとthrowまたは既存分岐への移行が線形化した後にだけ進入できる。

### 3. 外部契約と生値非公開

上記1 codeをcompletion-drain 50 codeへ追加して51 codeとし、native reply、TypeScript bridge、runner serialization、workflow annotationのexact allowlistを同期する。予約fence 4 codeは不変とする。全codeを127文字以下に保ち、unknown、extra suffix、exact 128文字は既存genericへ正規化する。

native reply、journal、runner serialization、workflow annotationは固定codeだけを伝播し、candidate count、candidate内容・順序、raw path、QPC、PID、FileObject、identity、sequence、handleを含めない。IPC keys、候補選択、exact 1の既存handoff predicate/認可、proof/ledger、semantic state、capacity、candidate branch、Pages、`public/`、`data/`条件は変更しない。

## 試験方針

- pure cardinality ruleへcount `-1`/`0`/`1`/`2`/`int.MaxValue`と対象/非対象aggregateを投入し、対象aggregateの2以上だけ76文字の新code、その他はoverrideなしとなることを固定する。
- exact post-reservation candidate 2件、exact candidate 1件と別cause 1件の混在をそれぞれ順序反転し、既存aggregateがexact targetを優先して同じtarget codeを返し、その後のcardinalityが同じambiguous codeを返すことを確認する。exactなしの別aggregateはoverrideしない。
- 候補内容・順序、snapshot入力、files、allocated、deferred、observations、notices、pending lease、peak、free、ledger、queue、generation handleを変更しないことをsemantic fingerprintで確認する。
- count 1のtarget aggregateではCHG-F005-044の既存`CanHandoffActiveDirectory`、全predicate、専用context、OtherBound proof、再検査、拒否codeを変更しないことを構造・回帰試験で固定する。count 1の認可PASS自体は本変更の期待値としない。
- production構造試験はarray snapshot→aggregate→cardinality 1回評価→即時throwまたは既存分岐の順序、同一gate、`Monitor.Wait`/`Monitor.Exit`/再lock/再列挙/mutable rereadなしを固定する。実Task/barrier fixtureはsnapshot直後のseal/phase/lease/ledger driftをgate外で待たせ、ambiguous decisionとsemantic fingerprint不変を確認する。
- ambiguous後にcompleted-write/completed-no-lease/post-request/active-directory/active-producer/known-directory認可、proof admission/replay、capacity/applyへ到達しないことを構造・実行試験で確認する。
- sentinel candidate count/content/order/path/QPC/PID/FileObject/identity/sequence/handleがnative reply、journal、runner serialization、workflow annotationへ出現せず、固定codeだけが伝播することを確認する。
- completion-drain 51 code、予約fence 4 code、127文字上限、unknown/extra/exact 128文字generic化をnative/bridge/runner/workflowで同期する。
- native規則、関連Vitest、typecheck、ESLint、trace_check、再現build 2回、独立受入、同一source SHAのhosted productionを実施し、candidate branch、Pages、`public/`、`data/`の非変更を確認する。

## 承認
