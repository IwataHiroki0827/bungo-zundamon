# CHG-F006-004 名人伝(000621)を抽出・二重レビュー・音声化・atomic受入しT-152を完結する

## 経緯

T-151（山月記/000624）完了時点で、`scripts/f006-prepare-editorial.ts`・
`scripts/f006-prepare-voice.ts`・`scripts/f006-content-preview.ts`・
`scripts/f006-capacity-actual.ts`はいずれもwork ID（`000624`等）を
module定数へハードコードしていた。T-152（名人伝, 000621）着手にあたり、
T-153（弟子, 001738）でも同一scriptを再利用できるよう、この4scriptを
CLI引数（`process.argv[2]`）でwork IDを受け取る設計へ変更した。

## 決定

1. **CLI引数化**: 4scriptとも冒頭で`process.argv[2]`を検証し（`f006-source.ts`の
   `F006_WORKS`定義済みwork IDと照合、または6桁数値の正規表現）、以降の
   module定数`WORK_ID`を導出する。既存の唯一のCLI entrypoint
   `scripts/f006-accept-work.ts`は元々CLI引数化済みであり無変更。
2. **`scripts/f006-prepare-editorial.ts`**: speaker判定・speech読み補正は
   work固有のcontentであるため`WORK_EDITORIAL_CONFIGS`（work IDをkeyとする
   lookup）へ切り出した。山月記(000624)分は既存確定内容をbyte互換で維持し、
   名人伝(000621)分を新規追加した。
3. **`scripts/f006-content-preview.ts`**: `buildIntegratedPublicTree`が
   work-previewモードで`active.catalogFragment.works`・
   `active.catalogBatch.workIds`へ「manifest累積範囲（先行accepted work分＋
   現在work分）」を要求する（`src/content/batch-public.ts`
   `expectedWorkIds = manifest.workIds.slice(0, activeIndex + 1)`）ことが、
   名人伝で初めて2work目のpreview構築を実行した際に判明した（山月記は
   1work目のため単一work fragmentで偶然この制約と一致していた）。
   `buildWorkFragmentPiece`関数へper-work処理（provenance生成・
   candidates/speech-revisions/reviews/voice-generationの読込・dialogue結合）
   を切り出し、`manifest.workIds.slice(0, workIndex + 1)`の全workについて
   呼び出して連結するよう変更した。あわせて、先行accepted work分の音声は
   `buildIntegratedPublicTree`自体が`manifest.workProgress[].
   acceptedAudioSources`（`content/batches/F006/accepted-audio/`実体）を
   根拠に内部でstagingコピーする既存の仕組み（`activePriorSources`）と
   二重になるため、`activeStage`への音声stageは現在work分だけに限定した
   （先行work分まで二重stageすると`PUBLIC_ACCEPTED_AUDIO_HASH_MISMATCH`で
   拒否される）。`assertV050Invariant`のcatalog.works成長数チェックも
   固定`+1`から`+accumulatedWorkCount`（累積work数）へ一般化した。
4. **`scripts/f006-capacity-actual.ts`**: WORK_ID CLI引数化のみ、ロジック
   無変更（work ID非依存の設計だったため）。
5. **`src/content/f006-acceptance.ts`**: 変更なし（元々work ID非依存の設計）。

## 実施内容

段階A（独立二重判定・読み補正）: 名人伝の4候補（「出かしたぞ」「善し！」
「既に、我と彼との別…」「ああ、夫子が…」）をAozora原典から実取得・照合し、
文脈から話者を確定した（飛衛/飛衛/紀昌/主人）。VOICEVOX 0.25.2 speaker 3
実測により「出かしたぞ」が音読み側で「しゅっかしたぞ」に誤読されることを
確認し、displayTextを変えずspeechTextだけをカタカナ読み「デカシタゾ」へ
補正した（他3候補はルビ由来の既存gaijiReplacements等で正読、追加補正不要と
実測確認）。primary/secondary独立二重判定は合意によりpending 0（4件承認）
で完結し、work FSMをpending→extracted→reviewedへ前進させた。

段階B1（音声生成・容量forecast）: `content/batches/F006/voice-config.json`
（F002/F004とbyte-identical、既存）をそのまま使い、ローカルVOICEVOX
0.25.2（`http://127.0.0.1:50021`）へ実接続してWAV 4件・計1,111,728 bytesを
実生成（miss 4/hit 0）。`verifyVoiceCompleteness`でapproved→audio→asset
参照の整合をPASS確認。容量forecastは`result: pass_with_warning`
（山月記に続く2work目のため既存public+累積分がwarning閾値超過、blocked
要因なし）。manifestをreviewed→budget-approved→voicedへ前進。

段階B2（preview構築・容量actual・atomic受入）: 上記CLI引数化・累積fragment
対応の`scripts/f006-content-preview.ts`を実行し、山月記(000624, 先行
accepted)＋名人伝(000621, 現在work)の2work分work-preview（909 files）を
構築。`scripts/f006-capacity-actual.ts 000621`で容量actual
`result: pass`（reasons: []、freeBytes約41.1GB）を確認。
`scripts/f006-accept-work.ts 000621`でwork statusをvoiced→acceptedへ
遷移させ、生成WAV 4件を`.voice-stage-000621/`から
`content/batches/F006/accepted-audio/000621/`へ正式昇格した。batch全体
statusは`draft`のまま（弟子(001738)が`pending`のため既存
`batchStatusFromWorks`仕様どおり）。
