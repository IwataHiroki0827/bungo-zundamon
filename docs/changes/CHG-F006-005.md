# CHG-F006-005 弟子(001738)を抽出・二重レビュー・音声化・atomic受入しT-153を完結する（F006全3作品完了）

## 経緯

T-152（名人伝/000621）完了時点でCLI引数化・累積fragment対応が確立済みの
`scripts/f006-prepare-editorial.ts`・`scripts/f006-prepare-voice.ts`・

`scripts/f006-accept-work.ts`を、T-153（弟子, 001738、F006最後の3作品目）へ
そのまま適用した。弟子は候補数が55件（山月記3件・名人伝4件と比べ大幅に多い）
であり、`WORK_EDITORIAL_CONFIGS`への話者判定・読み補正定義の追加に相応の
実測作業を要した。

## 決定

1. **speechCorrectionsの型を単一補正から配列へ拡張**: 山月記・名人伝は
   1候補あたり最大1件の読み補正で足りていたが、弟子では1候補内に複数の
   誤読（例: 「温」と「強」が同一candidate内で共に誤読）が確認された。
   `f006-prepare-editorial.ts`の`WorkEditorialConfig.speechCorrections`型を
   `Record<anchor, SpeechCorrection>`から`Record<anchor, readonly
   SpeechCorrection[]>>`へ変更し、適用loopをrevision chain（`revision:
   index+1`、`before`を前段の`after`へ継承）として順次適用するよう変更した。
   既存2作品（山月記・名人伝）の定義は配列長1でラップするだけで動作は
   完全に不変（`applySpeechRevisions`は元々複数revision chainをcandidateId
   単位で受理する設計だったため、下流ロジックの変更は不要だった）。
2. **話者判定・読み補正はwork固有contentのため`WORK_EDITORIAL_CONFIGS`へ
   追加**: 既存パターンをそのまま踏襲。

## 試験

`src/content/f006-acceptance.test.ts`を更新した。3作品全てがaccepted済み
となったため、以下2点を変更した:
1. 成功系テストの`ACCEPTED_WORK_ID`を`000621`から`001738`へ変更
   （`assertOrder`は対象work以降にacceptedなworkが存在しないことを要求

   ケースは、F006にpending workが存在しなくなったため、
   「manifestに存在しないwork ID（`999999`）」による同一エラーコード
   （`F006_WORK_ORDER`）の再現へ差し替えた（`assertOrder`は
   `index < 0`も同一分岐で拒否するため検証意図は保たれる）。
既存5ケース（prepare→accept→recoverの冪等成功・mint偽造prepared値拒否・
work順違反拒否・manifest path allowlist外拒否・workId形式不正拒否）は
全てPASS。
