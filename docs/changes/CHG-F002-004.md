# CHG-F002-004 規約再確認期限の実行時判定をリリースゲートへ移す

## 変更理由

`content/licenses.json` の `terms.validUntil` は、東北ずん子・ずんだもんの
キャラクター利用ガイドライン側が定めた有効期限ではない。
**プロジェクトが自ら置いた「この日までに再確認する」というリマインダー**である。

現状 `renderCreditsV2`（FUN-F002-025）は次の判定を持つ。

```ts
if (!Number.isFinite(checkedAt) || !Number.isFinite(validUntil) ||
    checkedAt > validUntil || validUntil < Date.now()) {
  throw new CreditsRenderError('CREDITS_POLICY_STALE');
}
```

この判定は `src/main.ts` から呼ばれる**ブラウザ実行時の経路**にある。結果として次が起きる。

1. 期限を過ぎた瞬間、**公開済みバンドルが何もしていないのに自壊する**。
   訪問者のブラウザでクレジットページが表示されなくなる。
2. 規約違反が生じたわけではなく、**こちらの事務的な日付だけでサイトが壊れる**。
   影響が釣り合っていない。
3. 判定時刻が閲覧者の端末時計に依存する。

実際に本リポジトリでも、テストfixtureの `validUntil` が 2026-08-01 で失効した結果
`CREDITS_POLICY_STALE` 6件が恒常的に失敗し、CHG-F005-049/050/051 で
「既存期限fixtureの失敗」として繰り返し脇に置かれていた。
公開サイトについても 2026-08-18 に同じ自壊が起きる状態だった。

## 変更内容

再確認義務そのものは維持する。非公式ファンサイトとしてガイドライン改定を
定期的に見直すことは妥当であり、REQ-F005-005 も選定時・公開直前の
権利再確認を求めている。**変えるのは期限切れの効果の置き場所だけ**である。

| | 現状 | 改訂後 |
| --- | --- | --- |
| 再確認する義務 | あり | あり（変更なし） |
| `checkedAt`/`validUntil` の形式・整合検査 | 実行時 | 実行時（変更なし） |
| **期限切れの効果** | **公開サイトが実行時にfail-closed** | **新規リリースをブロック** |

### 実行時（FUN-F002-025）

`validUntil < Date.now()` の判定だけを外す。
`checkedAt`/`validUntil` が RFC 3339 instant であること、`checkedAt <= validUntil`
であることの検査は維持し、不正なら従来どおり `CREDITS_POLICY_STALE` とする。
期限を過ぎているだけの状態では描画を止めない。

### リリース前（新設）

リリース準備の検査へ「`terms.validUntil` がリリース時点を過ぎていないこと」を追加する。
過ぎている場合はリリースを止め、規約を再確認して `checkedAt`/`validUntil` を
更新するまで新規公開できないものとする。

これにより期限切れは「訪問者に影響せず、再確認するまで新しく公開できない」状態になる。
本来意図していた統制はこちらである。

## 失う性質と、それを許容する根拠

期限を過ぎた公開サイトが、再確認前でも表示され続ける。
一方で次の理由から許容する。

- ガイドラインは規約側で改定されうるが、**改定が即座に既存公開を違法化するものではない**。
  非営利・広告なし・非公式表示という本サイトの用途は、現行ガイドラインの
  最も緩い区分に収まっており、構造的に安定している（`docs/evidence/rights/` 参照）。
- 実行時に落としても**再確認が早まるわけではない**。むしろ訪問者に不利益を与えるだけで、
  運用者への通知経路にはなっていない。
- リリースブロックは運用者に直接届き、かつ再確認しない限り解除されない。
  統制としてはこちらの方が強い。
