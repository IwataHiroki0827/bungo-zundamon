# CHG-F005-053 T-122決定的hosted相関検証

## 変更理由

Q-045で、CHG-F005-049/050/051とT-110完了後の現行Program pinによるT-122 follow-up productionを3 attempt実行しても、前段の既知handoff多重固定codeで安全停止し、event tuple固定6分類へ到達しなかった。自然なETW配送順へ追加で依存しても有限回のhosted影響確認を保証できない。

プロジェクトオーナーの継続指示を安全側へ限定して反映し、T-122の認可・proof・state、容量actual、候補保存、公開条件を変更せず、同じproduction assemblyの既存規則を直接実行する決定的hosted相関試験へ置き換える。

## 変更内容

### 1. production共有規則を使うT-122 target suite

`native/f005-guard-tests/F005Guard.CorrelationTests.csproj`からProjectReference生成されたproduction assemblyの`WriteCompletionDrainRules.LookupFailure`と`RecheckSealedFailure`を直接呼び出すtarget `CHG-F005-048/T-122`を追加する。production規則の複製、test-only production分岐、条件付きコンパイル、guardのIPC・環境変数・command line入口追加は禁止する。

manifestは、lookupの負数・候補数包含関係違反・epochとlate同時存在・broad 0矛盾をgeneric mismatchへ、broad/epoch/exact/lateが全て0の境界をPASSへ、epoch空をlate proof有無へ、exact件数0/1/複数をmissing/PASS/ambiguousへ固定する。recheckはseal件数0/1/複数・不正値、fields空、各単独false、全trueをmissing/PASS/ambiguous/generic/fieldsへ固定し、6つのT-122 codeと既存generic/late/PASSの排他性を確認する。

構造試験はproduction callback内の3呼出箇所が同じ共有規則を使用し、固定codeの後段fall-through、旧generic codeへの逆戻り、認可条件変更がないことを検査する。target processは既存と同じRUNNER_TEMP外部root、実Windows identity、private Jobのread-only相関基盤で実行し、caller供給の偽PASSを禁止する。

### 2. read-only hosted evidence契約

既存`.github/workflows/f005-hosted-native-probe.yml`をtarget選択可能な固定manifest契約へ拡張し、今回のself-pathではT-122だけを実行する。workflow全体の`actions: read`/`contents: read`、checkout credentialなし、push・artifact uploadなし、raw stdout/stderr各65,536 bytes上限、未知・重複・欠落marker拒否を維持する。

canonical evidenceはCHG-F005-052と同じfield集合を縮退なく維持する。schema/kind、target ID、source commit、workflow run ID/attempt、runner OS/arch、`ImageOS`/`ImageVersion`、Windows build/UBR、PowerShell、Program/production project/build.ps1/global.json/workflow/test project/test source/test harness・selector/case manifest SHA、pinned native binary SHA、実load production assembly SHA/MVID、test assembly SHA/MVID・executable SHA、固定SDK/runtime、kernel ETW preflight、期待/PASS件数、Pages run ID/attempt/conclusionとdeploy job conclusion、結果を含む。PID、path、QPC、FileObject、identity、handle、stack、自由文は含めない。`public/`・`data/`・candidate/audio/staging差分0とcandidate branch不存在を同一jobで確認する。

Pages相関は固定workflow path `pages.yml`、`event=push`、`head_sha == sourceCommit`でbounded pollし、該当runがexact 1件かつterminalであることを要求する。run ID/attempt/conclusionを固定し、そのattemptのjob一覧で`deploy`がexact 1件かつ`skipped`であることを確認する。run欠落・複数一致・active attempt・timeout・head SHA差・job欠落/多重・`skipped`以外は固定codeでFAILとし、canonical evidenceを生成しない。

### 3. T-122 hosted影響判定

次を全て満たす単一source commitのcanonical evidenceでT-122のhosted影響をPASSとする。

1. pinned native guard buildとkernel ETW preflightがPASSする。
2. manifest SHA、期待件数、PASS件数が一致し、実load production/test assembly SHA/MVIDとtest executable SHAをCHG-F005-052と同じsource/build/runner tupleへ結合する。
3. lookup/recheckの全分岐が既存6 code、generic mismatch、generic late、PASSへ排他的に収束する。
4. productionの3呼出箇所が共有規則を使い、認可・proof・stateと後段fall-throughを変更しない。
5. raw値非公開、tracked出力差分0、candidate branch不存在、固定`pages.yml`の同一SHA・push・terminal・単一run/attemptとdeploy exact 1件 `skipped`を確認する。
6. workflowがread-onlyでcredential、push、artifact uploadを行わない。

この証跡はT-122固定分類のhosted影響確認にだけ使用し、production end-to-end成功、候補受入、容量actual、公開判定の代用にはしない。

## 影響範囲

`docs/traceability/tm.json`のT-122既存タグと`FUN-F005-017`・`FUN-F005-047`参照関係から、`REQ-F005-012`、`REQ-F005-013`、`DES-F005-006`、`DES-F005-012`、`FUN-F005-017`、`FUN-F005-047`、`UT-F005-017`、`UT-F005-047`、`IT-F005-005`、`QT-F005-008`、`QT-F005-009`、`T-070`、`T-122`を影響対象とする。実装・再試験タスクとして`T-127`を追加する。

## 試験方針

- target manifestのcase ID、順序、件数、SHAを固定し、欠落・余分・重複・順序差・偽PASS markerを拒否する。
- lookup/recheckの境界値、矛盾tuple、各単独false、全true、code優先順位をproduction assemblyへ直接投入する。
- production呼出箇所、固定code集合、read-only権限、raw値非公開、candidate/Pages非公開を構造検査する。
- local native通常suite、T-122 target、関連Vitest、typecheck、ESLint、trace_check、同一SHA再現build2回、独立受入後にhosted targetを実施する。

## 承認

既承認の要求・認可・proof・state・容量・候補保存・公開条件を変更せず、hosted影響確認の試験方法だけを決定化するdesign-level変更である。要求承認ゲートは設けず、影響文書更新、独立レビュー、T-127実装、local/hosted影響試験完了まで`in-review`を維持する。

## 独立設計レビュー

初回レビューはHigh 0 / Medium 2 / Low 1であった。canonical evidenceがCHG-F005-052より縮退していた点、Pages同一SHA相関のworkflow・event・単一terminal run/attempt・deploy job条件が不足していた点、lookup全ゼロPASS境界がmanifestへ明記されていない点を指摘された。

CHG-F005-052と同一のsource/build/runner/load assembly field集合を明記し、固定`pages.yml`・push・head SHA・bounded poll・exact 1 terminal run/attempt・deploy exact 1件`skipped`と全拒否条件を追加した。lookup全ゼロPASSも固定caseへ追加した。修正後の独立再レビューはHigh 0 / Medium 0 / Low 0でPASSし、trace_checkは`対応漏れなし: OK`である。
