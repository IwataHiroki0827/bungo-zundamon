# CHG-F005-042 completion-requested current SetInfoのsealed post-request replay

## 変更理由

commit `2cec0bcffc42197db229870dcd40913ea47af4da`のActions run `31208447007`は、T-115のcompleted-write handoffを通過後、`F005_ETW_WRITE_COMPLETION_DRAIN_LATE_DIAG_SETINFO_SEAL_NOT_COMPLETED_RETAINED`で安全停止した。

このcodeへ到達する候補は、`CompletionRequestedAtQpc`が存在し、event QPCがそれより後で、current pathのlease FileObject exact generation・identity/path proofを満たす。`Prepared`はcompletion QPCを持たず、`Released`はcallback admission writer内でactive phaseのnull化・seal clearと一体に遷移するため、通常callbackが同一active phaseとして観測できない。したがってproduction到達状態は`CompletionRequested`に限定される。ただし、完了要求後のeventを無条件にepochへ含めず、sealed replayが既に持つidentity・process・atomic適用の全再検査を維持する。

## 予定変更

### 1. post-request候補の完全条件

completion drainの`epoch.Length == 0`経路で、次の全条件を満たす場合だけ、通常late throwに代えて`PostRequestSystemSetInfo`付きのsealed contextを返す。

- broad candidate、epoch 0、exact late `ProofCandidate`の既存条件が成立する。
- `lateCandidates.Length == 1`である。
- aggregate codeがexact `F005_ETW_WRITE_COMPLETION_DRAIN_LATE_DIAG_SETINFO_SEAL_NOT_COMPLETED_RETAINED`である。
- seal stateがexact `CompletionRequested`で、同一active phaseを参照する。
- normalized pathはseal current path、eventはSystem PID 0/4の`setinfo`、FileObjectはseal lease FileObjectのexact generationである。
- `CompletionRequestedAtQpc < eventQpc <= DrainDeadlineQpc`である。下限同値は既存epoch、deadline同値はpost-request、deadline超過は既存`TIMEOUT`/late拒否とする。
- `completedWrites[normalized]`は未作成である。存在はstate不変条件違反として`STATE_CHANGED`で停止する。

候補0/複数、write、parent、他bucket、state差、deadline欠落・超過、completed record存在は認可しない。aggregate codeの選択と既存35 external codeは変更しない。

### 2. sealed proof/replayへの明示接続

T-115のcompleted-write handoffとは異なり、本変更は対象sealを`completionDrainSeal`として明示的に使用する。snapshotへ固定enum/flag `PostRequestSystemSetInfo`を保存し、seal sequence、`SealedCurrent` exact-generation proof、seal/phase EventCount、既存queue/replay、atomic applyへ接続する。

`RecheckSealedCallbackLocked`は通常`IsWithinEpoch`または明示flag付きpost-request完全条件のどちらか一方だけを受理する。post-request再検査では、event kind、current path、seal state、completion QPC、drain deadline、event QPC境界、completed record不存在、SealedCurrent proof、generation before/after、state before/after、producer tuple、effective/proof identity、retained current identityを再確認する。さらに既存どおりretained producer processのPID/start key/sequence完全一致と`Signaled`を要求する。

flagなしlate、flag付きだが条件差、parent/other-bound proofは`EVENT_TUPLE_MISMATCH`または既存先行codeで停止する。completed-write、reserved、directory等の他認可へfall-throughしない。replay後のfinal fence、completed record作成、`CompletedRetained`遷移は既存順序を維持する。

### 3. 認可集合と不変条件

追加認可集合は、完了要求後かつdrain deadline内に観測した単一System SetInfoで、対象sealのcurrent FileObject exact generation・identityと、終了済みretained producer tupleをsealed replay時に再証明できるものだけである。write、parent、別generation、process未終了、deadline超過、複数candidateを含めない。

IPC、raw path/QPC/FileObject/identity/process値非公開、容量actual、notice、candidate/Pages条件、外部35 codeは変更しない。
