# CHG-F005-057 active-directory全適格候補集合の非選択handoff

## 変更理由

CHG-F005-056/T-130のproduction run `31246255285`は、active-directory handoffの既存predicateを満たすlate candidateが複数あり、かつ集合の全件が適格な`F005_ETW_WRITE_COMPLETION_DRAIN_ACTIVE_DIRECTORY_HANDOFF_ELIGIBLE_ALL`へ到達した。候補保存前にfail-closedし、candidate branchは不存在、Pages deployは`skipped`である。

`ALL`だけでは個々の旧sealによるevent ownershipや候補間同一性を証明しない。一方、既存active-directory handoffの出力は旧sealを選択・保持せず、同一gateで取得した現在の`activeLease`だけである。後段のbound-lease/after-lease認可、OtherBound retained identity、context固有tuple/process再検査も旧sealを入力としない。全candidateが同じevent-global値とactive lease snapshotに対して既存predicateを個別に満たす場合に限り、候補を選ばず現在のactive directory認可へ一度だけ引き渡せることを構造上固定する。

## 変更内容

### 1. 全適格集合の純粋判定

production共有純粋規則`CanHandoffActiveDirectoryCandidateSet(totalCandidateCount, eligibleCandidateCount, aggregateFailureCode)`を追加する。次の全条件が成立する場合だけtrueとする。

- `totalCandidateCount >= 2`
- `eligibleCandidateCount == totalCandidateCount`
- aggregateが既存`LATE_RETAINED_PARENT_OTHER_ACTIVE_SAME_PARENT_POST_RESERVATION_WRITE`

負値、eligible>total、total 0/1、eligible 0/1、適格・不適格混在、別aggregateはfalseとする。単一候補は既存`CanHandoffActiveDirectory`を変更せず、複数集合だけを新規則で扱う。

### 2. 候補非選択のhandoff

`TryAuthorizeWriteCompletionDrainEventLocked`は、既存`lateCandidates` snapshot、aggregate、event-global scalar、候補別共有predicate、checked eligible countを同一gate内で一度だけ使用する。新規則がtrueの場合はcandidateをindex・並べ替え・選択せず、同じgateで取得済みの`activeLease`参照だけを`activeDirectoryHandoff`へ設定して即時returnする。defensiveに`activeLease`がnullなら`STATE_CHANGED`へ閉じる。

各candidateのpredicateは、System/BIRTH_MISSING/write/nonzero unbound FileObject、CompletedRetained、同一active voice phase、seal parent path、別active lease、phase instance、active parent、active予約後をすべて独立に満たす。event-global値とactive lease snapshotは集合全体で共有されるため、複数candidateの部分条件を合成して認可しない。旧sealのidentity・sequence・QPC・proof・replay・EventCountはhandoffへ持ち込まない。

適格0件は`STATE_CHANGED`、適格1件は`ELIGIBLE_EXACT_ONE`、`2 <= eligible < total`は`ELIGIBLE_MIXED`として従来どおりterminal停止する。`ELIGIBLE_ALL`と旧`ELIGIBLE_AMBIGUOUS`は外部互換allowlistへ残すが、全適格集合のproduction経路ではemitしない。

### 3. 後段認可と非変更境界

handoff後はCHG-F005-044既存順の`TryAuthorizeBoundLeaseDirectoryWriteLocked`、poison確認、`TryAuthorizeAfterLeaseReservationDirectoryWriteLocked`、poison確認だけを評価する。両false/非poisonは`STATE_CHANGED`、いずれかのPASS後もOtherBound retained identity、context排他、bound/after固有tuple/process再検査をcapacity適用前に必須とする。

completed-write、completed-no-lease、post-request replay、旧seal proof、別認可へfall-throughしない。completion-drain 55 code、予約fence 4 code、IPC、capacity actual、candidate保存、branch、Pages、`public/`、`data/`条件は変更しない。

## 試験方針

- pure規則へ負値、eligible>total、total 0/1/2/3/`int.MaxValue`、eligible 0/1/2/3/全件、対象/別aggregateを投入し、対象かつtotal 2以上の全件適格だけtrueとする。
- 全適格2件/3件と順序反転でcandidate index・sort・first/max/latestを使わず、active lease参照だけをhandoffすることを固定する。
- 適格1＋不適格複数は`EXACT_ONE`、適格2＋不適格1は`MIXED`、0件は`STATE_CHANGED`へ従来どおり停止する。
- snapshotからhandoff returnまで同一gate、再列挙・wait・再lockなし、旧seal proof/replay/EventCount 0、全semantic fingerprint不変を構造・barrier試験で固定する。
- handoff後のbound→poison→after→poisonの順、両false、各poison、各PASS、OtherBound/context再検査、全後段排他を既存試験と追加fixtureで検査する。
- native通常suite、T-109/T-110/T-122/T-112固定target、関連Vitest、typecheck、ESLint、trace_check、再現build 2回、独立受け入れ後に同一source SHAのhosted productionを実施する。

## 承認

既存単一handoffと同じactive lease出力・後段認可へ、全candidateが同じ既存predicateを満たす集合だけを候補非選択で接続するdesign-level変更である。要求、capacity actual、候補保存、公開条件は変更しないため要求承認ゲートは設けず、独立設計レビュー、T-131実装、local/hosted影響試験完了まで`in-review`を維持する。

## 独立設計レビュー

production実物に対する整合性・実現性・セキュリティの独立レビューはHigh 0 / Medium 0 / Low 0でPASSした。全適格判定は同一`lateCandidates` snapshot・同一gate・共有predicateに閉じ、候補を選択せず現在active leaseだけを既存bound/after認可へ渡す。後段の独立tuple/process/retained identity再検査、非fall-through、旧seal非依存と整合し、要求変更には該当しない。
