# CHG-F005-025 System directory write完全候補の限定再結合

## 変更理由

GitHub Actions run `30520302499`は`F005_ETW_PID_NOT_JOB_MEMBER_SYSTEM_DIRECTORY_WRITE_REJOIN_CANDIDATE`で安全停止した。System PID 0/4のcache directory writeが、同一phaseでroot workerが作成した同一native identityのdirectoryへ遅延到着した完全候補である。

## 変更内容

- `BIRTH_MISSING`、System PID 0/4、write、非0未結合FileObject、voice phase開始後、active leaseなし、exact cache directory bucket、固定stage `CANDIDATE`、root PID/ProcessSequenceNumber存在の全条件一致時だけroot worker世代へ再結合する。
- candidate判定後のdirectory identityを後段へ渡し、容量算入直前のfilesystem再読込で二重照合する。
- TOCTOU差替えは`ETW_SYSTEM_DIRECTORY_WRITE_REJOIN_IDENTITY_MISMATCH`で停止する。
- 容量actualへ通常eventとして算入し、候補保存・公開条件を緩和しない。

## セキュリティ境界

認可前のcheap条件で非対象を除外してからfilesystem/owner照合する。同一phase/path/root PID・ProcessSequenceNumber/native identity ownerとroot activeを維持し、別bucket・別phase・active lease中・既結合/空FileObject・非candidateを拒否する。

CHG-F005-025反映後のnative pinはProgram SHA-256 `9c6ee9d83f3bc0581d1dd06bcfd615b51337e44d15daa6def2e2cff2f45dd1c7`、output binary SHA-256 `411d183deb66224cb73ea88d63e2f35343f10c6b4c0dc4289709197398095c62`、75,028,316 bytesとする。

## 検証

- 完全候補1件と拒否条件11件、identity二重照合、first-poison、容量・候補保存不変を検査する。
- native規則123件、対象回帰124件、型、ESLint、同一SHAの再現build 2回、trace、`git diff --check`、公開差分0をPASSした。
- 独立レビューの初回Low 1件を解消し、最終判定High/Medium/Low 0件をPASSした。hosted productionで限定再結合後の継続を確認する。
- Actions run `30520947829`でleaseなしdirectory write再結合を通過後、`CACHE_OTHER_DIRECTORY_UNBOUND_LEASE`を取得した。目的を達成したためactive lease関係の診断をCHG-F005-026へ分離する。
