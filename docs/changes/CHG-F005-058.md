# CHG-F005-058 active producer birth後eventのinitial/current予約境界固定診断

## 変更理由

CHG-F005-057/T-131のproduction run `31247640858`は全適格候補集合の非選択handoffを通過し、既存`F005_ETW_WRITE_COMPLETION_DRAIN_LATE_DIAG_WRITE_ACTIVE_PRODUCER_AFTER_RESERVATION_BIRTH`で候補保存前に安全停止した。

このcodeは予約handler時に観測済みのimmutable producer birthよりeventが後で、かつ`eventQpc <= activeLease.CurrentPathReservedAtQpc`であることを示す。一方、snapshotの`LeaseReservedAtQpc`は初回予約から不変で、current reservationはrename等で更新され得る。現codeだけではeventが初回予約以前か、初回予約後からcurrent予約までかを区別できない。既存scalarだけでこの一軸を固定診断し、認可設計を混同しない。

## 変更内容

### 1. birth後の二境界分類

既存`ReservationProducerBirthFailureCode`のinvalid、record missing、tuple mismatch、event birth同値以前を変更しない。従来`ACTIVE_PRODUCER_AFTER_RESERVATION_BIRTH`を返す条件だけを次の順で分離する。

1. `birthStartedAtQpc < eventQpc <= initialLeaseReservedAtQpc`は`...ACTIVE_PRODUCER_AFTER_RESERVATION_BIRTH_AT_OR_BEFORE_INITIAL`
2. `initialLeaseReservedAtQpc < eventQpc <= currentPathReservedAtQpc`は`...ACTIVE_PRODUCER_AFTER_RESERVATION_BIRTH_AFTER_INITIAL_TO_CURRENT`

既存どおり`current < initial`、`event > current`、phase/birth/initial tuple矛盾は`STATE_CHANGED`へ閉じる。`birth < initial`の場合の`event == initial`は前者、`event == initial + 1`は後者、`current == initial`では後者へ到達しない。既存許容境界`birth == initial == event`は先行する`event <= birth`判定により旧`AT_OR_BEFORE_RESERVATION_BIRTH`を維持し、新codeへ入らない。

### 2. production境界と外部契約

productionは既存予約snapshot、initial/current/event QPC scalarを同一gateで一度だけ純粋規則へ渡し、返却codeを同じthrow位置で停止する。snapshot再取得、map再参照、wait、再lock、認可、handoff、state更新を追加しない。

新2 codeをcompletion-drain exact集合へ追加し、native reply、TypeScript bridge、runner、production workflow regexを同期する。旧`ACTIVE_PRODUCER_AFTER_RESERVATION_BIRTH`は外部互換allowlistへ残すが新classifierからemitしない。各codeは127文字以下とし、生QPC、path、PID、identity、候補数を公開しない。予約fence4 code、IPC、capacity actual、candidate保存、branch、Pages、`public/`、`data/`条件は変更しない。

## 試験方針

- phase/birth/initial/current/eventのinvalidと-1/同値/+1、`current == initial`、`current > initial`を全境界で固定し、`birth == initial == event`は旧birth同値以前codeを維持する。
- birth後かつevent initial以下を`AT_OR_BEFORE_INITIAL`、initial超current以下を`AFTER_INITIAL_TO_CURRENT`へ排他的に分類する。
- 旧code非emit、既存record missing/tuple mismatch/birth同値以前/STATE_CHANGEDの非変更を確認する。
- 同一gate、snapshot/map再参照なし、全後段非fall-through、semantic fingerprint不変、生値非公開を構造試験で固定する。
- completion-drain 57 code、予約fence4 code、127文字、unknown/extra/exact128 generic化をnative/bridge/runner/workflowで同期する。
- native通常suite、T-109/T-110/T-122/T-112固定target、関連Vitest、typecheck、ESLint、trace_check、再現build 2回、独立受け入れ後にhosted productionを実施する。

## 承認

既存immutable scalarの時間境界を認可非変更で固定分離するdesign-level変更である。要求承認ゲートは設けず、独立設計レビュー、T-132実装、local/hosted影響試験完了まで`in-review`を維持する。

## 独立設計レビュー

初回レビューはHigh 0 / Medium 1 / Low 0で、`event == initial`の期待が既存`birth == initial == event`境界では先行するbirth同値以前codeと競合する点を指摘した。新しいinitial境界は`birth < initial`の場合に限定し、三値同値は旧`AT_OR_BEFORE_RESERVATION_BIRTH`を維持するようCHG・UT方針を修正した。

修正後の独立再レビューはHigh 0 / Medium 0 / Low 0でPASSした。`birth < event <= initial`と`initial < event <= current`の排他分類、三値同値の旧code維持、invalid優先、57 code同期、認可非変更に残指摘はない。
