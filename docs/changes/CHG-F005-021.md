# CHG-F005-021 closed active lease完全候補の限定再結合

## 変更理由

GitHub Actions run `30517281377`は`F005_ETW_CLOSED_LEASE_REJOIN_CANDIDATE`で安全停止した。reservation tuple、lease snapshot、FileObject binding、現存native identityがすべて一致しており、closed後に届くSystem SetInfoを元helper世代へ再結合できる安全候補である。

## 変更内容

- closed lease固定診断が`CANDIDATE`の場合だけ、lease worker PID・ProcessSequenceNumberへ再結合する。
- lease snapshot identityを後段へ渡し、filesystem再読込後に同じidentityを再照合してTOCTOU差替えを拒否する。
- snapshot欠落、binding非互換、current欠落、identity不一致の4 stageは従来どおりpoisonして停止する。
- 再結合eventは通常のETW容量actualへ算入し、候補保存・受入条件を緩和しない。

## セキュリティ境界

前段の`BIRTH_MISSING`、System PID 0/4、SetInfo、非0 FileObject、同一phase/予約path、予約後QPC、Job非escapeを維持する。`CANDIDATE`判定時と容量算入直前の二重identity照合を要求し、差替えは`ETW_CLOSED_LEASE_REJOIN_IDENTITY_MISMATCH`で停止する。

CHG-F005-021反映後のnative pinはProgram SHA-256 `fe8e1e40033edb14b2e7c86f97fc0c716334284ab52a28f27acc9615ac5957b9`、output binary SHA-256 `ad9ff5781ce3592579446a5666db331ba6bddafadae4088791a60a0d754fbefa`、75,024,220 bytesとする。

## 検証

- `CANDIDATE`だけが非deferredでworker generationとexpected identityを返し、他4 stageは停止する構造を検査する。
- 認可直後identity再照合、first-poison、exact classifier、容量actual・候補保存不変を回帰検査する。
- native規則95件、対象回帰124件、型、ESLint、同一SHAの再現build 2回、trace、`git diff --check`、公開差分0をPASSした。独立レビュー最終判定はHigh/Medium/Low 0件である。
- hosted productionでidentity二重照合と容量actualを維持したままproduction runnerが継続することを確認する。

## 承認

要求目的・容量停止基準・公開条件を変更しない設計境界変更であり、要求承認ゲートは設けない。hosted影響試験完了まで`in-review`を維持する。
