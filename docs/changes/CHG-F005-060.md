# CHG-F005-060 completed no-lease複数候補のcurrent identity一意handoff

## 変更理由

T-133 production run `31250367800`は`COMPLETED_NO_LEASE_DIRECTORY_HANDOFF_CANDIDATE_AMBIGUOUS`で停止した。対象aggregateを作る先行分類により複数候補は既存`CanHandoffCompletedNoLeaseDirectory`の候補固有条件を全件満たすため、同predicateの再評価では一意化できない。CHG-F005-047のknown-directory認可とadmit前再検査が必須にしているcurrent directory identityを前倒しし、現在実体と一致するsealが一意な場合だけ既存handoffへ接続する。

## 変更内容

aggregateがexact `WRITE_ACTIVE_LEASE_MISSING`でlate candidateが2件以上の場合、同一gateで`filesByPath[normalized]`のcurrent directory identityを1回だけ取得し、既存`lateCandidates` array中の`seal.DirectoryIdentity`との一致数をchecked countする。path entry欠落は一致0件として閉じる。

- identity一致0件は`...COMPLETED_NO_LEASE_DIRECTORY_HANDOFF_IDENTITY_MATCH_NONE`で停止する。
- identity一致1件はその一意sealだけを既存`completedNoLeaseDirectoryHandoff`へ渡す。
- identity一致2件以上は`...COMPLETED_NO_LEASE_DIRECTORY_HANDOFF_IDENTITY_MATCH_AMBIGUOUS`で停止する。

旧`...CANDIDATE_AMBIGUOUS`は外部互換allowlistへ残すが新しい複数候補classifierからemitしない。候補順、最新QPC、seal sequence、indexで選ばない。sort、wait、再lockを追加せず、一意候補以外のsealをproof/replay/EventCountへ接続しない。handoff後のknown-directory認可が返す`expectedIdentity`と選択sealの`DirectoryIdentity`をcontext作成前に再照合し、CHG-F005-047のadmit前再検査、retained parent再inspection、OtherBound proof、preflight/apply再検査をそのまま使う。

新2 failure codeをcompletion-drain集合へ追加して59から61へ同期する。raw candidate数、index、path、QPC、PID、FileObject、identity、sequence、handleを公開しない。認可predicate、state、capacity、candidate保存、branch、Pages、`public/`、`data/`条件は変更しない。

## 影響範囲

`REQ-F005-012`、`REQ-F005-013`、`DES-F005-006`、`DES-F005-012`、`FUN-F005-017`、`FUN-F005-047`、`UT-F005-017`、`UT-F005-047`、`IT-F005-005`、`QT-F005-008`、`QT-F005-009`、`T-070`、`T-121`、`T-133`を対象とし、実装・再試験タスク`T-134`を追加する。

## 試験方針

- candidate 0/1/2/3、identity一致0/1/2/3、current identity欠落、対象/別aggregate、invalid countを固定する。
- current identityとseal identityのexact 1、候補位置反転、全不一致、複数一致を一気通貫fixtureで検査する。
- exact 1だけが既存handoffへ進み、known authorization後のidentity再照合を通す。他候補のseal/proof/replay/EventCountを使わず、後段CHG-F005-047全拒否軸を維持する。
- 61 code、127文字、unknown/extra/exact128、native/bridge/runner/workflow同期、通常native、全固定target、関連Vitest、再現build2回、独立受け入れ、hosted productionを実施する。

## 承認

既存known-directory認可が要求するcurrent identityと一致する一意候補だけへ既存handoffを接続するdesign-level変更で、要求承認ゲートは設けない。独立設計レビューとlocal/hosted影響試験完了まで`in-review`を維持する。

## 独立設計レビュー

初回レビューはHigh 1 / Medium 0 / Low 0で、既存predicateは対象aggregateの全候補で成立するためeligible exact 1が到達不能と指摘された。候補固有かつ既存後段認可が必須とするcurrent directory identity一致へ設計を修正した。再レビューはHigh 0 / Medium 0 / Low 0でPASSし、identity正本、exact 1到達性、同一gate、認可後再照合、後段再検査、非公開契約に残指摘はない。
