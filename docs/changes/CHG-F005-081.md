# CHG-F005-081 表現注意抽出(FUN-F005-014)の実装とCatalogへの反映

## 経緯

T-074（CHG-F005-080付近の調査、progress記載）で、DD-F005.mdに設計が存在する
`extractVerifiedShumiNotice`(FUN-F005-014、DES-F005-005/DES-F005-010)が未実装であり、
`scripts/f005-final-integration.ts`の実プロダクション経路から一度も呼び出されていないため、
「趣味の遺伝」(`001104`)の公式表現注意(青空文庫の図書カード備考欄)がCatalogへ反映されない
状態(QT-F005-006に抵触する可能性)であることが判明していた。`projectF005Credits`
(FUN-F005-032、`DataDrivenWorkNoticeV1`)は実装・単体テスト済みだったが、その入力側を
生成する関数が存在しなかった。

## 実装内容

### 1. `extractVerifiedShumiNotice(source: SourceRecordV2, catalogNotice: F005ShumiNoticeCandidate): VerifiedWorkNotice`

`src/content/f005-source.ts`に追加(`F005SourceErrorCode`へ`F005_NOTICE_INVALID`を追加)。

公式card raw(`source.card.bytes`、mint済み`SourceRecordV2`経由)をUTF-8で復号し、
唯一trustedな

```
<tr><td class="header">備考：</td><td>{text}<br><div id="link"></div><script type="text/javascript" src="../link.js"></script></td></tr>
```

構造だけを正規表現で許可して`{text}`(`[^<]+`、タグ混入不可)を抽出する。行が0件・複数件、
制御文字混入、`&`混入(entity処理未実装のためfail-closedで拒否)、NFC非正規化は
`F005_NOTICE_INVALID`。

card raw sha256・抽出text sha256を独立に再計算し、呼出元が渡す自己申告
`catalogNotice`(schemaVersion/workId/text/sourceUrl/sourceRawSha256/textSha256/placements、
exact schema検証あり)の値と**再計算した値**を照合する。自己申告値同士だけが辻褄が合っていても
再計算値と不一致なら拒否するため、「自己申告値同士だけの一致」を許さない設計要求
(DD-F005.md)を満たす。一致した場合だけ、再計算した値で`VerifiedWorkNotice`を構築し
`mintedWorkNotices`へ登録して返す。

### 2. `rehydrateF005PredeploySnapshot(workspace, context, snapshotRelativePath): Promise<F005SourceSnapshot>`

同じく`src/content/f005-source.ts`に追加。既存の`rehydrateF005SelectionSnapshot`と対称の
実装で、`content/batches/F005/source-snapshots/predeploy-<run>.json`
(runはpredeploy収集時の`observedAt`から生成されるファイル名断片)を実物・Approved Context
へ再結合して再mintする。selectionとの違いはpathがrun付きで固定でない点だけであり、
`F005_PREDEPLOY_SNAPSHOT_PATH_PATTERN`で字句を制限したうえで、以降の`sealed`artifact
再照合・canonical schema厳格検証・`hasExactKeys`・`rights`再計算+一致確認は
selection側と同一のロジックを踏襲する(検証の厳格さを緩めていない)。

この関数が必要な理由: `projectF005Credits`(FUN-F005-032)はselection/predeploy
両phaseの`RightsUsageDecision`(`decisions.length===2`、phase重複禁止)を要求する。
最終統合scriptはgit clean checkout前提でlive再取得を行わないため、既に収集・commit済みの
predeploy snapshotを検証付きで再読込する経路が必要だった。

### 3. `content/batches/F005/work-artifacts/001104/shumi-notice-candidate.json`(新規)

`extractVerifiedShumiNotice`へ渡す自己申告candidate。実card raw
(`data/batches/F005/source-snapshots/selection/works/001104/card.html`、
sha256=`5c5c1228fb5b1430bc6fa00ecbb4b6b125a244d1e61fb14eefbfae083c856201`)から
Pythonで独立に検算した値(text/sourceUrl/sourceRawSha256/textSha256)で構成しており、
`extractVerifiedShumiNotice`側の独立再計算と完全一致することを確認済み。

### 4. `scripts/f005-final-integration.ts`の結線

- 各作品ループ内で`SourceRecordV2`を`sources`配列へ収集し、`001104`のとき
  `extractVerifiedShumiNotice`で検証済みnoticeを生成する。
- `content/batches/F005/source-snapshots/`配下の`predeploy-*.json`のうち
  ファイル名でソートした最新のrunを`rehydrateF005PredeploySnapshot`で再検証し、
  selection/predeploy両方の`RightsUsageDecision`を`evaluateF005RightsAndUsage`で得る。
- `mergeNewAuthorCatalog`後の`finalCatalog`(mint済みbrand)に対し`projectF005Credits`を
  呼び出し、Catalog/source/権利decision/artworkとの同一join再検証を通す(通らなければ
  最終統合全体が失敗する fail-closed 経路)。
- 検証成功を条件に、`001104`の`work.notices`へ既存の`dialogue-excerpt-scope`に加えて
  `{textKey: "official-content-warning", placements: ["work-list","work-detail","credits"]}`
  を追加する。この`textKey`は既存の`src/notices/work-notice-text.ts`/`src/ui/render.ts`/
  `src/ui/catalog-loader.ts`(`CatalogWorkNoticeTextKey`の一部として既に実装・試験済み)
  でそのまま描画される、既存の汎用注意文言レンダリング経路を再利用している。

## 未実施・残課題(設計判断が必要なため本タスクでは実施していない)

`projectF005Credits`が返す`CreditProjection`(検証済みnoticeの実文言・出典URLをcredits
配置へ投影したもの)自体は、これを永続化・公開・UI側で読み取って表示する経路が
コードベース上どこにも実装されていない(既存呼び出しは`f005-catalog.test.ts`の
テストのみ)。よって本タスクでは`projectF005Credits`の呼び出し自体で検証は行うが、
その出力を新規の永続artifact(例: `content/credits/F005.json`)として書き出すことは
行っていない(公開先path・UI消費経路・承認ゲート要否が未設計のため、スコープ外の
新規設計を避けた)。「表現注意がCatalogへ反映される」という主要な要求は、上記(4)の
`official-content-warning`textKey経路(既存の実装・試験済み経路)で満たしている。

T-074が既に指摘していたその他の残課題(UT-F005/IT-F005の未対応ID・spec_coverage機械照合
ファイル整備、E2E specへのF005固有REQ/QT-F005タグ付与)は本タスクの範囲外であり未着手。
