# CHG-F005-008 write-through固定診断カテゴリ

## 変更理由

GitHub Actions run `30506631401`は`wav-validated`後に`F005_CAPACITY_IPC_FAILED`へ安全停止した。native helperは固定reply codeを返すが、TypeScript bridgeが全codeを同じ上位codeへ集約したため、open・flush・identity・readback・cleanup・protocolのどの固定区分かを安全診断から判別できなかった。

## 変更内容

- native helperのinitial write、rename、commit、abort replyを、`open`、`flush`、`identity`、`verify`、`cleanup`、`protocol`の6個の固定公開codeへ分類する。
- 分類済み`F005NativeCapacityError`はbridge外側catchでgeneric codeへ再包装せず、helper停止・回収後に同じ固定codeをvoice境界へ渡す。
- Win32番号、path、message、未知値は公開せず、未知replyは`protocol`へ集約する。
- production runnerの既存allowlistへ6 codeを追加し、安全annotationの`causeCode`だけで区分を観測できるようにする。

## セキュリティ境界

診断は既知prefix・完全一致だけで分類し、native reply原文をannotation、ログ要約、文書へ転記しない。分類変更は認可、容量計算、候補保存、公開条件を変更しない。

## 検証

- 分類10ケース（directory/open、flush、identity、verify、commit/abort cleanup、protocol、非文字列）、外側catchのcode保存、実Error型によるrunner `causeCode`結合を実行する。
- 型検査、対象ESLint、集中回帰、独立レビュー後にhosted再試験する。
- 実行結果: 対象回帰37件、型検査、ESLint、YAML、差分検査、独立セキュリティレビュー（High/Medium/Low 0）をPASS。`public/`・`data/`差分0。

## 承認

要求内容を変えない診断分類であり要求承認ゲートは設けない。hosted正常系が完了するまで`in-review`を維持する。
