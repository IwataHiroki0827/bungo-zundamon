# CHG-F005-061 completed no-lease同一identity seal集合handoff

## 変更理由

T-134 production run `31251365842`はcurrent directory identityと一致するcompleted no-lease sealが複数で停止した。全一致sealは既存aggregateによりCompletedRetained、同一active phase参照、同一parent path、completion upper後、active leaseなしを満たし、さらにcurrent identityが共通である。単一sealを順序・QPC・sequenceで選ばず、この同値集合全体を不変証拠として既存known-directory認可へ接続する。

## 変更内容

identity一致sealが2件以上の場合、既存最大128件の`lateCandidates` snapshotから一致sealを同一gateで一度だけ検証し、新規`ImmutableArray<CompletedNoLeaseDirectorySealMember>`へ値コピーする。member snapshotはseal reference、SealSequence、CompletionRequestedAtQpcだけをimmutable valueとしてconstructor-onlyで保持し、集合contextもこのdefensive copy以外の配列・List・元candidate参照を保持しない。contextはactive phase reference/instance/start、directory path/current identity、event FileObject/QPC、root tupleを保持する。元候補配列や一時計算配列の要素差替え・順序変更はcontextへ影響しない。候補順は意味に使わず、重複reference/sequence、upper欠落、event<=upper、非CompletedRetained、phase/path/identity差はSTATE_CHANGEDへ閉じる。

known-directory認可を集合全体に対して1回だけ実行し、返却expected identityが集合共通identityと一致した後にcontextを作る。proof-independent recheckでは対象SealSequenceが各1件で同じreference、全memberがCompletedRetained、同じphase/parent/identity/upper、eventが各upper後であることを検査し、全`RetainedParent`を共通identityへ再inspectionする。

callback snapshotは従来どおり`SealSequence = null`、NormalEpoch、OtherBound proofとし、集合memberをsealed replayへ渡さずEventCountを更新しない。preflight/applyではcontext集合の全memberとcurrent directory identityをcapacity/semantic更新前に再検査する。1件でもrelease/drift/replacementならfail-closedし、別memberだけで継続しない。集合は既存seal上限内で、新規handleを取得しない。

旧`IDENTITY_MATCH_AMBIGUOUS`は外部互換allowlistへ残すが、一致集合2件以上の正常contextからemitしない。identity一致0件は既存NONE、1件は既存単一contextを維持する。completion-drain 61 code、認可predicate、IPC、capacity、candidate保存、branch、Pages、`public/`、`data/`条件は変更しない。

## 試験方針

- 集合2/3/128件、重複reference/sequence、候補順反転、各memberのstate/phase/path/identity/upper/event境界を固定する。
- context生成後に元配列/Listの要素差替え・追加・削除・順序変更を行い、defensive copy済みmember集合が不変であることを固定する。
- known authorization 1回、identity drift、context前/後のseal release・directory replacement、retained parent再inspection失敗を動的fixtureで検査する。
- 他memberのsealed proof/replay/EventCount使用0、OtherBound proof1件、semantic fingerprint、capacity、notice、Observation不変を失敗軸ごとに確認する。
- 61 code非変更、通常native、全target、関連Vitest、typecheck、ESLint、trace_check、再現build2回、独立受け入れ、hosted productionを実施する。

## 承認

同じcurrent identityへ一致する全sealを集合証拠として既存認可・全member再検査へ接続するdesign-level変更である。要求承認ゲートは設けず、独立設計レビューとlocal/hosted影響試験完了まで`in-review`を維持する。

## 独立設計レビュー

初回レビューはHigh 0 / Medium 1 / Low 0で、contextが入力配列を保持し得る所有権契約不足を指摘された。最大128件の検証後にimmutable member valueを新規ImmutableArrayへdefensive copyし、元配列/Listを保持しない設計とmutation fixtureを追加した。修正後レビューはHigh 0 / Medium 0 / Low 0でPASSし、集合所有権、全member再検査、rollback、bounds、認可非変更に残指摘はない。

## 実装・試験結果

集合contextとproduction共有全member validation seamを実装した。独立受け入れ初回M1のmember drift動的fixture不足を是正し、最終H0/M0/L0でPASSした。native900件、固定target、関連Vitest64件、typecheck、ESLint、trace_check、再現build2回をPASSした。Program SHA-256は`adb57f86b0bcc37a0aee9ed79954546d3d8d572b03c6eebd2bc4f089fd1a3dff`、binary SHA-256は`ae8794c292ea01d6505ff9756b1dea0e1ec738f5f50b5909e95787bbffa24636`、75,212,636 bytesである。

production run `31252362866` attempts 1/2は予約birth initial以前、attempt 3は`EVENT_TUPLE_LOOKUP_EPOCH_EMPTY_NO_LATE_PROOF`で安全停止した。集合handoff経路の再到達はなかったが、新実装を含む同一SHAでunknown化・candidate保存・公開がないことを確認し、実装影響試験を完了とする。
