# CHG-F005-079 共有integrateArtworkProvenancesへF005 ArtworkProvenanceV4分岐を追加する

## 変更理由

T-073はCHG-F005-078で`BATCH_ARTIFACT_MISSING`を解消した後も継続し、以下を順次修正した
(いずれも小規模な実装レベルの不備修正で個別CHG登録は行わず、T-073配下でまとめて解消した):

1. 公開provenanceがmkdtemp一時ディレクトリのみに書かれ、実workspaceを参照する
   `referencedPublicEvidence`と不整合(`content/provenance/F005/{workId}.json`ENOENT)
   → 事前準備script`scripts/f005-prepare-public-provenance.ts`で永続化・commit済みevidenceを
   参照する設計へ変更(commit `9445d25`, `cf6b629`)。
2. F004公開Catalog fragmentが最終統合に合流しておらずcatalog不整合
   → `scripts/f005-final-integration.ts`へ合流処理を追加(commit `2db2dc6`)。
3. 公開treeの`publicFiles`に作者画像evidenceが未登録
   → 追加(commit `0eb8e0b`)。
4. F005のconfigHash計算が他batchと不統一
   → `voiceConfigHashV2`へ統一(commit `a8dcb5d`)。
5. 最終blocker: `src/content/batch-public.ts`の`integrateArtworkProvenances`(F001〜F004の
   公開treeを支える共有関数)が`ArtworkProvenanceV1`(F001legacy)/`V2`(F002)/`V3`(F003)の
   3分岐しか持たず、F005が導入する`ArtworkProvenanceV4`
   (`src/content/f005-artwork.ts`で定義・検証ロジック実装済み)を
   `PUBLIC_REFERENCE_MISSING: 作者画像provenance schema validatorが未登録です: F005`で拒否していた。

本CHGは上記5.のみを対象とする(1〜4は個別commitで既に解消済み)。

## 変更内容

`src/content/batch-public.ts`の`integrateArtworkProvenances`へ`F005`分岐を追加した。

- schema validator未登録エラーの判定条件に`F005`を追加。
- `author.introducedByBatchId === 'F005'`のとき、既存のV2/V3向け
  `validateArtworkProvenance`呼び出しの代わりに、`f005-artwork.ts`の
  `parseAndRehydrateF005ArtworkProvenance`(生JSONをF005ApprovedBatchContext・生成入力・最終画像へ
  再結合し同一sealを再計算できたものだけをrehydrateする)と
  `verifyF005ArtworkAgainstCatalog`(既存3作者画像とのbyte一致・dHash距離8以下の近似重複を拒否する)を
  呼び出す。これらは`scripts/f005-final-integration.ts`が内部検証で既に使用し動作確認済みの関数を
  そのまま再利用しており、新規に複雑なロジックを書き下ろしていない。
- `F005ApprovedBatchContext`は`f005-context.ts`の`loadVerifiedF005Definition(workspace)`から取得。
  最終画像バイト列は既にbuildIntegratedPublicTreeの先行処理でhash検証済み・staging済みの
  `author.artwork.path`から読み取る。既存3作者の比較画像も同様にstagingから読み取る
  (staging内ファイルは全てcopyVerifiedで実体検証済みのため、workspace直接読取と同等の信頼性)。
- 検証済みacceptanceの`path`/`sha256`がcatalog上の`author.artwork.path`/`author.artwork.sha256`と
  一致することを確認し、不一致時は既存パターン通り`PublicIntegrationError('PUBLIC_ARTWORK_PROVENANCE_INVALID', ...)`を投げる。
- 検証後の`ArtworkCreditManifest`構築・公開manifest書き出し・bundle集約は、F002/F003と共有の
  `assertArtworkProvenanceMatches`/`artworkCreditFromProvenance`(`notices/artwork-bundle.ts`)を
  そのまま再利用した。両関数は`rawManifest.output.path ?? rawManifest.output.publicPath`という
  fallbackを既に持っており、V4スキーマ(`output.publicPath`)に対しても変更なしで動作することを確認した。

既存のV1(F001)/V2(F002)/V3(F003)分岐のロジック・挙動は一切変更していない。

## 影響範囲

- `src/content/batch-public.ts`(F001〜F004の公開tree生成にも使われる共有コード。F005作者が
  存在する場合にのみ新分岐へ入るため、F001〜F004単体のビルド挙動には影響しない)
