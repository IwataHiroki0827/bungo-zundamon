# CHG-F005-043 active producer birth境界の固定診断

## 変更理由

commit `22b46499ab1d6519dd7d93459ea78ce1872a74cc`のActions run `31211412904`は、T-116のpost-request sealed replayを通過後、`F005_ETW_WRITE_COMPLETION_DRAIN_LATE_DIAG_WRITE_AT_OR_BEFORE_ACTIVE_RESERVATION`で安全停止した。

このcodeへ到達する候補は、`CompletedRetained` sealのparent pathに対するSystem writeで、別のactive leaseが同じparentを使用し、event QPCがactive lease予約QPC以下である。eventがactive producerのbirth QPC以下ならactive producerへは帰属できない一方、birth後ならactive producerが予約前に発生させた可能性を排除できない。現診断だけでは両者を区別できないため、認可せずactive producerのimmutable birth境界を固定分類する。

## 予定変更

### 1. 対象bucketと正本

epoch 0のlate候補集約結果がexact `WRITE_AT_OR_BEFORE_ACTIVE_RESERVATION`の場合だけ、現在の`pendingWriteLease`が保持するworker PID、process start key、process sequenceを、`registeredWorkerProcesses`のstart key正本と照合する。参照する`RegisteredWorkerProcess.StartedAtQpc`はprocess登録時に固定済みのimmutable値とし、可変`processBirthByPid`、raw ETW path、現在時刻、追加IPCは使用しない。

正本recordはstart keyで0/1件に決定し、次を全て満たす場合だけ有効とする。

- record PID、start key、process sequenceがactive leaseと一致する。
- active leaseのphase instanceがactive phaseと一致する。
- `StartedAtQpc > activePhase.StartedAtQpc`である。
- `StartedAtQpc <= activeLease.CurrentPathReservedAtQpc`である。
- 呼出元の既存bucket保証どおり`eventQpc <= activeLease.CurrentPathReservedAtQpc`である。

### 2. 固定4分類

既存bucketを次の固定順で4 codeへ細分化し、同じ位置で停止する。

1. start key正本recordがない場合: `...WRITE_ACTIVE_PRODUCER_RECORD_MISSING`
2. PID/start key/sequence/phase instanceまたはphase→birth→reservation順が不一致の場合: `...WRITE_ACTIVE_PRODUCER_TUPLE_MISMATCH`
3. `eventQpc <= StartedAtQpc`の場合: `...WRITE_AT_OR_BEFORE_ACTIVE_PRODUCER_BIRTH`
4. `StartedAtQpc < eventQpc <= active reservation`の場合: `...WRITE_AFTER_ACTIVE_PRODUCER_BIRTH`

前段bucketが異なる場合、active phase/leaseが変化した場合、eventが予約後へ変化した場合は新分類へ入れず、既存codeまたは`STATE_CHANGED`でfail-closeする。複数late seal候補でもactive producer tupleは共通であり、前段の決定的集約後に1回だけ分類する。

### 3. 認可集合と外部契約

本変更は診断のみであり、selected seal、producer tuple、binding proof、replay marker、queue、ledger、semantic map、capacity、notice、Observation、seal/lease stateを変更しない。4分類後は必ずthrowし、sealed replay、completed-write、reserved、directory等の認可へfall-throughしない。

外部exact codeは35件から39件へ限定拡張し、native reply、TypeScript bridge、runner、workflow annotationのallowlistを同期する。raw path/QPC/FileObject/identity/PID/start key/sequenceは公開しない。candidate保存、Pages公開、`public/`、`data/`条件は変更しない。

## 影響範囲

`tm.json`の`DES-F005-006`/`DES-F005-012`から、`REQ-F005-012`、`REQ-F005-013`、`FUN-F005-017`、`FUN-F005-047`、`UT-F005-017`、`UT-F005-047`、`IT-F005-005`、`QT-F005-008`、`QT-F005-009`、`T-070`、`T-116`、`T-117`を影響対象とする。

## 試験方針

- exact前段bucket、record欠落、有効recordを固定し、他bucketでは新分類を呼ばない。
- PID/start key/sequence/phase instance、phase開始QPC、birth QPC、active reservation QPCのall-trueと各falseを固定する。
- phase開始/birth同値・+1、birth/reservation同値・+1、event/birthの-1・同値・+1、event/reservation同値・+1を固定する。
- start key lookupが0/1に決定し、PID再利用後の`processBirthByPid`を参照しないことを構造試験で固定する。
- 分類後に全認可へfall-throughせず、失敗前後のledger、queue、semantic、capacity、notice、Observation、seal、leaseが不変であることを確認する。
- external 39 code、127文字上限、unknown/extra/exact 128文字generic化、native/bridge/runner/workflow同期を確認する。
- native規則、関連Vitest、typecheck、ESLint、trace_check、再現build 2回、独立受入、同一source SHAのhosted productionを実施する。

## 承認

認可・要求を変更しないdesign変更であり、要求承認ゲートは設けない。独立設計レビュー、実装、影響試験、hosted再観測まで`in-review`を維持する。

独立設計レビューは初回High 0 / Medium 0 / Low 1で、`eventQpc < StartedAtQpc`の代表境界不足を指摘した。birth-1を試験方針へ追加し、active lease/active phaseのphase instance照合も明示した再レビューはHigh 0 / Medium 0 / Low 0でPASSした。exact前段bucket、immutable start key record、4分類の排他・網羅、非認可・非fall-through、39 code同期が妥当と判定された。
