# CHG-F005-005 終了済みJob childの遅延ETW認可

## 変更理由

GitHub Actions run `30501840477`で、夢十夜の最初のWAVを書き込んだnative helperが正常終了した後にFileIO ETW callbackが遅延到着し、保持済みprocess handleを`job.Contains()`へ渡した判定が「終了済み」を「Job外」と同一視して`F005_ETW_PID_NOT_JOB_MEMBER_RETAINED_OUTSIDE_JOB`で安全停止した。

## 変更内容

- childを最初に認可するときは、従来どおり同じprocess handleの生存、Job所属、ProcessSequenceNumber、存在する場合のprocess start keyを完全照合する。
- 一度認証して保持したhandleが生存中なら、Job外またはJob照会失敗をescapeとして拒否する。
- 保持handleがsignaledなら、同じProcessSequenceNumber・start key・ProcessStart QPCへ結合された遅延ETWだけを正常終了後eventとして受理する。
- PIDからprocess handleを引き直さず、保持handleをsession終了まで維持するため、PID再利用された別processを元childへ帰属させない。
- `WAIT_TIMEOUT`以外の異常値とJob照会失敗は従来どおりfail-closedとする。

## セキュリティ境界

終了済みprocessをPID一致だけで受理しない。Job内での初回認証に成功した保持handleとboot一意のProcessSequenceNumberを必須とし、生存中のJob外process、process世代不一致、start key不一致、birth QPC以前のeventは引き続き拒否する。
