# CHG-F005-014 完了済みwriteの遅延System SetInfo再結合

## 変更理由

GitHub Actions run `30511757503`は`CACHE_WAV_FILE_DONE_ID`で安全停止し、lease終了後に到着したSystem `SetInfo`が同一voice phaseで完了したWAVのnative identityと一致することを確認した。候補生成を安全に継続するには、この完全一致eventだけを元のJob worker世代へ再結合し、それ以外を従来どおり拒否する必要がある。

## 変更内容

- 完了write台帳へworker PID、`ProcessSequenceNumber`、phase instance、target予約QPC、native identityを内部保持する。
- 通常のJob member認可とactive write lease認可が失敗した後に限り、完了write遅延System `SetInfo`の専用認可を評価する。
- `BIRTH_MISSING`、System PID 0/4、`setinfo`、非0かつ未結合または同一path/identity結合済みのFileObject、同一phase instance、target予約後かつwrite完了時刻以下のQPC、現実体あり、native identity完全一致の全条件を満たす場合だけ元worker PID/sequenceへ再結合する。再結合後、容量算入直前にもidentityを再照合してTOCTOU差替えを停止する。
- 1条件でも不一致なら既存の固定診断で停止する。write/rename/delete、別phase、予約以前、write完了後、別FileObject binding、欠落、同名差替えは認可しない。

## セキュリティ境界

再結合にはpathキーとnative identityの両方、予約から完了までの閉区間QPC、FileObject binding互換を要求し、PID一致だけでは認可しない。認可時と容量算入直前の二重identity照合で差替え窓を閉じる。完了台帳はvoice phase限定・最大128件・phase境界消去を維持する。外部processのwriteは従来のJob認可で停止し、System metadata event以外へ例外を広げない。公開codeへ内部tupleを出力しない。

CHG-F005-014反映後のnative pinはProgram SHA-256 `2e81bb335decb82010e9dfa8097b92fe9b0fdc650d59ef7b92398eeb5da763b3`、output binary SHA-256 `4dcacd9ad7c5701c6a2760eb79273a975abc8a06a88dcf4e91d30e8c50e9d72f`、75,024,220 bytesとする。

## 検証

- PID 0/4の正常完全一致と、authorization failure、PID、operation、FileObject、phase、予約前QPC、完了後QPC、別binding、実体、identityの各単独不一致をpure ruleで検査する。
- 再結合が通常Job認可とactive lease認可の後段にあり、元worker PID/sequenceだけを復元することをsource試験で固定する。
- native規則、対象回帰、型、ESLint、再現build、trace、独立レビュー後にhosted productionを再試験する。

2026-07-30に対象5 test file 124件、native規則64件、型検査、ESLint、再現build 2回、YAML、trace、差分検査がPASSした。通常Job→active lease→completed fallbackの順序、QPC閉区間、FileObject binding互換、identity二重照合、元worker PID/sequence復元、全条件の単独否定を自動試験した。Program SHA-256、binary SHA-256、bytesは上記pinへ一致し、`public/`と`data/`の差分は0件である。独立セキュリティレビューはHigh 0、Medium 0、Low 0でPASSした。
