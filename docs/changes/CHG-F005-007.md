# CHG-F005-007 same-handle rename targetの事前予約

## 変更理由

GitHub Actions run `30505547616`はtemporary fileの書込みとcreate通知認証を通過した後、同一handleを最終WAV名へrenameする区間で`F005_ETW_PID_NOT_JOB_MEMBER_SYSTEM_PROCESS_UNBOUND_FILE_OBJECT_SETINFO_UNKNOWN_PATH`へ安全停止した。CHG-F005-006はtemporary pathだけを予約しており、rename syscall中にSystem PID 0/4の`SetInfo`が新pathでrename通知より先着する順序を認可できなかった。

## 変更内容

- root pipe clientはnative helperへrenameを指示する前に、現在pathとexact target pathを容量guardへ送る。
- guardはactive voice phase、root client、同じJob child process generation、結合済みFileObject・file identity、target不在を検証し、target pathと予約QPCをleaseへ封印する。
- System `SetInfo`の唯一の追加許可は、予約後QPCのexact target path、同じFileObject、same identityに限定する。System write/create/rename/deleteは引き続き拒否する。
- rename通知は予約済みfrom/toと一致する場合だけlease pathを更新し、target予約QPCを新current pathの下限へ昇格して予約を消費する。未消費rename予約がある間はcompleteとphase closeを拒否する。

## セキュリティ境界

target pathの推測やrename後通知だけではSystem eventを代理帰属させない。rename syscall前に認証済みrootがexact targetを予約し、既に結合済みのproducer process generation・FileObject・file identityと予約後QPCが完全一致する場合だけ受理する。通知後もtargetのQPC下限をrename予約時刻へ維持し、遅延到着した予約前eventを認可しない。target既存、予約前event、別path/FileObject/identity、二重予約、未消費予約は固定codeでfail-closedとし、候補branchと公開treeを変更しない。
