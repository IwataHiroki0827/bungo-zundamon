# CHG-F005-018 完了後500ms限定再結合

## 変更理由

GitHub Actions run `30515251601`は`F005_ETW_COMPLETED_WRITE_REJOIN_AFTER_COMPLETION_WITHIN_500MS`で安全停止した。同一WAV・同一native identityのSystem SetInfoはwrite完了後100ms超500ms以内であり、現行の完了QPC上限だけが完全tupleの再結合を拒否している。

## 変更内容

- 完了write再結合の時間条件を、予約後かつ完了QPC以前から、予約後かつ完了後500ms以内へ限定拡張する。
- 500ms判定はETW `TimeStampQPC`と`Stopwatch.Frequency`の同一QPC clockで行い、上限ちょうどを許可し、1 tick超過を拒否する。
- `BIRTH_MISSING`、System PID 0/4、SetInfo、非0 FileObject、同一phase/path、互換FileObject binding、現存同一identity、認可後identity再照合の全条件を維持する。
- 再結合したeventは従来どおり容量actualへ算入し、候補保存条件を緩和しない。

## セキュリティ境界

完了台帳はvoice phaseだけ、最大128 path、phase終了でclearする。500ms超、別path/phase/identity、非互換FileObject、実体欠落、TOCTOU差替えはfail-closedを維持する。時間条件単独では認可せず、固定完全tupleの一条件としてのみ使用する。

CHG-F005-018反映後のnative pinはProgram SHA-256 `ea0ed4b365142c3d8e6c17acd497469c0c0edd909490a86f8113df4863daa47f`、output binary SHA-256 `454670851d27e47ad5b5b60a58e76575eba770ae47f313bb0aac4e43cf426e55`、75,024,220 bytesとする。

## 検証

- 完了QPC以前、完了後500ms上限、500ms+1 tick、不正frequencyをpure ruleで検査する。
- 他9拒否stage、FileObject binding、identity二重照合、first-poison、capacity/candidate不変を回帰検査する。
- long極値を含むnative規則90件、対象回帰124件、型、ESLint、同一SHAの再現build 2回、trace、`git diff --check`、公開差分0をPASSした。独立レビュー最終判定はHigh/Medium/Low 0件である。
- hosted productionで500ms限定再結合後のidentity・容量・候補保存を再試験する。

## 承認

安全境界内の設計変更であり要求目的・容量停止基準・公開条件は変更しないため、要求承認ゲートは設けない。hosted影響試験完了まで`in-review`を維持する。
