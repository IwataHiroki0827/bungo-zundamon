# CHG-F005-034 pending rename消費後のbound FileObject path固定診断

## 変更理由

commit `12cc0b9c4afe3ba824696afef28dab01c4deab86`のActions run `31032629020`は、CHG-F005-033の`AFTER_LEASE_RESERVATION`限定再結合を通過し、`audio-renamed`後に`F005_ETW_PID_NOT_JOB_MEMBER_SYSTEM_PROCESS_BOUND_FILE_OBJECT_REJOIN_RENAME_LEASE_PATH_PATH_MISSING`へ安全停止した。T-106の専用14 stageへ到達したためQ-034は解消したが、pending renameがない状態でactive leaseと異なる既知bound FileObject pathが観測された理由を生値なしで識別できない。

## 予定変更

既存の`REJOIN_RENAME_LEASE_PATH_PATH_MISSING`失敗だけを対象に、認可を変更せず次の固定stageへ細分化する。

- 観測pathがfile、directory、その他のどれかを固定分類する。
- directoryの場合は、既存のdirectory snapshot/current identity、同一phase root owner/root active、active leaseのphase・親path・closed・FileObject/snapshot/binding・current identity・Job状態を同じ評価順で再利用する。
- active lease current pathが欠落する場合は、この分岐ではpending targetがないことが確定しているため、到達不能なrename後段へ進めず`NO_PENDING_DIR_LEASE_CURRENT_MISSING`へ固定する。
- suffixは`NO_PENDING_PATH_*`と`NO_PENDING_DIR_*`の短い固定namespaceとし、全codeを127文字以下にする。
- 旧exact `...PATH_MISSING`、未知suffix、`CANDIDATE`を含む全stageをfail-closedとし、自動認可、容量actual確定、候補保存、公開tree変更へ接続しない。

raw path、QPC、identity、FileObject値は公開しない。固定codeだけをTypeScript bridgeとrunnerへ伝播する。

### 固定stageと評価順

外側の既存分岐で、bound FileObject snapshot有、snapshot path一致、current有、identity一致、active lease有、phase一致、lease path不一致、pending targetなしまでを保証する。その後を次の順序で評価する。

1. `File.Exists`なら`NO_PENDING_FILE`で即時停止する。
2. `Directory.Exists`でなければ`NO_PENDING_OTHER`で即時停止する。directoryだけを後段評価へ進める。
3. directory snapshotがなければ`NO_PENDING_DIR_SNAPSHOT_MISSING`、currentがなければ`NO_PENDING_DIR_CURRENT_MISSING`、identity不一致なら`NO_PENDING_DIR_ID_MISMATCH`、同一phase root ownerがなければ`NO_PENDING_DIR_OWNER_MISSING`、root inactiveなら`NO_PENDING_DIR_ROOT_INACTIVE`、既存分類外なら`NO_PENDING_DIR_UNKNOWN`とする。
4. active leaseがdirectory直下でなければ`NO_PENDING_LEASE_PARENT`、closedなら`NO_PENDING_LEASE_CLOSED`、FileObject未結合なら`NO_PENDING_LEASE_UNBOUND`、snapshotなしなら`NO_PENDING_LEASE_SNAPSHOT_MISSING`、bindingなしなら`NO_PENDING_LEASE_BINDING_MISSING`、binding path/identity不一致なら`NO_PENDING_LEASE_BINDING_MISMATCH`とする。
5. lease current pathがなければ`NO_PENDING_LEASE_CURRENT_MISSING`、identity不一致なら`NO_PENDING_LEASE_ID_MISMATCH`、lease workerがJob外でaliveなら`NO_PENDING_LEASE_ESCAPE`、全件一致なら`NO_PENDING_CANDIDATE`として停止する。
6. 外側で保証済みのlease存在・phase一致が既存helperから不一致として返るなど、到達不能状態は`NO_PENDING_STATE_DRIFT`へ固定して停止する。

上記19 suffixをexact集合とする。full code長は83〜101文字であり、127文字上限を満たす。

## 影響範囲

## 承認

既承認の容量guard内で認可を変更しないdesign診断追加であり、要求承認ゲートは設けない。影響文書更新、独立レビュー、影響試験、hosted再試験まで`in-review`とする。

計画レビューは初回High 0 / Medium 2 / Low 0を受け、exact 19 suffixと評価順、83〜101文字のcode長、文書・pin・hosted試験方針を追記した。再レビューはHigh 0 / Medium 0 / Low 0でPASSした。

## 試験方針

- native規則試験で上記19 suffix、path種別の即時return、directory bound leaseの評価順、pending targetなしのlease current欠落、到達不能drift、`CANDIDATE`までの排他性を固定する。
- TypeScript exact union/anchored regex/runnerで全固定code、83〜101文字、旧exact・未知suffixのgeneric化、生値非公開を確認する。
- 構造試験で既存`PATH_MISSING`分岐だけが新診断へ入り、認可helper、容量actual、candidate・`public/`・`data/`を変更しないことを確認する。
- DD-F005、UT-F005、IT-F005、QT-F005と本CHGへ評価順、影響試験、hosted判定を反映する。
- Program SHA-256、output binary SHA-256、bytesをbuild evidence、build script、source pin、設計文書で同期し、同一SHA再現buildを2回行う。
- commit固定hosted試験で新固定stageを取得し、旧exact・未知suffixが受理されないこと、candidate branch未作成、Pages deploy skip、`public/`・`data/`差分0を確認する。
