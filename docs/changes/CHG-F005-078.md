# CHG-F005-078 F005受理時にactualCapacityRef/rightsSnapshotIdsが書かれない不備を修正する

## 変更理由

T-073で`scripts/f005-final-integration.ts`が`BATCH_ARTIFACT_MISSING`で停止した。
原因は`src/content/f005-acceptance.ts`のacceptedへの状態遷移(`finalizeF005WorkAcceptance`)が、
work単位の`actualCapacityRef`とbatch単位の`rightsSnapshotIds`を一度も
`content/batches/F005/batch.json`へ書き込んでいなかったこと。

- `actualCapacityRef`: F002〜F004は共有の`appendActualEvidence`(`batch-runtime.ts`)が
  voiced段階でwork recordへ先に書き込み、`transitionWorkState`のaccepted分岐は
  `...current`のspreadでそれを保持するだけで足りる。F005はこの中間書き込みを経由せず、
  actual容量report自体(`content/batches/F005/capacity-actual/{workId}/{journalId}.json`)は
  生成・検証(`verifyActualCapacityBinding`)されるのに、manifestへの反映が抜けていた。
- `rightsSnapshotIds`: F002〜F004は共有の`transitionBatchState('rights-verified', ...)`が
  batch作成初期に`rightsSnapshotIds`を設定する。F005 batchはこの共有batch-level遷移を
  一度も経由せず(`batch.stageRecords`が空のまま`status`はwork進捗から自動導出される設計)、
  そのため`rightsSnapshotIds`が空配列のまま残っていた。

## 変更内容

### 恒久修正(コード)

- `src/content/batch.ts`
  - `PreparedWorkAcceptanceEvidence`へ任意項目`actualCapacityRef`・`rightsSnapshotIds`を追加。
  - `validatePreparedEvidence`で両項目が存在する場合の形式検証(safe path / string array)を追加。
  - `transitionWorkState`のaccepted分岐で、`evidence.actualCapacityRef`が存在すれば
    `updatedWork.actualCapacityRef`へ反映する(未指定ならF002〜F004同様`...current`保持のみ)。
  - `transitionWorkState`の戻り値manifestで、`evidence.rightsSnapshotIds`が存在すれば
    batch全体の`rightsSnapshotIds`を上書きする(未指定なら既存値を維持)。
  - いずれも既存のevidence(`kind: 'stage'`、または`actualCapacityRef`/`rightsSnapshotIds`を
    指定しない`kind: 'accepted'`)には影響しない後方互換な追加。
- `src/content/f005-acceptance.ts`
  - `finalizeF005WorkAcceptance`: accepted evidence構築時に、既に検証済みの
    `actualRef.path`(= `journal.actualCapacityReportPath`)を`actualCapacityRef`として付与。
    `manifest.rightsSnapshotIds`が空の場合のみ、新設ヘルパー`readF005RightsSnapshotIds`で
    `content/batches/F005/source-snapshots/selection.json`の`policies[].decision.contentSha256`
    (選定時に検証済みのcanonical evidence)から`${policyId}:${contentSha256}`形式へ変換して付与。
  - `validateManifestNextTemp`(crash-recovery時のexpected manifest再構築)にも同じevidence拡張を
    再現する変更を加え、recoveryのsealed bytes一致検証が新manifest構造とも整合するようにした。
  - 新設ヘルパー`readF005RightsSnapshotIds`はcanonical JSON一致・schema/kind/batchId一致・
    `decision.decision === 'allow'`・`artifact.sha256 === decision.contentSha256`を検証してから
    値を返す(捏造・改変耐性)。

### バックフィル(既存accepted 3作品の是正)

work状態遷移はforward-onlyであり、既にaccepted確定済みの3作品を通常フローで
やり直すことはできない。そのため一回限りのスクリプト
`scripts/f005-backfill-acceptance-evidence.ts`を新規作成し(実行後も削除せず記録として残す)、
下記の実evidenceから機械的に値を導出してbatch.jsonへ直接書き込んだ。値は捏造せず、
実ファイルを読み込みSHA256/schemaを検証してから採用している。

- `actualCapacityRef`(work単位、3件): `content/batches/F005/capacity-actual/{workId}/`配下に
  実在する一意な`{journalId}.json`のpathをそのまま採用。journalIdは対応する
  `voiceEvidenceRef`(`content/batches/F005/work-artifacts/{workId}/runs/{journalId}/voice-generation.json`)の
  run識別子と一致することを確認済み。
- `rightsSnapshotIds`(batch単位): `content/batches/F005/source-snapshots/selection.json`の
  `policies[]`(voicevox-terms / zundamon-audio-terms / zundamon-character-guideline)から
  `decision.contentSha256`(= `artifact.sha256`、選定時2026-07-29T04:18:45Zに取得・検証済み)を
  読み取り、`${policyId}:${contentSha256}`形式で3件生成。

  実際に書き込んだ値:
  - `voicevox-terms:10dbc1bafcbe612378b998e96882809970f1591194ab2851669e11805feff40b`
  - `zundamon-audio-terms:d249b088ad9562edd123397422864d32765f183d7e4f60c857a100f4228572ec`
  - `zundamon-character-guideline:d1c146255cac9e3d9432b73787c22b6faf33df4454fc314720ceb9c1c0bf115d`

  なお2026-08-19の規約再確認(`docs/evidence/rights/F005-policy-recheck-2026-08-19.md`)は
  上記選定時SHAとその時点の最新取得SHAを比較し「実質的変更なし」と判定済み
  (`content/batches/F005/rights-adjudications.json`)。選定時SHAを採用するのは、
  F002〜F004の`rightsSnapshotIds`が「rights-verified遷移時点で検証した規約」を記録する
  設計だからであり、それに対応するF005側の時点は選定時(extraction判定の根拠)である。

書込みは`writeJsonArtifactAtomic`(`expectedFingerprint`によるCAS、temp+rename)で行い、
`validateBatchManifest`で事前検証してから確定させた。
