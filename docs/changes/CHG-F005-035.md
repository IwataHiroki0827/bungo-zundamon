# CHG-F005-035 pendingなしbound directory writeとunbound leaseの固定診断

## 変更理由

commit `e3f85b32b9dfe14b6b219c5471ff1ad4170de358`のActions run `31035627381`は、attempt 1で既知のdirectory lease binding不一致へ安全停止し、attempt 2でCHG-F005-034の新stage `F005_ETW_PID_NOT_JOB_MEMBER_SYSTEM_PROCESS_BOUND_FILE_OBJECT_REJOIN_NO_PENDING_LEASE_UNBOUND`へ到達した。観測pathは既知bound directoryの完全候補まで進んだ一方、active leaseはFileObject未結合であり、lease予約・current path・deferred correlation・process状態との関係が未確定である。

## 予定変更

既存の`REJOIN_NO_PENDING_LEASE_UNBOUND`失敗だけを対象に、認可を変更せず次の固定stageへ細分化する。

1. lease snapshotが既に存在する不変条件違反を`UNBOUND_SNAPSHOT_PRESENT`へ固定する。
2. event QPCがlease `CurrentPathReservedAtQpc`以下なら`UNBOUND_BEFORE_RESERVATION`へ固定する。eventが予約QPCと同値なら拒否し、予約QPC + 1 tickだけを後段候補にする。
3. lease current pathの再open取得に失敗したら`UNBOUND_CURRENT_INSPECTION_FAILED`、欠落なら`UNBOUND_CURRENT_MISSING`へ固定する。
4. deferred System SetInfoが0件なら`UNBOUND_DEFERRED_MISSING`、exact 1件でないか、次のtupleのどれかが不一致なら`UNBOUND_DEFERRED_TUPLE`へ固定する。
   - `WorkerPid`と`ProducerSequenceNumber`がlease保存値と一致する。
   - `Phase`と`WorkId`がactive phaseと一致し、`PhaseInstanceId`がleaseとactive phaseの双方に一致する。
   - `RelativePath`とsnapshot pathがlease current pathと一致する。
   - FileObjectが非zeroで、現在の`filesByObject`に未結合である。
   - `CurrentPathReservedAtQpc < deferred QPC <= event QPC`である。deferred QPCの予約同値は拒否、予約 + 1 tickとevent同値は候補、event + 1 tickは拒否する。
5. 再openしたlease current identityがdeferred snapshot identityと不一致なら`UNBOUND_CURRENT_ID_MISMATCH`へ固定する。
6. 保持process handleのinspectionはidentity取得、wait、alive時だけJob照会の順に行い、wait、identity、Job照会失敗をそれぞれ`UNBOUND_PROCESS_WAIT_FAILED`、`UNBOUND_PROCESS_IDENTITY_FAILED`、`UNBOUND_JOB_QUERY_FAILED`へ固定する。取得PID/start key/sequenceがlease保存値と不一致なら`UNBOUND_PROCESS_TUPLE`へ固定する。
7. 同一世代processがsignaledならJob照会せず`UNBOUND_PROCESS_SIGNALED`、aliveかつJob外なら`UNBOUND_LEASE_ESCAPE`、aliveかつJob memberの全件一致だけを`UNBOUND_CANDIDATE`へ固定する。

上記14 suffixをexact集合とし、既存bound FileObject外側tuple、directory/root候補、lease phase/parent/open、FileObject未結合、pending targetなしの評価順を維持する。full code長は96〜112文字で127文字上限を満たす。旧exact `...NO_PENDING_LEASE_UNBOUND`、未知suffix、`UNBOUND_CANDIDATE`を含む全stageをfail-closedとし、自動認可、lease binding、容量actual確定、候補保存、公開tree変更へ接続しない。raw path、QPC、identity、FileObject値は公開しない。

## 影響範囲

`tm.json`とFUN-F005-047の容量guard経路から、`REQ-F005-012`、`REQ-F005-013`、`DES-F005-006`、`FUN-F005-047`、`UT-F005-047`、`IT-F005-005`、`QT-F005-008`を影響対象とする。

## 承認

既承認の容量guard内で認可を変更しないdesign診断追加であり、要求承認ゲートは設けない。影響文書更新、独立レビュー、影響試験、hosted再試験まで`in-review`とする。

計画レビューは初回High 0 / Medium 2 / Low 0を受け、deferred完全tuple、current再照合、QPC境界、process inspection順を追記した。再レビューはHigh 0 / Medium 0 / Low 0でPASSした。
