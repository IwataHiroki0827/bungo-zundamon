# CHG-F005-003 native buildのcheckout path・commit非依存化

## 変更理由

T-070の手動操作不要な実行環境を探索するためGitHub hosted Windowsで固定native guardをbuildしたところ、source・SDK・runtime・project設定が同一でも、ローカル固定値と異なるbinary SHA-256になった。別の絶対pathへ同じsourceを配置する再現試験とcommit後の再buildにより、single-file publishへcheckout絶対pathとGit commit SHAが混入することを確認した。

安全境界であるbinary pinは維持し、固定source rootへ正規化するMSBuild `PathMap`とsource revisionのinformational version非埋込みをbuild入力へ追加して、実行場所・commitに依存しない同一binaryを得る。source・project自体のSHAはbuild evidenceで引き続き直接検証する。

## 変更内容

- `dotnet publish`へ`PathMap=<native絶対path>=/_/native/f005-guard`を明示する。
- `IncludeSourceRevisionInInformationalVersion=false`を明示し、Git commit SHAをbinary metadataへ埋め込まない。
- 固定SDK `9.0.316`、runtime `9.0.18`、RID `win-x64`、既存ABIは変更しない。
- Git管理下、source-only別path、GitHub hosted Windowsの3 buildが一致するbinary SHA-256 `1846897edcc399e62ce91a6075e0271e60c9bd431123aa965586eafdc4069813`へpinを更新する。
- source pin、build script、build evidence、hosted probeの3者を同じ値へ結合し、差があれば従来どおりfail-closedとする。
- hosted probeはnative関係fileの変更でも自動起動し、build結果とkernel ETW preflight結果をsource commit固有のevidence branchへ保存する。

## リスクと対策

- source path・commit情報を正規化してもsource・project・SDK・runtimeの個別SHA照合は維持する。
- output binary SHAは更新後の実buildから取得し、推測値を採用しない。
- hosted probeはcontent生成と公開を行わず、ETW能力の確認だけを実施する。
- `public/`は変更せず、公開済みv0.4.0のtreeを前後でexact比較する。

## 承認

既存要求、ABI、実行時安全境界を変更しない設計レベルの再現性修正であるため、要求承認ゲートは設けない。

設計独立再レビューは2回ともHigh/Medium/Low 0でPASSした。Git管理下とsource-only別pathのbuild、固定commit後の正式buildはすべて74,958,684 bytes・SHA-256 `1846897edcc399e62ce91a6075e0271e60c9bd431123aa965586eafdc4069813`で一致した。重点4 files 97 tests、全70 files 1,241 tests、typecheck、lint、697 files build、依存監査0、`public/` 694 files / 229,844,709 bytes・差分0をPASSした。

GitHub Actions run `30445446783`はcommit `196260407b99bed8f6978016d659b3847683c4bb`をWindows X64でbuildし、同じbinary SHA、容量ABI `f005-capacity-pipe-v3`、ETW `kernel-fileio`、result `pass`をcommit固有evidence branchへ保存した。これによりT-077と本変更を`done`へ閉じる。
