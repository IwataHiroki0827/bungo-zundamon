# CHG-F005-003 native buildのcheckout path非依存化

## 変更理由

T-070の手動操作不要な実行環境を探索するためGitHub hosted Windowsで固定native guardをbuildしたところ、source・SDK・runtime・project設定が同一でも、ローカル固定値と異なるbinary SHA-256になった。別の絶対pathへ同じsourceを配置する再現試験により、single-file publishへcheckout絶対pathが混入することを確認した。

安全境界であるbinary pinは維持し、固定source rootへ正規化するMSBuild `PathMap`をbuild入力へ追加して、実行場所に依存しない同一binaryを得る。

## 変更内容

- `dotnet publish`へ`PathMap=<native絶対path>=/_/native/f005-guard`を明示する。
- 固定SDK `9.0.316`、runtime `9.0.18`、RID `win-x64`、既存ABIは変更しない。
- 異なる絶対pathのローカル2 buildとGitHub hosted Windows buildが一致するbinary SHA-256 `fc73dbfff165693ff29caac5a7449dadae8842e0a90e70e0bcf269fe5883398d`へpinを更新する。
- source pin、build script、build evidence、hosted probeの3者を同じ値へ結合し、差があれば従来どおりfail-closedとする。
- hosted probeはnative関係fileの変更でも自動起動し、build結果とkernel ETW preflight結果をsource commit固有のevidence branchへ保存する。

## リスクと対策

- source path情報を正規化してもsource・project・SDK・runtimeの個別SHA照合は維持する。
- output binary SHAは更新後の実buildから取得し、推測値を採用しない。
- hosted probeはcontent生成と公開を行わず、ETW能力の確認だけを実施する。
- `public/`は変更せず、公開済みv0.4.0のtreeを前後でexact比較する。

## 承認

既存要求、ABI、実行時安全境界を変更しない設計レベルの再現性修正であるため、要求承認ゲートは設けない。影響文書の独立再レビュー、ローカル・hosted再現build、影響試験が完了するまで`in-review`を維持する。
