# CHG-F005-002 容量実測と作品受入の循環解消

## 変更理由

T-070のproduction runnerを実物へ接続する際、`CapacityActualV3`は音声・build・preview・受入の全mutationを記録したETW journalをcloseした後でしか確定できない一方、従来の`acceptF005Work`は同じsession内でmanifestを`accepted`へ遷移する前にactual report SHAを要求していた。この順序ではactual SHAを先に得られず、監視を省略するか未確定値を受け入れる以外に実行経路がない。

REQ-F005-011〜013の音声生成、actual容量測定、論理atomic受入という目的は変更せず、payload昇格とmetadata確定を二段階へ分けて循環を解消する。

## 変更内容

- work previewはclosed後にしか存在しないactual reportへ依存しない。previewはforecast、build/staging/dist、baseline不変証跡を検証する。
- ETW監視session内の`stageF005WorkAcceptance`はaudio/content artifactを論理transactionの`artifacts-committed`まで昇格する。live manifestは`voiced`のまま保持する。
- native sessionをcloseした後、`measureF005ActualCapacity`がclosed journalを再計算し、canonical actual reportを保存する。
- `finalizeF005WorkAcceptance`はactual reportの実体SHA、closed journal SHA、recorder ID、work tupleを再検証してから、actual SHA必須の`accepted` manifestをmetadata-only CASで確定する。
- native容量ABIを`f005-capacity-pipe-v3`へ更新し、work IDとcandidate SHAをclosed journal自身へsealして全phaseを同じsession workへ固定する。任意PIDの後登録を廃止し、実pipe clientのroot登録とbreakaway禁止Job継承、close時member列挙へ限定する。当時のローカル固定binary SHA-256は`a184eaa2fa9936dc63079a499fb3c062c040cec986e0b71c6d0664a3f9b23277`であり、checkout path非依存の再現可能pinへは後続`CHG-F005-003`で更新する。
- recovery trash清掃はraw path unlinkを禁止し、open時から第三者write/delete/renameを遮断したnative held capabilityのidentityとSHAをdelete直前に再照合する。同じhandleへ`FileDispositionInfo`を設定してcloseし、同名replacement、capability replay、未知capabilityは削除しない。
- native `open`はvolume serialとfile indexをcanonical `nativeIdentity`として返し、content SHAと別fieldでpre-scan snapshotへ保存する。後続delete/renameは再open時とmutation直前にexpected identityを必須照合し、同一SHAの別identity replacementも保持して競合停止する。
- accepted manifestが参照するvoice/acceptance/actual evidenceと受入phase/lockは、basenameとwhole-file SHAを含むcanonical tempのfsync、native target-absent CAS、固定native directory sync、post-readを必須とする。temp fsync直後の停止ではtarget不在ならexact schema/tuple/phase chain検証後に昇格し、target同一bytesなら走査外の一意recovery-trashへCASして削除しdurabilityだけを再確立する。bytes差、複数temp、filename/actual SHA差、未知tempは第三者値を保持する。
- final metadata CASは容量payloadを変更せず、native safe path identity、expected SHA、fsync、atomic rename、post-read SHAと`WorkAcceptanceJournalV3`で保護する。
- crash回復はtrusted root配下の全transaction directoryとtrashを一切mutationせずglobal pre-scanする。target/temp allowlist、各base最大1、canonical schema、immutable tuple、仮想phase chain、manifest exact transitionに加え、canonical actualがあればphaseに依存せず6 bucket/audio exact set/native owner-session-work-candidate-derived recorder ID/SHAをfull bindingする。capacity phaseではnext SHAとCAS前・old→backup後・next→live後の3状態だけを許可する。各target/temp/trashのnative volume/file identityをSHAと別にplanへsealし、後続rename/deleteのcapability再open/APIへexpected identityを必須入力する。invalid/missing/state差と同SHA replacementは全path/bytesを保持して停止する。全plan PASS後だけbootstrap/rollback/roll-forwardし、全削除はheld native exact identityだけを使う。

## リスクと対策

- stage後・actual生成前の停止ではacceptedを公開せず、journalと実体SHAからrollbackする。valid actual保存後は削除・上書きせず同一evidenceでfinalizeを再開する。
- actual report偽造、別session流用、stale manifestはfinalize前に拒否する。
- metadata finalize中の停止はold/new manifest SHAとactual SHAを持つjournalから再開し、中間manifestを公開状態として扱わない。
- prepared/manifest-next/journal/finalize lockのtemp fsync直後停止に加え、invalid actual＋valid prepared temp、capacity有＋manifest-next欠落、live/backup/next許可3状態外、pre-scan後rename/delete再open前の同SHA replacementを自動試験し、異常時のglobal mutation 0を確認する。
- `public/`は受入中に変更せず、既存v0.4.0 hashを前後でexact比較する。

## 承認

既存要求の閾値、作品順、受入条件を変更しない設計レベルの循環解消であるため追加の要求承認ゲートは設けない。影響文書の独立再レビューとT-076の影響再試験を完了し、`done`へ閉じた。

2026-07-29の設計文書独立再レビューで、1作品1session、V3 phase hash chain、work/session/candidate binding、actual保存後3停止窓、stage途中の逆順rollback、第三者変更拒否を確認し、High/Medium/Low 0でPASSした。実装の初回独立受入はdurable CAS、safe path、native work/candidate binding、実build結合、fault試験不足によりREDOであり、T-076は`doing`を維持する。

修正後はnative rename/deleteのexpected identityを必須化し、rename確定identityを後続deleteへ継承した。rename close後もtargetをnative identityで再open検証し、同一SHA・別identityへの差替えを削除せず競合停止する試験を追加した。重点7 files 180 tests、全70 files 1,240 tests、typecheck、lint、697 files build、依存監査0件、`git diff --check`、`public/` 694 files / 229,844,709 bytes・差分0をPASSした。最終独立実装受入はHigh/Medium/Low 0でPASSし、T-076を完了した。
