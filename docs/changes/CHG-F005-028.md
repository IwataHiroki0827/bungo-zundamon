# CHG-F005-028 System結合済みFileObject writeの固定診断

## 変更理由

GitHub Actions run `30522848642`はbound active lease中directory writeの固定診断を通過後、`F005_ETW_PID_NOT_JOB_MEMBER_SYSTEM_PROCESS_BOUND_FILE_OBJECT`で安全停止した。System PID 0/4の遅延eventが、先行する認証済みeventで登録済みのFileObjectを使用しているが、path・identity・active leaseとの関係をgeneric codeだけでは判別できない。

## 変更内容

- System PID 0/4、`BIRTH_MISSING`、結合済みFileObjectの場合だけ、snapshot、path、current、identity、active lease存在、phase、path、FileObject binding、closed、Job escapeを固定11 stageへ分類する。
- snapshot→path→current→identity→lease→phase→lease path→binding→closed→Jobの段階returnとし、上位不一致後に下位状態を評価しない。
- 旧generic `SYSTEM_PROCESS_BOUND_FILE_OBJECT`をTypeScriptとrunnerの受理リストから外し、固定11 suffixだけを伝播する。
- `CANDIDATE`を含め認可、容量actual、候補保存、公開条件は変更しない。

## セキュリティ境界

FileObject mapはgate内でのみ参照し、snapshot pathと観測path、filesystem current identity、同一phase active lease pathとFileObjectを完全一致させる。生path・identity・FileObject・PID・sequence・QPCを出力せず、未知suffixはgeneric/nullへ閉じる。

CHG-F005-028反映後のnative pinはProgram SHA-256 `7c9e8f9f41b2a0e56d456c5bf450057b838acae2bd0617bd7b43424505628bb3`、output binary SHA-256 `05f3bd5bbbccf77c70349b1000a32d765f04bad8df76a12cc5526ef9994feb5f`、75,028,316 bytesとする。

## 検証

- 固定11 stage、段階評価、旧generic拒否、未知suffix拒否、runner exact伝播、認可分岐不変を検査する。
- 初回独立レビューのLow 1件（helper呼出しのgate内配置をsource試験で未固定）を、`lock (gate)`→authorization→唯一のhelper呼出し→Poisonの順序assertで解消した。
- native規則147件、対象回帰124件、補強後回帰50件、型、ESLint、同一SHA再現build 2回、trace、差分検査、公開差分0をPASSした。最終独立レビューはHigh/Medium/Low 0件である。
- commit固定のhosted productionを再試験する。

## 承認

認可を変更しない診断追加であり、要求承認ゲートは設けない。固定stage取得と影響試験完了まで`in-review`を維持する。
