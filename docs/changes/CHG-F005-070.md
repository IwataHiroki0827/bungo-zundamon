# CHG-F005-070 別pathへbindされたevent FileObjectの関係固定診断

## 変更理由

CHG-F005-069 hosted run `31666533719` attempt 1は `audio-renamed` 後に
`...POST_UPPER_PROOF_PARENT_BOUND_EVENT_FO_BOUND_OTHER_PATH` で安全停止した。

これによりlate eventのFileObjectはledger上State Boundであり、active leaseのpathとは
異なるpathへbindされていることが確定した。一方でevent自体のpath（`normalized`）は
親directoryであり、同一FileObject値がdirectory eventとして観測されている。

現在の停止点はそのbind先pathが「active lease以外」であることしか示さない。もっとも
有力な仮説はkernelがFILE_OBJECTのアドレスを解放後に別fileへ再割当てし、ledgerが
旧bindingを保持し続けているアドレス再利用である。これを判定するには、bind先pathが
現候補集合（同一voice phaseの他WAV）に属するのか、event directoryそのものなのか、
同一親配下の未知fileなのか、別親配下なのかを分離する必要がある。

認可・handoff・再結合条件・候補保存条件は一切変更せず、関係だけを固定分類する。

## 変更内容

`WriteCompletionBindingLedger.MatchEventFileObject` を、単一 `TryGetValue` exact 1回の
ままoverloadで拡張する。既存2引数版は互換のため残し、新版が
`EventFileObjectBoundPathRelation` をout引数で同時に返す。追加入力はevent directory、
候補seal群のCurrentPath集合、候補seal群のParentPath集合であり、いずれも既に
authorize経路が保持している値をそのまま渡す。

関係は次の順で確定する。fileObject 0、active lease path未指定、event directory未指定、
候補集合null、entry不在、State非Bound、bind先path空、bind先pathがactive lease pathと
一致のいずれかは `Invalid` とする。以降、bind先pathがevent directoryと一致なら
`EventDirectory`、候補CurrentPath集合に含まれるなら `CandidateCurrentPath`、
候補ParentPath集合に含まれるなら `CandidateParentPath`、bind先pathの親が
event directoryと一致なら `SameParentFile`、それ以外を `DifferentParent` とする。

`ParentBoundActiveLeaseFailureCode` は評価順・既存分岐を変更せず、
`EventFileObjectMatchResult.BoundOtherPath` の分岐だけを関係別の固定codeへ差し替える。
共通prefixは `...POST_UPPER_PROOF_PARENT_BOUND_EVENT_FO_` とし、suffixは次の6種とする。

- `OTHER_EVENT_DIR` — bind先がevent directoryそのもの
- `OTHER_CANDIDATE_CURRENT` — bind先が候補sealのCurrentPath（同一phaseの他WAV）
- `OTHER_CANDIDATE_PARENT` — bind先が候補sealのParentPath
- `OTHER_SAME_PARENT_FILE` — bind先の親がevent directoryだが候補集合外
- `OTHER_DIFFERENT_PARENT` — bind先の親がevent directoryと異なる
- `OTHER_RELATION_INVALID` — 関係lookupが `Invalid` を返した場合

関係引数がnullまたはenum未定義値の場合は後段前に `STATE_CHANGED` へ閉じる。
旧 `BOUND_OTHER_PATH` は互換・他経路のために残し、新6 code追加で外部code集合を
97から103へ同期する。raw path・raw FileObject・件数・entry値はいずれも返さない。

候補生成、handoff、OtherBound admission/apply、semantic map、auth fingerprint、
active lease、state、容量actual、候補保存条件、公開条件は変更しない。

## 試験方針

- 6 codeそれぞれの単独到達と、CHG-F005-069までの既存validationが優先されることを固定する。
- 関係判定の優先順（EventDirectory > CandidateCurrentPath > CandidateParentPath >
  SameParentFile > DifferentParent）を境界込みで固定する。
- `Invalid` を返す全前提違反（fileObject 0、entry不在、State Bound以外、path空、
  active lease path一致、候補集合null）を固定する。
- ledger lookupが拡張後も exact 1回であることを回帰する。
- null・enum未定義値の `STATE_CHANGED` を固定し、後段への到達0を確認する。
- 103 code同期、raw値非公開、127文字上限、semantic/auth fingerprint不変、
  `public/`・`data/` 差分0を回帰する。
- native全件、固定target suite（57/43/74/52）、Vitest、typecheck、ESLint、
  同一SHA再現build 2回、hosted影響試験を実施する。
