# CHG-F005-059 reservation snapshot STATE_CHANGED軸の固定診断

## 変更理由

CHG-F005-058/T-132のproduction run `31248931250`は予約snapshotのinitial/current境界分割後、`F005_ETW_WRITE_COMPLETION_DRAIN_STATE_CHANGED`で候補保存前に安全停止した。現規則はregistered record再出現、active lease/phase差、current予約逆転、event current予約超過を同一codeへ集約しているため、認可を変更せず原因軸だけを固定する。

## 変更内容

production call-siteと`ReservationProducerBirthFailureCode`の実到達可能な矛盾条件を、次の優先順で固定分類する。

1. snapshot分類時にactive phase instanceと差がある場合は`...ACTIVE_PRODUCER_RESERVATION_STATE_ACTIVE_PHASE_CHANGED`。
2. `currentPathReservedAtQpc < initialLeaseReservedAtQpc`は`...ACTIVE_PRODUCER_RESERVATION_STATE_CURRENT_BEFORE_INITIAL`。

複数矛盾は上記の先行codeへ閉じる。既存snapshot missing、tuple mismatch、birth/initial/current境界、認可、handoff、state更新、candidate保存条件は変更しない。入力は同一gateで既に取得済みのbool/scalarだけとし、再lock、再参照、wait、現在時刻取得を追加しない。

先行するbroad/aggregate分類と同一gateの線形化により、対象branchではactive lease/phase存在と`event <= current`が保証される。`activeLease`は同じgate内で`pendingWriteLease`から取得後に再代入・wait・gate解放がないため参照差も到達不能である。直前のrecord missing分類によりregistered record不在も保証される。これら防御入力は既存`STATE_CHANGED`を維持し、構造試験でproduction非到達を固定する。

新2 codeをcompletion-drain exact集合へ追加して57から59へ更新し、native reply、TypeScript bridge、runner、production workflow regexを同期する。各codeは127文字以下とし、生QPC、path、PID、FileObject、identity、sequence、handle、候補数を公開しない。`STATE_CHANGED`自体は他経路と到達不能入力の外部互換契約として維持する。

## 影響範囲

`REQ-F005-012`、`REQ-F005-013`、`DES-F005-006`、`DES-F005-012`、`FUN-F005-017`、`FUN-F005-047`、`UT-F005-017`、`UT-F005-047`、`IT-F005-005`、`QT-F005-008`、`QT-F005-009`、`T-070`、`T-132`を対象とし、実装・再試験タスクとして`T-133`を追加する。

## 試験方針

- phase instance差とcurrent<initialの各単独・複数異常を固定し、先行順位と排他分類を検査する。
- active lease/phase欠落、event超過、pending lease差、record再出現、inner event違反がproduction call-siteから到達不能であることを構造・一気通貫fixtureで固定する。
- 既存missing/tuple/birth/initial/current分類と後段非fall-through、semantic fingerprint不変を回帰する。
- completion-drain 59 code、予約fence4 code、127文字、unknown/extra/exact128 generic化をnative/bridge/runner/workflowで同期する。
- native通常suite、T-109/T-110/T-122/T-112、関連Vitest、typecheck、ESLint、trace_check、再現build 2回、独立受け入れ後にhosted productionを実施する。

## 承認

既承認の認可・proof・lease binding・capacity・candidate保存・公開条件を変更しないdesign-level固定診断である。要求承認ゲートは設けず、独立設計レビュー、T-133実装、local/hosted影響試験完了まで`in-review`を維持する。

## 独立設計レビュー

初回レビューで5軸中2軸、修正版レビューで6軸中4軸が先行分類・同一gateの保証によりproduction到達不能と判明した。call pathを再追跡し、実到達可能なphase instance差とcurrent予約逆転の2軸だけへ限定した。最終再レビューはHigh 0 / Medium 0 / Low 0でPASSし、到達不能な防御入力の既存STATE_CHANGED維持、59 code同期、認可・state・handoff・公開条件非変更に残指摘はない。
