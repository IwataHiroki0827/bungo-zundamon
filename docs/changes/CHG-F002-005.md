# CHG-F002-005 規約再確認の期限という概念を廃止する

## 変更理由

CHG-F002-004 で期限切れの効果を実行時からリリースゲートへ移した。
しかし**そのゲートを通す手段が構造上塞がっている**ことが判明した。

`terms.checkedAt` / `terms.validUntil` は `public/content/licenses.json` の中にあり、
このファイルは F001 v0.1.0 baseline に凍結されている。

```
content/baselines/F001-v0.1.0.json
  files[60] = { path: content/licenses.json, sha256: a2f4c52e…, bytes: 3060 }
```

baseline の SHA は `src/content/baseline.ts` に固定 commit と共に直書きされている。

```ts
const F001_COMMIT = '2733b5fd368e847a01708724511f993f5e1b2484';
const F001_EXPECTED_BASELINE_SHA = '722b88affbc84a3e1250bcc1e2e6d538957a02d94483b706bb55609483b9fbc9';
```

実測では日付を更新しただけでリリース検査が停止する。

```
$ node --experimental-transform-types scripts/verify-project.mjs
[build error] F001_ASSET_HASH_MISMATCH
```

**更新できないファイルの中に、更新が必須の項目が入っていた。**
2026-08-18 の期限到来後、規約を実際に再確認しても新規リリースができない状態だった。

## 変更内容

暦に基づく期限という概念そのものを廃止する。

| | 現状 | 改訂後 |
| --- | --- | --- |
| `checkedAt` の形式検査・確認日表示 | あり | あり（変更なし） |
| `validUntil` との前後関係検査 | 実行時 | **廃止** |
| 期限切れによるリリースブロック | `verifyLicenseTermsFreshness` | **廃止** |
| 規約変更の検知 | F005 predeploy | F005 predeploy（変更なし） |

`licenses.json` は一切変更しない。凍結された `validUntil` は参照しない旧項目として残る。
F001 baseline・固定定数・固定 commit もいずれも変更しない。

## 再確認義務がなくなるわけではない

REQ-F002-015 が求める再確認は、**暦ではなく規約本文の突き合わせ**で実現されている。
F005 predeploy（FUN-F005-006）は公開直前に規約本文を再取得し、
選定時 snapshot と SHA-256 を比較する。

```ts
const before = [...selection.policies.map((policy) => policy.artifact.sha256)];
const after = [...snapshot.policies.map((policy) => policy.artifact.sha256)];
if (JSON.stringify(before) !== JSON.stringify(after)) {
  throw new F005SourceError('F005_SOURCE_DRIFT', 'selection/predeployの原典または規約SHAが変化しました');
}
```

REQ-F002-015 の記述（「canonical URL、取得日時、版または snapshot SHA-256 を
選定時と deploy 直前に保存・比較する。変更時は……未判定なら公開を停止する」）は
この機構そのものを指しており、**要求文の変更は不要**である。

廃止するのは、この実質的な検査に対して重複していた暦の目安だけである。
規約が改定されていなければ日付が古くても公開してよく、
規約が改定されていれば日付が新しくても公開は止まる。後者が本来の統制である。

## 失う性質と、それを許容する根拠

「一定期間ごとに人が規約を読み直す」という運用上の促しがなくなる。

- 規約**改定**は predeploy の SHA 比較で必ず検知され、未判定なら公開が止まる。
  暦の期限が捉えていたのは改定の可能性であって改定そのものではない。
- 期限切れは実際には統制として機能していなかった。テスト fixture の
  `validUntil` が失効した際、CHG-F005-049/050/051 で 3 回続けて
  「既存期限 fixture の失敗」として脇に置かれている。
- 非営利・広告なし・非公式表示という本サイトの用途は現行ガイドラインの
  最も緩い区分に収まっており、構造的に安定している（`docs/evidence/rights/` 参照）。

## 影響範囲

- `src/notices/credits.ts` — `validUntil` の解析・比較を削除、有効期限の表示を削除
- `scripts/verify-project.mjs` — `verifyLicenseTermsFreshness` を削除
- `docs/design/DD-F002.md` — FUN-F002-025 の規約再確認
- `content/licenses.json` / `public/content/licenses.json` — **変更しない**
- `content/baselines/*` / `src/content/baseline.ts` — **変更しない**
- `docs/srs/SRS-F002.md` — REQ-F002-015 は predeploy の SHA 比較を指しており変更しない

## 承認

要求レベル変更のため承認ゲートを必須とする。
Q-049 でプロジェクトオーナーが「期限の概念そのものを廃止する」を選択し承認済み。
