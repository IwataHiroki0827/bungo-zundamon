# CHG-F002-005 規約再確認の記録を凍結ライセンス文書から分離する

## 変更理由

CHG-F002-004 で規約再確認期限の効果を実行時からリリースゲートへ移した。
しかし**そのゲートを通す手段が構造上塞がっている**ことが判明した。

`terms.checkedAt` / `terms.validUntil` は `content/licenses.json` と
`public/content/licenses.json` の中にある。後者は F001 v0.1.0 baseline に
凍結されている。

```
content/baselines/F001-v0.1.0.json
  files[60] = { path: content/licenses.json, sha256: a2f4c52e…, bytes: 3060 }
```

この baseline は `src/content/baseline.ts` の固定定数と結び付いている。

```ts
const F001_RELEASE = 'v0.1.0';
const F001_COMMIT = '2733b5fd368e847a01708724511f993f5e1b2484';
const F001_EXPECTED_BASELINE_SHA = '722b88affbc84a3e1250bcc1e2e6d538957a02d94483b706bb55609483b9fbc9';
```

実測すると、日付を更新しただけでリリース検査が停止する。

```
$ node --experimental-transform-types scripts/verify-project.mjs
[build error] F001_ASSET_HASH_MISMATCH
```

一方 REQ-F002-015 は次を要求している。

> canonical URL、取得日時、版または snapshot SHA-256 を**選定時と deploy 直前に
> 保存・比較する**

つまり `checkedAt` は deploy ごとに更新されることが前提である。
**更新できないファイルの中に、更新が必須の項目が入っている。**

結果として 2026-08-18 の期限到来後、規約を実際に再確認しても
`checkedAt` を書き換えられず、新規リリースが恒久的に不可能になる。

なお公開中のサイトへの影響はない。CHG-F002-004 で実行時判定を外したため、
期限切れは訪問者に影響せず新規公開だけを止める。

## 変更内容

凍結すべきものと更新されるべきものを分ける。

| | 現状 | 改訂後 |
|---|---|---|
| ライセンス本文・クレジット・canonical URL | `licenses.json`（F001凍結） | 変更なし（凍結のまま） |
| `terms.checkedAt` / `terms.validUntil` | 同一ファイル内 | 規約確認証跡ファイルへ分離 |
| F001 baseline / 固定定数 | — | 変更しない |

凍結の目的は「**何を根拠に公開したか**」の改竄検知である。
「**いつ再確認したか**」は更新されることが正しく、凍結対象に混在させたのが
設計の取り違えである。分離すれば F001 不変量を一切緩めずに再確認を回せる。

分離後、`renderCreditsV2`（FUN-F002-025）は確認証跡ファイルから
`checkedAt` を読み、クレジット画面に確認日を表示する。
形式・前後関係の検査は現状どおり実行時に行う。
期限切れの判定は `verifyLicenseTermsFreshness`（リリース前検査）が担う。

## 却下した代替案

**F001 baseline と固定定数を更新する。**
リリースのたびに初回リリースの改竄検知不変量を作り直すことになり、
baseline が「凍結された既知の正しい状態」を意味しなくなる。
`F001_COMMIT` との結び付きも失われる。改竄検知の価値を捨てる対価が
日付更新に見合わない。

## 影響範囲

- `content/licenses.json` — `terms` の移設（**公開バンドルの `public/` 側は不変**）
- 新設: 規約確認証跡ファイル（パスは実装時に確定）
- `src/notices/credits.ts` — 確認日の参照元
- `scripts/verify-project.mjs` — `verifyLicenseTermsFreshness` の参照元
- `docs/design/DD-F002.md` — FUN-F002-025
- `docs/srs/SRS-F002.md` — REQ-F002-015 の検証方法（記録の所在）

`public/content/licenses.json` を変更しないため、F001/F002 baseline、
`F001_EXPECTED_BASELINE_SHA`、固定 commit はいずれも変更しない。
