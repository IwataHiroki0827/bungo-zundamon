# CHG-F005-010 native helperの作業ディレクトリ隔離

## 変更理由

GitHub Actions run `30508494379`はCHG-F005-009によりnative executableをworkspace外へ配置した状態でも、`wav-validated`後かつwrite予約前にSystem `SetInfo`のunknown workspace pathを観測して安全停止した。この時点で容量guardのphaseは開始済みであり、新たに起動するwrite helperだけがworkspaceをcurrent working directoryとしていた。

## 変更内容

- 容量guard、write-through helper、directory flush、acceptance用native clientのcurrent working directoryを、workspaceではなく検証済みnative executableのparent directoryへ固定する。
- native `hello`はpathを返さず、current working directoryと実行file directoryが一致するかをboolean `workingDirectoryIsExecutableDirectory`で返す。
- build検証と全clientは同booleanが`true`であることを必須とし、誤ったcwdで起動したprocessをfail-closedにする。
- artifact build childはworkspaceを対象にする本来の観測対象であるため、従来どおりworkspace cwdを維持する。

## セキュリティ境界

cwd変更はnative tooling processだけに限定する。native operationへ渡すworkspace root、relative artifact path、capacity phase、ETW監視rootは変更しない。helloへabsolute pathを含めず、公開済み固定SHAとboolean以外のhost情報を追加しない。

CHG-F005-010反映後のnative pinはProgram SHA-256 `53ba8789095a98237f60c8aa3e74526bf6272ea0c1826719803963fe1527e6bd`、output binary SHA-256 `dad0f01ae8358312854670737ec94be1f6d3ba6e3a90d9437ffef27d07e1fa11`、75,016,028 bytesとする。

## 検証

- native buildのhelloでcwd一致booleanを検査する。
- 通常modeとwrite-through modeの実binary helloでcwd一致を検査する。
- 容量guard、write helper、directory flush、acceptance clientの全spawnがexecutable parentをcwdに使うことを検査する。
- 型検査、ESLint、対象回帰、native相関規則、再現build、独立セキュリティレビュー後にhosted正常系を再試験する。

2026-07-30に型検査、ESLint、対象5 test file 124件、native相関規則37件、再現build 2回、YAML・差分検査がPASSした。wrong-cwd実binaryはhello boolean `false`、正しいcwdでは`true`を返した。Program SHA-256、binary SHA-256、bytesは上記pinへ一致し、`public/`と`data/`の差分は0件である。独立セキュリティレビューはHigh 0、Medium 0、Low 0でPASSした。

## 承認

要求内容を変えないtooling隔離の補正であり要求承認ゲートは設けない。hosted正常系が完了するまで`in-review`を維持する。
