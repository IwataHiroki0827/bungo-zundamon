# CHG-F002-003: Windows transaction試験の重複要求を共通境界保証へ是正

| 項目 | 内容 |
|---|---|
| 発生日 | 2026-07-26 |
| 起票契機 | T-029独立受入で、IT-F002-009/QT-F002-014の記述が4 transactionすべてに同一のjunction・共有違反試験を重複要求していると判明 |
| レベル | testspec |
| 承認 | 既存REQ-F002-020とDES-F002-015の安全・回復要件を変更しないテスト責務分担の是正 |
| 状態 | done |

## 変更理由

旧IT/QT仕様は、FUN-F002-003/019/033/037の各transactionについて、journal回復に加えて実junction、rename共有違反、別process強制終了をすべて個別実施するよう読めた。一方、実装は各transaction固有のjournal回復と、共通path/atomic filesystem境界のfail-closedを別の試験群で保証している。各機能へ同じOS failure modeを重複注入することは、ユーザー要求・SRS・DDの安全条件ではなく、試験責務の過剰な重複だった。

## 変更内容

- 4 transactionは、それぞれのjournal主要状態から完全な旧版または検証済み新版へ収束することを必須とする。
- 実junction/reparse、rename前のhash/identity競合、`EBUSY/EPERM`は、共通path/atomic primitiveと代表transactionのWindows実試験で保証する。
- FUN-F002-019固有の100/250/500 ms retry、retry超過時の旧public維持・rollbackは従来どおり必須とする。
- manifest/public/accepted-audioの実rename経路では子process強制終了と別process再起動を維持する。published manifestは全journal phaseのfault hook回復で同じ永続化契約を検証する。
- 手動確認を追加せず、自動証跡だけで判定する。

## 非変更事項

- REQ-F002-020、DES-F002-015、FUN-F002-003/019/033/037の実装契約は変更しない。
- journal回復、atomic rename、post hash検証、reparse拒否、第三者競合非上書き、public retry/rollbackを緩和しない。
- F002のexact candidate・全自動試験・公開後smoke条件を変更しない。

- 独立再レビューでHigh/Medium 0件になること。

FUN-F002-019の`renameRetry`には試験専用のrename/delay adapterを追加し、実装経路へ`EBUSY`と`EPERM`を注入した。初回0 msから100/250/500 msの3回retry後に成功する境界と、新public renameが4回失敗した場合に検証済み旧publicをrollbackし、stagingを維持する境界を直接検証した。対象18件、typecheck、lintはPASSした。
