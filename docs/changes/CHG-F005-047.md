# CHG-F005-047 active lease欠落late directory write限定handoff

## 変更理由

CHG-F005-046のproduction run `31224657445`はProcessStart予約fenceを通過し、`wav-validated`後に`F005_ETW_WRITE_COMPLETION_DRAIN_LATE_DIAG_WRITE_ACTIVE_LEASE_MISSING`へ到達した。これはCompletedRetained sealのparent directoryに対するlate System writeが存在する一方、callback handler時には`pendingWriteLease`がないことを示す。

同じno-lease directory writeを通常authorization順へ到達させた場合、既存`TryAuthorizeKnownSystemDirectoryWriteLocked`はactive voice phase、System/BIRTH_MISSING、unbound FileObject、phase開始後、pending leaseなし、cache directory exact bucket、directory snapshot/current identity、同一phase root owner observation、root process activeの完全条件で限定認可する。completion-drainの先行throwだけがこの既存認可への到達を妨げるため、exact late 1候補だけを専用handoffする。

## 変更内容

### 1. exact 1候補だけのhandoff

`TryAuthorizeWriteCompletionDrainEventLocked`はepoch 0のlate候補が1件だけで、aggregate failureがexact `F005_ETW_WRITE_COMPLETION_DRAIN_LATE_DIAG_WRITE_ACTIVE_LEASE_MISSING`の場合に限り、`completedNoLeaseDirectoryHandoff`へ対象sealを返す。候補は既存broad/late/proof条件により、System PID 0/4、`BIRTH_MISSING`、write、nonzero FileObject、active voice phaseとseal phaseの同一参照、seal current/parent path、completion upperより後、ledger上unbound parent FileObjectを満たす。加えてseal `CompletedRetained`、normalized pathがseal parent、`pendingWriteLease == null`を再確認する。

setinfo、CURRENT_PATH、複数late candidate、MIXED、別seal state、active lease有り、別phase/path、bound FileObjectはhandoffしない。completed-write handoff、post-request marker、active-directory handoff、normal sealed replayとは排他的に1件だけ返す。分類中に認可・proof・ledger・seal/lease/capacity/notice/Observationを変更しない。

### 2. 既存root directory認可への限定接続

`ObserveEtw`は専用handoff時、他completion contextがすべてnull/normalであることを確認してから`TryAuthorizeKnownSystemDirectoryWriteLocked`を1回だけ呼ぶ。PASS時は既存root PID/sequenceとdirectory expected identityを使用する。falseかつpoison済みなら停止し、falseかつ非poisonでも`F005_ETW_WRITE_COMPLETION_DRAIN_STATE_CHANGED`で停止する。他のreserved/completed/bound/after/known authorizationへfall-throughしない。

PASS時にconstructor-only `CompletedNoLeaseDirectoryRejoinContext`を作り、seal sequence/reference、phase reference/instance/started QPC、directory path/identity、event FileObject/QPC、root PID/start key/sequenceをscalarで保持する。callback snapshotは旧sealのsealed replayへ入れず、`SealSequence = null`、normal replay、既存OtherBound proofとする。旧sealのEventCount、replay queue、producer tupleは使用しない。

### 3. atomic適用前の再検査

handoff PASS直後かつ`AdmitCallbackProofLocked`より前に、proof非依存のphase/no lease/seal/root/directory/retained parentを同じgateで再検査する。これを通過した場合だけOtherBound proof admissionとgeneration handle保持へ進む。

`PreflightImmutableRejoinLocked`と`ApplyCallbackSnapshotCoreLocked`はafter-lease、bound-lease、completed-no-lease contextを最大1件に限定する。completed-no-lease contextではcapacity/semantic適用前に次を再検査する。

- active phase reference、phase instance、started QPCが不変でvoiceである。
- `pendingWriteLease`が引き続きnullである。
- seal sequenceが一意で同じseal reference、`CompletedRetained`、同じphase、parent path、directory identity、completion upperを保持し、event QPCがupperより後である。
- root PID/start key/sequenceがsession scalarと一致し、保持root processがnon-signaledかつJob memberである。
- `SystemDirectoryWriteRejoinStage`が引き続き`CANDIDATE`で、directory snapshot/current identityと同一phase root owner observationが不変である。
- proofがOtherBound、同一event FileObject/path/identity、Bound stateであり、seal retained parentとgeneration handleの双方がdirectory identityへ再inspectionできる。

tuple/state差は`F005_ETW_WRITE_COMPLETION_DRAIN_STATE_CHANGED`、proof/identity差は既存`...BINDING_MISMATCH`または`...EVENT_IDENTITY_FAILED`、root/directory既存認可差は既存known-directory failureで停止する。失敗時はsemantic map、capacity、notice、Observation、seal/lease stateを未変更または既存checkpointへatomic rollbackし、別認可へ進まない。

現行ledgerのproof admission、generation handle保持、reorder queue追加はsemantic checkpointより前に行われる。queued replay時のcontext driftでpreflightが失敗した場合、これら内部証拠は巻き戻さず、既存上限内で保持したままsessionをpoisonする。poison後は再適用せず、session Disposeがqueue、ledger、generation handleを解放する。内部証拠の保持を認可成功やsemantic適用として扱わず、rollback対象をfiles/allocated/deferred/observations/notices/leases/peak/freeの既存semantic checkpointへ限定する。

### 4. 外部契約

新しい外部failure codeは追加しない。completion-drain 43 code、予約fence raw/F005 4 code、IPC keys、127文字上限、unknown正規化を維持する。raw path、QPC、FileObject、identity、PID、handleをreply/journal/annotationへ追加しない。candidate保存、candidate branch、Pages、`public/`、`data/`条件も変更しない。

## 影響範囲

`tm.json`の`DES-F005-006`/`DES-F005-012`から機械抽出した候補のうち、本変更を直接担う`REQ-F005-012`、`REQ-F005-013`、`FUN-F005-017`、`FUN-F005-047`、`UT-F005-017`、`UT-F005-047`、`IT-F005-005`、`QT-F005-008`、`QT-F005-009`と、`T-070`、`T-120`、`T-121`を影響対象とする。

## 試験方針

- production共有純粋規則でexact write ACTIVE_LEASE_MISSING 1件だけを候補とし、setinfo、candidate数0/2、全別bucket、seal state、parent、phase、active lease、FileObject bindingの各単独falseを固定する。
- handoff時の既存known-directory認可呼出しを1回以下にし、PASS、poison false、非poison false、他completion context混在、他認可非fall-throughを構造・実行fixtureで確認する。
- context constructor-only scalarとSealSequence null、OtherBound proof、旧seal replay/EventCount 0を固定する。
- preflight/applyのphase、lease null、seal、QPC、root PID/start key/sequence/non-signaled/Job、directory candidate、proof、retained parent/generation handleを各単独falseで確認する。
- reorder queue後に新lease生成、root終了、seal release、directory identity差替えを発生させ、capacity適用前に停止してsemantic/capacity/notice/Observationを未変更に保つ。admitted proof/queue/generation handleはbounded内部証拠としてpoison中だけ保持し、再適用せずDisposeで解放する。
- 既存known-directory直接認可、completed/active/post-request handoff、completion-drain 43 code、予約fence4 codeを非変更とする。
- native規則、関連Vitest、typecheck、ESLint、trace_check、再現build 2回、独立受入、同一source SHAのhosted productionを実施する。

## 承認

既存known-directory完全認可への到達順だけを変更し、認可条件・要求・容量判定は変更しないdesign変更である。要求承認ゲートは設けず、独立設計レビュー、実装、影響試験、hosted再観測まで`in-review`を維持する。

## 独立設計レビュー

初回レビューはHigh 0 / Medium 1 / Low 0であった。Mediumは、proof admission、generation handle、reorder queueがsemantic checkpointより前に作成される現行transactionに対し、内部ledgerまで全rollbackする初期記述が実装不可能という指摘である。proof非依存contextをadmit前に再検査し、queued drift後はsemantic stateのみ未変更、bounded内部証拠はpoison中保持して再適用せずDisposeで解放する既存fail-closed契約へ修正した。

修正後の独立再レビューはHigh 0 / Medium 0 / Low 0でPASSした。admit前再検査、semantic checkpoint境界、proof/queue/handleの既存上限、poison後再適用不能、Dispose解放が現行実装と整合し、UT/QTまで検証可能であることを確認した。
