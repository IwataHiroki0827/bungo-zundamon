# CHG-F005-075 final Catalogの受理時刻を作品単位の証跡で裏付ける

## 変更理由

最終Catalog統合（T-073）で `projectF005CatalogFragment(..., 'final')` が停止した。

```
F005CatalogError: final accepted時刻とmanifest stage recordが一致しません
```

`assertManifest` は batch単位の末尾 stage record が `accepted` であり、その
`completedAt` が `manifest.acceptedAt` と一致することを要求していた。

しかしF005は**作品単位でatomicに受理する**設計であり、
`finalizeF005WorkAcceptance`（FUN-F005-022）と `recoverF005WorkAcceptance`
（FUN-F005-023）は `workProgress[].stageRecords` だけを進める。
batch単位の stage record は一度も書かれない。実際の受理済みmanifestは次の状態である。

```
status         = accepted
acceptedAt     = 2026-08-14T12:20:21.434Z
acceptedBy     = f005-production-runner
stageRecords   = []                      ← batch単位は空
workProgress[].stageRecords[-1] = accepted / 2026-08-14T12:20:21.434Z
```

`validateBatchManifest` も `sources-fixed` までしか末尾 stage record を要求しないため、
この状態はmanifestとして正当である。batch単位の stage recordを要求していた
`assertManifest` の側が、F004のbatch一括受理を前提にしたまま残っていた。

## 変更内容

受理時刻の裏付けを、F005が実際に生成する証跡へ合わせる。

| | 現状 | 改訂後 |
| --- | --- | --- |
| 検証対象 | batch単位の末尾 stage record | 各作品の末尾 stage record |
| 要求 | `stage === 'accepted'` かつ `completedAt === acceptedAt` | **全作品**が `accepted` で、**最後に受理された作品**の `completedAt` が `acceptedAt` と一致 |

```ts
const acceptedCompletions = manifest.workProgress.map((work) => {
  const record = work.stageRecords.at(-1);
  return record?.stage === 'accepted' ? record.completedAt : null;
});
```

3作品すべての受理記録を見るため、検査対象は1件から3件へ増える。
batch単位の record は存在しないものを見ていたのに対し、こちらは実在する証跡である。

## 影響範囲

- `src/content/f005-catalog.ts` — `assertManifest` の final分岐
- `src/content/f005-catalog.test.ts` — UT-F005-025 の時刻矛盾ケースを作品単位の偽装へ変更
- 受理済み成果物 — 変更しない
