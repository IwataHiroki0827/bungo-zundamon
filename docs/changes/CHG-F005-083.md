# CHG-F005-083 未着手リリースパイプライン10件を汎用リリース経路採用へ設計不採用化

## 経緯

CHG-F005-082（T-074）で、DD-F005.mdに設計は存在するが`src/content/`配下に実装が
一切存在しない未着手サブシステムとして、以下10個のFUN-F005-IDが確定していた。

- **release/deployパイプライン一式**（FUN-F005-035〜039、DES-F005-012）:
  `prepareF005Release`（release準備）・`verifyF005ReleaseCandidate`
  （候補検証、clean build＋ETW容量観測）・`recordPublishedF005`（公開確定）・
  `rollbackF005Deployment`（ロールバック）・`recoverPendingDeployDisablement`
  （デプロイ無効化復旧）。
- **CAS付き1段階状態遷移**（FUN-F005-042、DES-F005-002/006）:
  `transitionF005WorkState`。既存の汎用`transitionWorkState`
  （in-memory manifest操作）とは別に、workspace・exclusive lock・journal・CAS
  を伴うF005専用ラッパーとして設計されていた。
- **第三者裁定authorization発行・解決**（FUN-F005-044/046、DES-F005-005）:
  `mintF005AdjudicationAuthorization`/`resolveF005Adjudication`。既存の
  `issueF005ReviewAuthorizations`/`sealF005ReviewJudgment`/
  `reconcileF005PrimarySecondary`とは別に、一回限りtoken発行・二重mint拒否・
  dispute結合を伴う新規CAS store型として設計されていた。

これらはいずれもDD-F005.md 7章「security・release」に記載されたF005専用の
ETW検証付きリリースパイプライン（native guard、Job Object収容、System IO
Provider/Kernel-Process ETW、write-through helper等の大規模native機構）に
連なるサブシステムであり、既存の単純な同型実装パターンを踏襲できる
1関数（CHG-F005-081で解消したFUN-F005-014のようなケース）には該当しない、
規模の異なる10個の未着手実装だった。

## 決定

オーナーと協議し、以下の方針で合意した。

- REQ-F005側にETW検証付きリリースパイプラインを明示的に要求する記述はなく、
  要求仕様自体の変更は不要（`level: design`）。
- F005専用ETW検証付きリリースパイプラインは新規実装しない。
- F001〜F004、および先日のv0.4.1パッチ（PR #3）で実績のある汎用リリース経路
  （`scripts/verify-project.mjs`によるbuild verification・静的security審査、
  GitHub Actions `PAGES_DEPLOY_ENABLED`/`PAGES_DEPLOY_COMMIT`変数による
  デプロイゲート）をF005にも適用する。
- FUN-F005-042（状態遷移）は、F001〜F004で実績のある既存の汎用
  `transitionWorkState`（`src/content/batch.ts`）で代替する。
- FUN-F005-044/046（第三者裁定）は、既存の`issueF005ReviewAuthorizations`/
  `sealF005ReviewJudgment`/`reconcileF005PrimarySecondary`
  （`src/content/f005-review.ts`、primary/secondary review reconciliation）
  による解決で完結させる。
