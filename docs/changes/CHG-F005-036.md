# CHG-F005-036 bound lease directory CANDIDATEの完全tuple限定再結合

## 変更理由

commit `ded3117211cb0ad9debf5a45ec564a8f7575d0f4`のActions run `31038467173`を3 attempt実行したが、attempt 1は既知`LEASE_BINDING_MISMATCH`、attempt 2は既知`LEASE_MISSING`、attempt 3は`F005_ETW_PID_NOT_JOB_MEMBER_SYSTEM_DIRECTORY_BOUND_LEASE_WRITE_REJOIN_CANDIDATE`へ安全停止し、T-109のhosted対象経路へ到達しなかった。attempt 3は既知cache directory、同一phase root owner、root active、active leaseのphase・親path・open・FileObject/snapshot/binding/current identity・Job状態がすべて一致する既存固定候補である。

## 予定変更

これまで拒否していたSystem directory writeのうち、既存`SYSTEM_DIRECTORY_BOUND_LEASE_WRITE_REJOIN_CANDIDATE`完全tupleだけを次の条件で再評価する限定認可拡張とする。

- authorization failureが`BIRTH_MISSING`、PIDがSystem、eventが`write`、event FileObjectが非zeroかつ未結合である。
- active phaseが`voice`でlease phase instanceが一致し、`activePhase.StartedAtQpc < lease.CurrentPathReservedAtQpc < event QPC`である。phase開始QPC同値、lease予約QPC同値、phase開始以前のlease予約は拒否し、それぞれ+1 tickだけを次段候補にする。
- 観測pathはcache内の既知directoryで、directory snapshot/current identity、同一phase root owner、root activeが一致する。
- active leaseは同一phase、観測directory直下、open、FileObject・snapshot・bindingが存在し、binding path/identityとlease current identityがsnapshotに一致する。
- `PendingRenamePath`と`RenameReservedAtQpc`は初回評価時にともに`null`で、current pathが安定している。
- 保持process handleのinspectionでPID/start key/sequenceがlease保存値と完全一致し、processは非signaledかつJob memberである。identity→wait→Jobの各失敗、signaled、Job外は固定codeで拒否する。
- 認可直後から`ObservationRecord`投入直前まで同一lock内で、次の順序を変えず再照合する。(1) active phaseとactive leaseの同一参照・phase instance・voice・phase/lease予約QPC、(2) event FileObject未結合、(3) `PendingRenamePath`と`RenameReservedAtQpc`がともに`null`、(4) directory snapshot/current identity、(5) lease current identity、(6) lease FileObject binding path/identity、(7) 保持process handleのPID/start key/sequence→wait→非signaled→Job member。filesystem/process取得失敗または値の変化は固定codeで停止する。process再inspectionは容量値計算後かつ`ObservationRecord` constructor呼出しの直前に行い、初回と同じ完全tuple、非signaled、Job memberを再度必須とする。
- producer PID/sequenceはlease保存値だけを返す。

一条件でも不一致なら既存固定診断へ流す。再結合後も容量actualは既存ETW observationから再計算し、lease binding、候補保存・公開条件を変更しない。raw path、QPC、identity、FileObject値は公開しない。

## 試験方針

- native規則試験はall-true baselineを1件置き、`authorizationFailure`、System PID、event、FileObject非zero、FileObject未結合、voice phase、phase instance、phase/lease/event QPC、exact candidate、`PendingRenamePath == null`、`RenameReservedAtQpc == null`、directory/lease tuple、process PID/start key/sequence、non-signaled、Job memberを1項目ずつfalseにする。各falseでは後段inspectionが評価されず、従来診断へfail-closedとなることを固定する。
- QPCはphase開始同値/+1、lease予約がphase開始同値/+1、eventがlease予約同値/+1を個別固定し、`phase start < lease reservation < event`以外を拒否する。pending rename path/reservationは初回と再照合で片方ずつ非nullにして拒否する。
- process identity/wait/Job、signaled/escape、lease保存producer tupleを初回と直前再inspectionで個別に固定する。
- 認可後のactive lease/phase、event FileObject、pending rename 2値、directory、lease current、binding、process再inspectionの各再照合失敗を前記exact 12 codeで停止させる。
- 構造試験で既存exact `CANDIDATE`だけが新helperへ入り、旧/未知codeや他stageを認可せず、lease binding・容量actual・candidate/public条件を変更しないことを確認する。
- TypeScript/runnerで前記exact 19 codeだけを伝播し、未知suffix・追加文字・128文字以上をgeneric化して生値非公開となることを確認する。
- DD-F005、UT-F005、IT-F005、QT-F005、本CHG、Program/binary/bytes pinとbuild evidenceを同期し、同一SHA再現buildを2回行う。
- commit固定hosted試験で限定再結合後の固定stageを取得し、candidate branch未作成、Pages deploy skip、`public/`・`data/`差分0を確認する。
