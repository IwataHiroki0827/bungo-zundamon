# CHG-F005-056 active-directory複数適格候補の全適格・混在固定診断

## 変更理由

T-109/T-110/T-112/T-122の決定的hosted相関を完了した最新guardでT-070 production candidateを再開した。run `31244948483`はbuild、kernel ETW、VOICEVOX取得、production pipeline、固定診断公開までPASSした後、`F005_ETW_WRITE_COMPLETION_DRAIN_ACTIVE_DIRECTORY_HANDOFF_ELIGIBLE_AMBIGUOUS`で候補保存前に安全停止した。candidate branchは不存在で、同一SHAのPages run `31244948486`はdeploy `skipped`である。

CHG-F005-051は既存active-directory handoff predicateを満たすlate candidateが複数あることだけを固定した。候補順、最新seal、最大QPCを根拠なく選ぶことは認可拡大になるため行わない。一方、複数適格候補がlate candidate集合の全件なのか、適格候補と不適格候補が混在するのかは、既存snapshotと共有predicateから生値を公開せず決定できる。認可を変更せず、この一軸だけを固定診断する。

## 変更内容

### 1. 全適格・混在のproduction共有分類

production共有純粋規則`ActiveDirectoryHandoffEligibleMultiplicityFailureCode`を追加する。入力は`totalCandidateCount`、`eligibleCandidateCount`、既存aggregate failure codeだけとし、次の順で排他的に分類する。

1. count負値、eligibleがtotal超過は既存`STATE_CHANGED`。
2. 対象aggregate以外、total 2未満、eligible 2未満は`null`とし、既存上流判定へ委譲する。
3. 対象aggregate、total 2以上、eligible 2以上、eligibleとtotalが等しい場合は`...ACTIVE_DIRECTORY_HANDOFF_ELIGIBLE_ALL`。
4. 同条件でeligibleがtotal未満の場合は`...ACTIVE_DIRECTORY_HANDOFF_ELIGIBLE_MIXED`。

既存`ActiveDirectoryHandoffEligibilityFailureCode`のcount検証、0件`STATE_CHANGED`、1件`EXACT_ONE`は維持する。2件以上では新規規則を呼び、旧`ELIGIBLE_AMBIGUOUS`は外部互換allowlistへ残すが新sourceからemitしない。全結果は診断後ただちにthrowし、候補選択、active-directory handoff、proof admission、replay、capacity applyへ進めない。

### 2. 線形化と非変更境界

既存の`lateCandidates` array snapshot、aggregate、event-global scalar snapshot、候補別`ActiveDirectoryHandoffCandidateMatches`、checked eligible countを同じ`gate` acquisition内で一度だけ使用する。新規規則のためにsealを再列挙せず、候補のpath、QPC、PID、FileObject、identity、sequence、handle、index、predicate bitsetを保存・出力しない。

`ALL`は全candidateが既存predicateを満たす事実だけを表し、候補間の同一性、event ownership、handoff可否を証明しない。`MIXED`も不適格理由や件数を表さない。両codeからstate更新や別認可へfall-throughしない。認可変更は実hosted結果と別変更管理・独立レビューなしに行わない。

### 3. 外部契約とhosted判定

completion-drain固定code集合へ`ELIGIBLE_ALL`と`ELIGIBLE_MIXED`を追加し、native reply、journal、TypeScript bridge、runner、production workflow regexをexact同期する。各codeは127文字以下とし、unknown、extra suffix、exact 128文字は既存genericへ正規化する。IPC key、容量actual、candidate保存、branch、Pages、`public/`、`data/`条件は変更しない。

同一source commitのhosted productionで旧`ELIGIBLE_AMBIGUOUS`ではなく新2 codeのどちらかへ一意に到達し、candidate branch不存在、Pages deploy `skipped`、公開tree差分0を確認した時点でT-130の影響確認をPASSとする。結果は将来の認可変更を自動承認しない。

## 影響範囲

`REQ-F005-012`、`REQ-F005-013`、`DES-F005-006`、`DES-F005-012`、`FUN-F005-017`、`FUN-F005-047`、`UT-F005-017`、`UT-F005-047`、`IT-F005-005`、`QT-F005-008`、`QT-F005-009`、`T-070`、`T-125`を対象とする。実装・再試験タスクとして`T-130`を追加する。

## 試験方針

- total/eligibleの負値、eligible>total、total 0/1/2/3、eligible 0/1/2/3、対象/別aggregateを全境界で検査する。
- total=eligible>=2を`ALL`、2<=eligible<totalを`MIXED`、上流対象を`null`または既存codeへ排他的に固定する。
- late candidate集合の順序反転、全適格、適格2＋不適格1、適格1＋不適格複数を一気通貫fixtureで検査し、候補順非依存と旧`AMBIGUOUS`非emitを確認する。
- snapshotからterminal throwまで同一gate、再列挙・wait・再lockなし、全semantic fingerprint不変、後段非fall-throughを構造試験で固定する。
- fixed code exact集合、127文字上限、raw値非公開、production workflowのfail-closed allowlistをnative/Vitestで同期する。
- native通常suite、T-109/T-110/T-122/T-112 target、関連Vitest、typecheck、ESLint、trace_check、同一SHA再現build2回、独立受入後にhosted productionを実施する。

## 承認

既承認の認可、proof、lease binding、capacity actual、semantic state、候補保存、公開条件を変更しないdesign-level固定診断である。要求承認ゲートは設けず、独立設計レビュー、T-130実装、local/hosted影響試験完了まで`in-review`を維持する。

## 独立設計レビュー

整合性・実現性・セキュリティをproduction実物と照合し、High 0 / Medium 0 / Low 0でPASSした。既存CHG-F005-051のpredicate、invalid/upstream境界、`EXACT_ONE`を維持し、複数適格時だけ`ALL`/`MIXED`へterminal分類する設計、旧`AMBIGUOUS`互換、同一gate、非fall-through、非公開、関連文書・試験範囲に残指摘はない。
