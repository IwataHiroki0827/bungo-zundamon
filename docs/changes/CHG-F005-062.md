# CHG-F005-062 epoch empty/no late proofの時間・binding固定診断

## 変更理由

T-135 hosted attempt 3はbroad seal存在、epoch 0、late proof候補0の`EVENT_TUPLE_LOOKUP_EPOCH_EMPTY_NO_LATE_PROOF`で停止した。この状態では各broad sealはeventが予約同値以前、またはcompletion upper後だが`ProofCandidate`不成立のいずれかである。既存snapshotから生値を出さず構成だけを固定する。

## 変更内容

既存のlateCandidates生成をproduction共有の単一loopへ置き換え、同一gateの`broad` arrayをこの分類用に一度だけ走査する。`eventQpc <= seal.CurrentPathReservedAtQpc`はat-or-beforeをcountし、ProofCandidateを評価しない。upper存在かつeventがupperより後の場合だけ`ProofCandidate`をsealごとexact 1回評価し、trueは既存lateCandidatesへ追加、falseはpost-upper-proof-missingをcountする。epoch 0かつ生成後lateCandidates 0の場合だけ固定診断へ進む。

- broad全件がat-or-beforeなら`...EVENT_TUPLE_LOOKUP_EPOCH_EMPTY_AT_OR_BEFORE_RESERVATION_ALL`。
- broad全件がpost-upper-proof-missingなら`...EVENT_TUPLE_LOOKUP_EPOCH_EMPTY_POST_UPPER_PROOF_MISSING_ALL`。
- 両者が混在するなら`...EVENT_TUPLE_LOOKUP_EPOCH_EMPTY_TIME_PROOF_MIXED`。

`reservation > upper`、count負値、合計不一致、両分類外はSTATE_CHANGEDへ閉じる。temporal invalidが1件でもあればepoch/late件数にかかわらず分類直後・全後段分岐前にterminal停止する。upperなしでreservation後は既存epoch、`reservation < event <= upper`も既存epochへ進む。proof trueが1件でもあれば既存late aggregateへ進み、新診断へ入らない。旧`EPOCH_EMPTY_NO_LATE_PROOF`は互換allowlistへ残すがvalid production classifierからemitしない。path、QPC、FileObject、identity、candidate数・比率は公開しない。分類loop外でProofCandidate/ledgerを再評価せず、path table再参照、wait、再lock、認可、state更新を追加しない。

新3 codeをcompletion-drain集合へ追加し61から64へ同期する。runner/workflowはexact codeだけを伝播し、候補保存・branch・Pages・`public/`・`data/`条件を変更しない。

## 試験方針

- broad 1/2/128、at-or-before/post-upper-proof-missing各0/1/全件、混在、invalid countを固定する。
- reservation/upperの-1/同値/+1、reservation>upper、upperなしreservation後、current/parent proof false、proof true、ledger nullをproduction共有fixtureで構成する。invalid単独に加えvalid epoch/valid lateとの混在でも後段前STATE_CHANGEDを固定する。
- at-or-beforeではProofCandidate 0回、post-upperではsealごとexact 1回、proof trueは既存late経路へ進むことをcall-countと候補順反転で固定する。
- 同一broad snapshot一走査、後段aggregate/handoff非fall-through、semantic fingerprint不変、64 code・127文字・非公開を検査する。
- 通常native、固定target、関連Vitest、typecheck、ESLint、trace_check、再現build2回、独立受け入れ、hosted productionを実施する。

## 承認

既存snapshotの時間/binding原因を認可せず固定するdesign-level変更で、要求承認ゲートは設けない。独立設計レビューとlocal/hosted影響試験完了まで`in-review`を維持する。

## 独立設計レビュー

初回確認でlateCandidates生成後のproof再評価とbroad二走査の曖昧さを指摘された。生成と原因countを単一loopへ統合し、at-or-before proof 0回、post-upper exact 1回、proof true既存経路、temporal矛盾STATE_CHANGEDを明記した。最終レビューはHigh 0 / Medium 0 / Low 0でPASSし、partition、call-count、到達性、非公開、認可非変更に残指摘はない。
