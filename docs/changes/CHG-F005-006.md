# CHG-F005-006 delete-on-close System SetInfoの後方相関

## 変更理由

GitHub Actions run `30503156339`はCHG-F005-005の終了済みJob child認可を通過した後、最初のWAV temporary書込みで`F005_ETW_PID_NOT_JOB_MEMBER_SYSTEM_PROCESS_UNBOUND_FILE_OBJECT_SETINFO_UNKNOWN_PATH`へ安全停止した。`FILE_FLAG_DELETE_ON_CLOSE`のkernel metadata更新が、同じJob childのCreate/Write callbackより先に配送される順序逆転が原因である。

## 変更内容

- helper書込み前に、root pipe clientがexact temporary path、active voice phase、実Job child PIDを容量guardへ予約する。
- guardはJob内childのprocess handle、ProcessStartKey、boot一意ProcessSequenceNumberを予約中保持する。
- System PID 0/4の`SetInfo`だけを即時算入せず、到着時のfile identity・容量・空き容量・ETW連番を封印して保留し、後着する認証済みJob childのCreateが同じpath、非zero FileObject、process世代、file identity、QPC順序を満たす場合だけ結合する。
- 結合後のSystem `SetInfo`は予約したETW連番順に`ObservationRecord`へ再投入して容量を再計算する。CleanupでFileObjectを失効し、同pointerの再結合を拒否する。System write/create/rename/deleteは従来どおり拒否する。
- helper正常終了、ETW二段drain、same identity再照合後だけ予約を閉じる。未解決保留、tuple差、helper生存中completeはclose不能とする。

## セキュリティ境界

path一致や時間窓だけではSystem eventをJob childへ代理帰属させない。予約済みprocess handleのJob所属・ProcessSequenceNumber、先着時に封印したfile identity、同一FileObject、Create→SetInfoのQPC順序をすべて要求する。Cleanup、replacement、pointer再利用、未再投入をnative規則試験で検出し、いずれかが欠ける場合は固定codeでPoisonして候補branchと公開treeを変更しない。
