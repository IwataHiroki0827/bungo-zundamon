# CHG-F005-004 hosted Windows候補生成workflow

## 変更理由

ローカルMedium integrity processはkernel ETWを開始できず、T-070 production runnerは音声生成前に安全停止していた。CHG-F005-003のActions run `30445446783`で、固定native binary、容量ABI v3、kernel FileIO ETWの正常系をGitHub hosted Windows上で確認できた。

手動UACや監視なしfallbackを使用せず、同じ安全境界のまま「夢十夜」62音声と作品単位atomic受入を実行するため、通常Pages buildとは分離した一回限りの候補生成workflowを追加する。

## 変更内容

- `feature/F005`でworkflow自身が追加・変更されたpushだけを起動条件とする。`workflow_dispatch`、schedule、main、tagからは起動しない。
- checkout、Node、npm lock、native guard、VOICEVOX ENGINE `0.25.2` Windows CPU asset URL・SHA-256を固定する。canonical JSON、承認Markdown、ProjectFactory YAML、native guardのsource・project・build scriptはGit属性でLF checkoutへ固定し、raw bytes検証をOS設定から分離する。
- native build evidenceは追跡済みbytesを保持し、生成結果との意味的完全一致を検証した場合だけ元のexact bytesへ戻す。実値差を表現差として隠さない。
- 作業ドライブは開始時10 GiB以上、ENGINE展開後5 GiB以上を要求する。1,802,304,190 bytesの圧縮物はSHA検証後に展開し、直ちに削除してActions cacheへ保存しない。
- ENGINEはhidden processとして`127.0.0.1:50021`だけで起動し、runnerが版・speaker UUID/name・style ID/nameを実APIへ照合する。
- production runnerは`000799`だけを処理し、native exact 5 phase、closed journal、actual容量、metadata finalizeまで完了させる。
- `public/`差分0、manifest `000799=accepted`、accepted audio 62 WAV、変更path allowlistを自動検証する。
- checkout credentialは永続化せず、供給物・ENGINE・runner実行中にwrite tokenを環境やGit設定へ渡さない。ENGINE停止後の最終検証・保存stepだけへwrite tokenを渡す。
- runner結果はbuild logと混在しない`F005_RESULT_JSON=` marker付き1行JSONとしてexact 1件を要求する。
- native build直後かつVOICEVOX取得前に、HEAD・symbolic branch・ignored外の作業ツリーを再検証する。各Git commandは`Start-Process`の終了値を明示検査し、stdoutなしのGit異常も拒否する。状態不一致時は変更pathだけをBase64化して記録し、大容量取得前に停止する。
- runnerは`Start-Process -Wait -PassThru`の`ExitCode`でnative非0終了を捕捉する。失敗時はwrite tokenのないstepでstdout/stderr末尾64 KiBまでをBase64化してログへ出し、workflow command注入を避けながら使い捨てrunnerの診断情報を残す。
- 成功時だけsource commit固有の`candidate/f005-t070-{40桁SHA}`へcommitする。既存候補branch、部分生成、失敗、allowlist外差分ではpushしない。
- Pages deploy、main、tag、既存branch、公開変数を変更しない。

## リスクと対策

- 大容量取得: disk guardと圧縮物即時削除、cache非保存でrunner全体停止を防ぐ。
- supply chain: 公式release固定URLとGitHub asset digestを照合し、差分を展開しない。
- 権限: checkoutは`persist-credentials: false`とし、jobのwrite tokenはENGINE停止後の最終保存stepだけでHTTP extraheaderへ一時注入する。Pages/id-token/secrets権限を与えない。
- 部分生成: workflow failure時はcommit/push stepへ到達させず、使い捨てrunnerとともに破棄する。
- 公開誤反映: `public/`差分0を要求し、候補branch名をsource SHAへ固定する。通常Pages deploy条件はmainの承認SHAだけなので候補branchを公開しない。

## 承認
