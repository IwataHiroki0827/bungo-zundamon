# ドメイン調査 F003（太宰治コンテンツ追加）

## 1. Tier判定

調査Tierは**大**とする。外部公開サイトへ文学作品本文を変換した合成音声を追加するため、著作権、青空文庫の利用条件、VOICEVOX・ずんだもん規約、公開物とGit repositoryの容量、文学表現の編集判断が同時に関係する。F002の調査を再利用しつつ、公式作家一覧・拡充CSV・図書カード・XHTMLを再確認し、ローカル容量実測と独立評価を行った。

## 2. 結論

F003は太宰治（人物ID `000035`）の代表3作品を追加する。

| 順序 | 作品 | 作品ID | 予備`「」`候補 | 主な注意 |
|---:|---|---:|---:|---|
| 1 | 女生徒 | `000275` | 47 | 一人称内面が中心。実発話・内心・引用を区別 |
| 2 | 走れメロス | `001567` | 62 | 最大約230字。会話境界は比較的明確 |
| 3 | グッド・バイ | `000258` | 173 | 未完表示と公式内容注意を保持 |

公式XHTMLの予備合計は282候補、読み上げ候補文字量は約9,084字、単一候補の最大は約256字である。正式件数は原典byte列、charset、本文selector、SHA-256を固定した既存抽出器の出力で確定する。

## 4. 権利・書誌

- 太宰治の公式作家ページには`＊著作権存続＊`表示がなく、推奨3作品は新字新仮名で公開中である。
- 公式拡充CSVで、人物ID `000035`、人物・作品著作権フラグ`なし`、役割`著者`、翻訳者なしを選定時と公開直前に再確認する。
- 青空文庫の著作権切れ作品は、有償・無償を問わず複製・再配布・共有・実演・口述・翻案・形式変換に利用できる。個別許諾や対価は不要である。
- 作品名、著者、底本、入力者、校正者、取得日、原典hash、加工履歴を保持する。書誌データのCC BY 4.0と本文作品の権利状態を混同しない。
- `女生徒`と`グッド・バイ`など図書カードに現代では不適切と受け取られ得る表現の注意がある作品は、注意を由来情報へ保持する。題材だけを理由に実発話を機械除外しない。
- `グッド・バイ`の公式XHTMLは本文末尾に`（未完）`と明記している。作品一覧・作品画面・クレジットでも未完であることを常時確認できるようにする。

## 5. 編集・音声

- 対象は本文領域の外側全角`「...」`。`『...』`単独、本文外の書誌、見出し、引用、手紙、作品内の表示物は自動公開しない。
- 全候補について、一次判定と独立再判定がそれぞれ`decision`、`reasonCode`、発話主体、文脈anchor、入力hash、判定器versionを記録する。判定内容が一致した候補だけを確定し、不一致は第三の裁定artifactが確定するまで`pending`として音声生成を止め、最終的に`pending: 0`にする。
- 表示文とVOICEVOX用読み上げ文を分離し、外国語名、旧語、読み、長音、句読点の補正履歴を保持する。
- 候補ごとに括弧対応、発話主体、引用混入を検査する。正規化後の読み上げ文が500 Unicode code point以下、校正済みprofileによる推定durationが120,000 ms以下、24 kHz・mono・16 bit PCMのWAV予測が`44 + ceil(durationMs × 48)`かつ5,760,044 bytes以下であることを全て満たさない候補は、現行設計で安全に扱えないものとして音声生成前に停止する。
- `女生徒`は候補47件・約801字で、非括弧の一人称叙述を収録しない。作品全文の朗読・要約ではなく、括弧発話の抜粋体験であることを明示する。
- `VOICEVOX:ずんだもん`の固定tupleと音声IDを使い、承認済みの差分だけを生成する。

## 6. 容量

- F002公開時点は2作者・6作品・213台詞、public実体約81.6 MB、音声約75.7 MBである。
- 候補282件でも総文字量は約9,084字であり、件数比例の容量予測は使用しない。approved確定後の文字量・句読点・VOICEVOX実測から正式forecastを作る。
- 追加WAVは`104,857,600` bytes以下を許可し、`104,857,601` bytes以上で停止する。生成前に正規化文字量・unique音声ID・推定durationから作品別forecastを作成する。
- Pages公開物は`524,288,000` bytes以上で警告、`786,432,000` bytes以下は警告域として許可し、`786,432,001` bytes以上または10進`1,000,000,000` bytes以上で停止する。source repositoryは`750,000,000` bytes以上で警告、`1,000,000,000` bytes以上で停止する。
- 単一Git objectは`104,857,600` bytes以上で停止する。作業ドライブは音声生成直前にdisk-guardで再確認し、`base = liveWriteUpperBounds + rollbackBackupBytes`、`required = base + max(67,108,864, ceil(base / 10))`として、空き容量が`required`と同値なら許可、1 byteでも不足すれば停止する。

## 7. 必須要求候補

1. F001/F002の作者・作品・台詞・音声・provenanceをexact baselineで不変照合する。
2. F003を承認済みBatchCandidateからdraft・3作品pendingで生成し、候補を自動公開しない。
3. 権利適格性を選定時と公開直前に再確認する。
4. 原典のbyte/hash/charset/本文selectorを固定し、候補全件をレビューする。
5. 二重編集判定、単一候補の数値上限、未完・公式内容注意の表示を機械検証し、条件未確定の音声生成を拒否する。
6. 作品単位atomic受入、最終統合、clean candidate release、公開後全route smokeを行う。
7. 手動入力を必須証跡にせず、自動試験と既存判断artifactで完結する。
