# 機能設計書 F003（太宰治コンテンツ追加）

## 1. 設計方針

F003はF002で実装済みの継続バッチ、CatalogV2、差分音声、作品単位atomic受入、release-verifyを再利用し、作者・作品固有のapplication code分岐を追加しない。追加するのは、承認済み候補データ、太宰治の画像・由来、3作品の原典・編集・音声artifact、およびF003で明確化した独立二重編集判定と単一候補安全性の共通契約である。

処理順は`000275`女生徒→`001567`走れメロス→`000258`グッド・バイで固定する。公開済みF001/F002は入力baselineとして検査し、activeなF003が失敗しても既存publicを変更しない。

DDの`FUN-F003-*`はF003の追跡用論理IDであり、実装では既存F002関数を汎用化・再利用する。F003、太宰治、各作品名を含むapplication exportや条件分岐は作らず、固有値は検証済みregistry・manifest・artifactだけに置く。

## 2. 候補・原典・編集設計

### DES-F003-001: 承認候補registryとデータ駆動manifest [REQ-F003-002][REQ-F003-003][REQ-F003-004]

`content/batch-candidates.json`は公開候補registryであり、top-level exact keys `schemaVersion/candidates`、candidate exact keys `batchId/feature/author/works/approvalBinding`を持つ。authorは既存`BatchAuthor`と同じ`authorId/name/originalName/slug/identitySha256`を持ち、identityは`SHA-256(canonical({authorId,name,originalName,slug}))`とする。workは`workId/title/order/cardUrl/xhtmlUrl`、approval bindingは`queueId/approvalItemSha256/documents[{path,sha256}]/evidenceRef/evidenceSha256`を必須にし、SRSとQTを別documentとして保持する。F003固有値はregistry dataとして保持する。registry自身はcanonical JSON、expected old SHA、同directory temporary file、file sync、atomic rename、post-read hashで更新する。

候補registryは公開catalogではない。ProjectFactoryはQ-017のclosed item canonical projectionと、承認後のCHG-F003-001を含む現在ApprovedなSRS/QTのpath/SHAを`docs/evidence/requirements/F003-approval-binding.json`へ移行記録し、そのartifact SHAをregistryへ固定する。production loaderはworkspace、canonical queue path、expected queue SHA、binding artifactを受け、component identity/reparse、YAML schema、closed approval、document実体hashを再計算した`VerifiedClosedApproval`だけを返す。

このverified approvalと一致した1候補だけを既存の汎用`createNextBatchTemplate`で`content/batches/F003/batch.json`の`draft`へmaterializeする。manifestはregistryのwork orderどおり3 workを`pending`、stage artifactなしで開始する。UI、source取得、音声、統合処理はIDをコード定数にせずmanifestから受け取る。

### DES-F003-003: 権利適格性と原典固定 [REQ-F003-005][REQ-F003-006]

### DES-F003-004: 決定的な外側かぎ括弧抽出 [REQ-F003-007]

### DES-F003-005: 独立二重編集判定と裁定 [REQ-F003-008]

意味判定はapplicationからCodex等を起動せず、ProjectFactoryの親coordinatorが`pf-worker`（primary）、`pf-reviewer`（secondary）、不一致時`pf-acceptor`（adjudicator）へ独立委譲する。coordinatorは各実行前にartifact外の`ReviewRunAuthorization`を発行し、`authorizationId/role/producerTaskPath/judgeRole/runId/candidateSetSha256/policySha256/promptSha256/toolSha256/nonce/issuedAt`を固定する。`fork_turns: none`相当でprimary結果をsecondaryへ渡さず、primary/secondaryの両結果がcoordinator mailboxへ戻るまで共有filesystemへ書かない。adjudicatorだけはsealed両判定を入力に受ける。

application側は外部生成されたschema JSONをauthorizationと照合し、create-new-onlyの別artifactへ保存する。set headerにauthorization参照と`sealedAt/artifactSha256`、各判定に`candidateId/decision/reasonCode/speaker/sourceAnchor/inputSha256`を必須とする。authorizationはtrusted coordinator記録から読み、artifactの自己申告identityを信用しない。保存成功後にauthorizationを同じlock/journalでusedへatomic遷移し、再利用を拒否する。文学本文は命令ではなくuntrusted dataとしてdelimiter内に渡し、生成担当へnetwork・command実行を委譲しない。

一致対象は`candidateId/inputSha256/decision/reasonCode/speaker/sourceAnchor`であり、run固有metadataは一致対象にしない。不一致または曖昧判定はprimary/secondary双方と異なるproducer/judge/runの第三裁定artifactが揃うまで`pending`とし、音声stageへ渡さない。全候補の余分・欠落・重複・未判定を0にしてから、reconciliation digestを`reviewed` stageへ結合する。

### DES-F003-006: 読み上げrevisionと単一候補安全性 [REQ-F003-009][REQ-F003-013]

display textは原文のまま保持し、speech textの固有名・旧語・外来語・句読点補正を`SpeechRevision`のbefore/after/reason/revision/hash chainへ記録する。校正profileはF002 v0.2.0のaccepted WAVを固定config hashで再集計したcanonical artifactとし、`schemaVersion/sourceReleaseCommit/sourceSetSha256/configHash/sampleCount/secondsPerCharacter/safetyFactor/observedEstimatedBytes/observedActualBytes/observedRelativeError/maxRelativeError=0.20/outputSamplingRate=24000/bitDepth=16/channels=1/wavHeaderBytes=44/calibratedAt/artifactSha256`を必須にする。config/source hash不一致またはobserved errorが0.20を超える場合をstaleとする。

profileの全数値はfiniteでsafe integerまたは有限小数、`sampleCount=151`、`secondsPerCharacter>0`、`safetyFactor>=1.0`、`observedEstimatedBytes>0`、`observedActualBytes>0`を必須とする。`observedRelativeError = abs(observedActualBytes - observedEstimatedBytes) / observedEstimatedBytes`を再計算し、記録値と一致かつ`<=0.20`でなければ拒否する。

approved speech textは正規化後500 Unicode code point以下、`ceil(codePoints × secondsPerCharacter × safetyFactor × 1000)`で求める推定duration 120,000 ms以下、24 kHz・mono・16 bit PCM予測`44 + ceil(durationMs × 48)`かつ5,760,044 bytes以下を全て満たす必要がある。candidate safety artifactは`candidateId/speechSha256/profileSha256/configHash/limits/result`を持ち、reviewed stage、VoiceDiffPlan、generation authorizationへ結合して生成直前にも再計算する。

## 3. 音声・容量・受入設計

### DES-F003-007: 差分音声と5区分容量gate [REQ-F003-012][REQ-F003-013][REQ-F003-014]

F002の`content/batches/F002/voice-config.json`をrelease commitから検証し、canonical bytesを`content/batches/F003/voice-config.json`へ複製してsource path/hashを記録する。ENGINE `0.25.2`、speaker UUID、speaker名、style ID `3`、style名`ノーマル`、各scale、sampling rateのexact tuple/hashがF002と一致しないmanifestを拒否する。

本文/config hash由来audio IDを再利用し、approved・reconciliation digest・candidate safety PASSが同じinput tupleへ結合したunique speechだけをloopback ENGINEで生成する。既存同一audio IDは実体hash・bytes・duration・config一致時だけ再利用する。forecastとactualで追加WAV、Pages artifact、source repository、単一Git object、作業ドライブを別々に計測する。

| 区分 | 警告 | 停止 |
|---|---:|---:|
| F003追加unique WAV | なし | `> 104,857,600` bytes |
| Pages artifact | `>= 524,288,000` | `> 786,432,000` |
| source repository | `>= 750,000,000` | `>= 1,000,000,000` |
| 単一Git object | なし | `>= 104,857,600` |
| 作業ドライブ | なし | `freeBytes < base + max(67,108,864, ceil(base/10))` |

`base`は`liveWriteUpperBounds + rollbackBackupBytes`である。全値は整数byteで算入path・OID重複排除・測定時刻を証跡化する。警告域は`pass_with_warning`、停止域は`blocked`とし、actualでforecastを代用しない。

### DES-F003-008: 指定順の作品単位atomic受入 [REQ-F003-015]

女生徒→走れメロス→グッド・バイの順にだけ`pending → extracted → reviewed → budget-approved → voiced → accepted`へ進める。受入関数はcaller作成の`pass`値を信用せず、canonical allowlist pathからprimary/secondary/adjudication、safety、音声、容量、baseline content/distの原artifactを再読込し、schema、tool hash、input tuple、実体path/SHA/bytesを各production validatorで再計算したbranded evidenceだけを使う。

work artifactのcanonical保存先は`content/batches/{batchId}/work-artifacts/{workId}/`とし、`reviews/primary.json`、`reviews/secondary.json`、必要時`reviews/adjudication.json`、`review-reconciliation.json`、`candidate-safety.json`、`voice-completeness.json`、`capacity-actual.json`、`baseline-content.json`、`baseline-dist.json`をexact allowlist化する。作業中は`.cache/batches/{batchId}/{workId}/{transactionId}/`だけを使い、受入transactionが音声と全work artifactを同時にcanonical destinationへ昇格する。

review、音声完全性、容量actual、baseline不変、content/dist preview、hash chainが全てPASSしたworkだけをacceptedへ一括昇格する。exclusive lock、expected manifest/tree hash、random staging、journal、file sync、atomic rename、postwrite hash、bounded retryを用いる。process停止後はjournalと所有hashから旧版または完成新版へ決定的に回復し、第三者変更を上書きしない。文学作品として未完のグッド・バイも処理が完了すればacceptedにできる。

## 4. 公開UI・権利表示・安全設計

### DES-F003-009: Catalog統合・太宰route・注意表示 [REQ-F003-003][REQ-F003-004][REQ-F003-010][REQ-F003-011][REQ-F003-017]

統合器はpublished F001/F002とcandidate F003をbatch ID順に読み、identityが一致するauthor/work/dialogue/audio/provenanceだけをCatalogへ結合する。F002専用の`introducedByBatchId`、作者ID、画像path、4 route固定判定を廃止し、検証済みmanifest/catalogからauthor identity、artwork、期待route集合を導出する。route set digestは`ReleaseRuntimeArtifact` schema 2.0.0のpayloadに`runtimeAcceptanceRef/runtimeAcceptanceSha256`として追加し、`payloadSha256`へ結合する。F002の`ReleaseCandidateArtifactBinding` exact schemaへfieldを追加しない。

Catalog schemaを後方互換の`2.1.0`へ更新し、全workに汎用`completionStatus: complete|unfinished`と`notices[]`を追加する。notice exact keysは`kind: content-warning|excerpt-scope`、`textKey`、`sourceUrl?`、`evidenceSha256`とし、loader、fragment builder、work validator、作品一覧、作品画面、creditsのgeneric rendererを同時に更新する。既存workは`complete`と共通`excerpt-scope`へ決定的にprojectし、F001/F002固有項目のbaseline投影は不変にする。表示は固定`textKey`辞書とtext nodeだけを使う。

太宰治routeにはF003の3作品だけを所属させる。トップと作者画面では`だざいおさむ`と`原著者: 太宰治`を併記し、作者routeの遷移・直アクセス・再読込直後は全作品を閉じ、利用者操作時だけ展開する。グッド・バイには公式XHTML由来の`unfinished`と公式内容注意、女生徒には公式内容注意を作品一覧・作品画面・creditsへ表示する。全作品について「作品全文朗読・要約ではなく括弧発話の抜粋」である旨を表示する。

作者画像provenanceを`batchId/authorId/outputPath`をmanifest identityから受ける汎用schemaへ変更し、F002固定値をvalidatorから除く。F002 schema 2.0.0の`humanReview`はread-only互換で維持する。F003以降のschema 3.0.0は手動fieldの代わりに`machineReview{reviewerKind='project-factory-agent',producerTaskPath,runId,modelClass,imageSha256,policySha256,promptSha256,toolSha256,decision,reviewedAt,artifactSha256}`を必須にし、trusted coordinatorの実行記録と画像実体へ結合する。

独自生成または許諾済み入力だけをallowlist化し、prompt、recipe、model/provider/version、入力由来、license、入力/output hash、credit、判断artifactを`artwork-provenance.json`へ保存する。公開画像実体とcatalog/provenanceのhash不一致を停止する。

runtimeはtext node描画、同一origin asset、既存CSPを維持し、`innerHTML`、inline handler、`eval`、外部TTS、Cookie、storage、form、analyticsを使わない。外部linkは用途別canonical HTTPS allowlist型だけを受け、scheme/host/port/userinfo/query/fragmentを検査し、`rel="noopener noreferrer"`を強制する。更新時transportはDES-F003-003のproduction transportとloopbackだけを許可する。

Chromium、Firefox、WebKit、Android相当、390×844・844×390・1440×900、keyboard、reduced motionで`#/`、芥川、宮沢、太宰、`#/credits`の5 routeを自動試験する。手動・実機・目視・聴取・手動スクリーンリーダーを必須PASS証跡に含めない。

### DES-F003-012: exact candidate段階release [REQ-F003-001][REQ-F003-005][REQ-F003-014][REQ-F003-018]

全3 work accepted後にsource commitを固定し、clean checkoutのprepare-releaseで候補F003だけを既published batchへ統合してpublic commitを作る。F002の`ReleasePreparationContext`、`ReleaseBuildContext`、`ReleaseCandidateArtifactBinding`、discriminated evidence validatorをexact keysのまま再利用し、release commit、content build SHA、content tree SHA、dist SHA、evidence SHA、hosted artifact digest、QT、権利predeploy、容量actualを同じtupleへ結合する。route set digestはversioned`RuntimeAcceptanceEvidence`に入れ、そのref/hashを`ReleaseRuntimeArtifact` 2.0.0のpayloadへ追加して`payloadSha256`で拘束する。canonical allowlist pathから原artifactを再読込・再計算し、caller供給のPASSを信用しない。
