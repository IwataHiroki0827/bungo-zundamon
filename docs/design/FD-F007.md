# 機能設計書 F007（森鴎外3作品追加）

## 1. 設計方針

F007は公開済みv0.6.0を固定baselineとし、6人目の作者として森鴎外と「舞姫」「高瀬舟」「山椒大夫」を順次追加する。F007はF006（中島敦、既存4作者へ5人目を追加）と同型の「新規作者1人・3作品」構造であり、F005固有のETW常時監視・native guard機構は一切使用しない。F006がF005から確立した「phase前後の実測差分による事後検証」と、F001〜F006実績の汎用release経路は、値がfeatureに依存しない汎用実装であるため直接再利用する。

- 承認候補registry・汎用CAS・4ゲート参照（`src/content/batch.ts`、`batch-candidate.ts`）
- 独立二重レビュー（`src/content/editorial-independent.ts`）
- 差分音声・容量forecast（`src/voice/generation.ts`、`src/voice/budget.ts`）
- 作品単位atomic受入（`src/content/batch-acceptance.ts`のpromoteVerifiedWorkArtifacts）
- phase前後の実測差分によるwrite健全性事後検証（CHG-F005-072、`src/content/f005-postcondition.ts`・`f005-postcondition-write.ts`。feature非依存の汎用実装）
- 汎用artwork provenance schema設計パターン（F006の`f006-artwork.ts`と同型の専用軽量schemaをF007向けに新設する。共有の`src/notices/artwork-provenance.ts`はOpenAI image_gen専用に凍結されているため変更しない）
- 汎用release経路（`scripts/verify-project.mjs`、`recordPublishedBatch`、`PAGES_DEPLOY_ENABLED`/`PAGES_DEPLOY_COMMIT`ゲート）

をそのまま再利用し、新規に定義するのは森鴎外固有のauthor identity・3作品registry・catalog統合・独自画像provenance・v0.6.0固定baseline pinに限定する。これらはいずれも「exact値がfeatureごとに異なるため既存モジュールを直接呼べない」箇所であり、F003→F004→F005→F006で確立済みの「featureごとに専用pinモジュールを1本作る」パターン（`f006-baseline.ts`のF006 pin、`f005-catalog.ts`/`f006-catalog.ts`のCatalog merge）をF007向けに新設するだけで、application codeへ作者名・作品名による分岐は追加しない。

QA-F007の確定回答により、F007は次の分岐を扱う。

- entity正規化（QA No.3）: 対象3作品のXHTMLに未定義entityは検出されていないため、allowlist正規化コードパスは適用しない。ただし選定時・公開直前の両方で検出手順自体は実行し、1件でも検出されればfail-closedで停止する。
- 作品固有注記UI（QA No.4）: **舞姫の図書カードに公式表現注意が存在するため、舞姫にのみ`DataDrivenWorkNoticeV1`相当のnotice UIを適用する**（下記DES-F007-010で方式を確定する）。高瀬舟・山椒大夫には注記を生成しない。公開直前再確認で内容変更・削除・他2作品への新設が見つかった場合はfail-closedで停止する。
- `proofreader: null`（QA No.5）: 3作品とも校正者欄記載ありのため、既存の`Proofreader = NonEmptyString | null`型は変更しないが、F007データではnull分岐を発動させない。
- ディスク容量（QA No.9）: 実装フェーズ着手前に`.cache/`の再取得可能データを整理済み（29 GiB→35 GiB、2026-08-22）。生成前forecastは実行時点の実測空き容量で改めて判定する。

## 3. 原典・抽出・レビュー

### DES-F007-004: 権利適格性と原典固定 [REQ-F007-005][REQ-F007-006]

選定時とpredeploy時に、既存`ProductionAozoraTransport`（F002〜F006が使用するHTTPS exact allowlist・DNS public IP確認・接続IP pin・redirect/proxy/retry禁止のtransport）だけを用いて公式拡充CSV・作家ページ・図書カードを取得し、人物/作品著作権なし、役割=著者、翻訳者なし、公開中、新字新仮名、author/work/URL一致を確認する。VOICEVOX・ずんだもんの各利用規約へ無料・広告なし・課金なし・スポンサーなし・非公式の用途分類と必須creditを適用し、`decision: allow`だけを取得日時・URL・raw SHA・接続証跡付きでrelease commit/runへ結合する。差分・未判定・transport異常はfail-closedとする。

XHTML（`058126_73682.html`／`045245_22007.html`／`000689_23257.html`）はexact URL、raw bytes、charset、本文selector、取得日時、SHA-256、底本、入力者、校正者、更新日を作品別`SourceRecordV2`相当へ固定する（`proofreader`はnon-null値のみを使用）。predeploy観測はrelease commitと結合し、選定時との差分・期限切れ・欠落を停止条件とする。DOMAIN-F007.mdで実際に取得済みのraw SHA-256（舞姫`6f2f8363c4d56c79e4a7d086a7eadb829d23e140a995fdf5a902d8750c4a2d0b`・高瀬舟`20b6db066b5589d7c218733cbc992896213188de1c6affd6a69651416df158a1`・山椒大夫`5c001bc5ef5990311de0e11e5f6d215efeeff49fcc816530501770c2734b1f01`）は選定時snapshotの参照値とし、公開直前の再取得時に同一かどうかを実測で確認する（一致を前提にせず改めて検証する）。

### DES-F007-005: 未定義entity検出と決定的抽出 [REQ-F007-007]

原典rawは変更せず、raw SHA-256を先に検証する。既存の未定義entity検出手順を選定時と公開直前の独立snapshotで実行し、対象3作品に未定義entity・`gaiji_list`問題が0件であることを確認する（DOMAIN-F007.md §3で`gaiji_list`セクション自体が非存在であることを実測確認済み）。1件でも検出されればfail-closedで当該作品を`pending`に留め、F005確立済みのversion付きexact allowlist正規化手順を必要な場合にだけ再利用対象とする。F007側で新しい正規化ルールは追加しない。

固定原典のexact XHTML 1.1外部DOCTYPE宣言だけをnetwork/filesystem resolverなしで許し、internal subset、他DOCTYPE、ENTITY、XInclude、外部schema/stylesheetをアクセス前に拒否する。深さ・node・属性・text上限内だけを解析し、候補ID・順序・表示文を決定的に生成する。同じ入力2回で候補集合のcanonical hashが一致しない場合は非決定的として停止する。

### DES-F007-006: 独立二重判定 [REQ-F007-008]

全候補をprimary/secondaryが互いの結果を見ずに判定する。既存`editorial-independent.ts`（F002〜F006が使用する汎用モジュール）の`registerEditorialAuthorizations`・`sealAndValidateEditorialJudgmentSet`・`reconcileIndependentJudgments`・`verifyEditorialCompleteness`・`loadAndVerifyEditorialJudgmentSets`をそのまま用い、`candidateSetSha256/policySha256/promptSha256/toolSha256/nonce`を含む一回限りのauthorizationで判定を封印する。不一致digestが確定した場合だけ第三裁定（adjudicator）authorizationを発行し、それ以前の裁定を拒否する。最終`pending: 0`まで音声stageへ渡さない。中断時は`recoverEditorialJudgmentTransaction`で回復する。3作品中最大の会話量（山椒大夫、かぎ括弧候補120件・発話文字概算7,751文字）はF006の最大値（弟子、57件・2,242文字）を上回るため、独立二重判定の作業量が既存4バッチより多くなる点をリスクとして記録する。

### DES-F007-007: 読み上げ補正 [REQ-F007-009]

display textは原文のまま保持し、旧語・固有名・外来語の読み補正を既存`applySpeechRevisions`（`src/content/f003-reuse.ts`）のbefore/after/reason/revision/hash chainへ記録する。舞姫のドイツ由来外来語・人名（エリス、豊太郎等）、高瀬舟・山椒大夫の旧語（庄屋、人買い等）はVOICEVOX実測に基づき個別に補正候補を作成する。候補の余分・欠落・重複・pendingを0としたreconciliation digestを後続stageへ固定する。

## 4. 音声・容量・受入

### DES-F007-008: 単一候補安全性・差分音声・容量事後検証 [REQ-F007-011][REQ-F007-012]

単一候補の安全性判定・差分音声生成は既存`src/voice/generation.ts`の`planVoiceDiff`・`authorizeVoiceDiffPlan`・`generateVoiceDiff`・`verifyVoiceCompleteness`をそのまま用いる。固定VOICEVOX tuple（ENGINE `0.25.2`、speaker UUID、style ID `3`、style名`ノーマル`、24 kHz/mono/16 bit PCM）はF002以来の既存configをF007向けにcanonical複製し、承認済み台詞だけを差分生成する。既存同一audio IDは実体hash・bytes・duration・config一致時だけ再利用する。単一候補は正規化後500 code point以下、推定120,000 ms以下、`44 + ceil(durationMs × 48)`かつ5,760,044 bytes以下を満たす場合だけ生成対象とする。

容量forecastは既存`forecastCapacity`・`measureGitRepository`・`verifyActualCapacity`（`src/voice/budget.ts`）を用い、REQ-F007-012が定める追加WAV・Pages artifact・source repository・単一Git object・作業ドライブの各区分をbyte単位で判定する。DOMAIN-F007.md §4の予測（追加127.9MiB、予測公開432.6MiB、GitHub Pages 1GiB上限に611MiBの余裕）を選定値として引き継ぐが、正式判定は生成前forecastの実測値を用いる。

書込み健全性（宣言外pathの新規出現・変更・消失が0件であること）は、SRS §3.1が明示するとおりCHG-F005-072で確立した事後検証方式をそのまま継続利用する。既存`scanF005Workspace`でphase開始時にbaseline snapshotを取り、既存`foldF005Declarations`で宣言済みmutationをsequence順に畳み込み、phase完了後に既存`verifyF005Postconditions`で実測差分とexact一致することを検証する。一時書込みは既存`writeF005TemporaryFile`で行う。native guardやETW常時監視は新設しない。いずれか不成立ならfail-closedとし、raw pathを出さない固定codeで停止する。

### DES-F007-009: 作品単位atomic受入 [REQ-F007-013]

舞姫→高瀬舟→山椒大夫の順にだけ`pending → extracted → reviewed → budget-approved → voiced → accepted`へ進める。受入は既存`promoteVerifiedWorkArtifacts`（`src/content/batch-acceptance.ts`）をそのまま用い、caller作成の`pass`値を信用せず、canonical allowlist pathからprimary/secondary/adjudication、safety、音声、容量、DES-F007-002のbaseline原artifactを再読込・再計算したbranded evidenceだけを使う。work artifactのcanonical保存先・作業staging・exclusive lock・expected manifest/tree hash・random staging・journal・file sync・atomic rename・postwrite hash・bounded retryは既存契約をそのまま継承する。process停止後は既存journalベースの回復から旧版または完成新版へ決定的に回復し、第三者変更を上書きしない。F006実装で判明した「間接ハッシュ規約と`promoteVerifiedWorkArtifacts`の直接evidence要求が噛み合わない」問題（F006 FUN-F006-010の方式訂正）が同型で発生する見込みが高く、F006同様の薄い受入ラッパー（`src/content/f007-acceptance.ts`）を新設する前提とする（詳細はDD-F007.mdで確定する）。

### DES-F007-012: 森鴎外独自作者画像とdHash provenance [REQ-F007-016]
