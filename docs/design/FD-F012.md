# 機能設計書 F012（聴く体験の拡充、v1.1.0）

## 1. 設計方針

F012はv1.0.0の公開Catalog・音声・書誌を入力として使うだけで、content pipeline（`src/content/**`・`scripts/f0NN-*.ts`）と公開tree（`public/`）を変更しない。
追加はruntime UI（`src/ui/*`・`src/main.ts`・`src/style.css`）、service worker（`src/sw/service-worker.js`）、build補助（`scripts/service-worker-build.mjs`・`vite.config.ts`）、
静的security検査（`scripts/release-checks.mjs`・`scripts/f002-security.mjs`）に限定する。表示文字列はすべて既存`setSafeText`経由のtextContentで描画し、innerHTML系sinkを追加しない。

## 2. 設計要素

### DES-F012-001: 作品単位の連続再生 [REQ-F012-001]

`AudioController`へ連続再生状態（key・台詞配列・index）を追加する。`playSequence(key, items)`は全台詞がCatalogに存在する場合だけ先頭から再生し、
`ended`で次の台詞を同じ単一Audio要素へ読み込む。最後の台詞の終了で`ended`（「連続再生が終わりました。」）を通知する。
一時停止・再開では状態を保持し、`control('stop')`・現在位置以外の台詞の明示再生・route切替・音声エラー・asset欠損・dispose で解除する。
進行状況は状態messageへ「（連続再生 n/N）」として表示し、作品パネルの「連続再生」ボタン（`aria-pressed`）で開始・停止する。

### DES-F012-002: お気に入りの書き出し・取り込み・共有 [REQ-F012-002]

新規`src/ui/favorites-transfer.ts`はstorageへ触れない純粋関数（書き出しJSON生成・取り込み検証・共有URL生成/解析）とする。
取り込み結果は`FavoriteController.merge(ids)`（`src/ui/favorites.ts`）だけが保存し、保存直前にstorageを再読込して他タブの変更を失わない。
共有リンクは`<base>?fav=v1:<id>,<id>...#/favorites`とし、hash routeを増やさない。起動時に1回だけ`location.search`を解析して`history.replaceState`で共有queryを除き、
お気に入り画面に確認UI（追加する/追加しない）を表示する。自動取り込みはしない。書き出しは`Blob`+`download`属性、取り込みは`input[type=file]`（form要素なし）で行う。

### DES-F012-003: トップ画面内の台詞検索 [REQ-F012-003]

新規`src/ui/search.ts`がCatalogごとに正規化済み索引（WeakMap）を1回だけ作り、キーワードと作者IDで絞り込む。
トップ（CatalogV2の作者一覧）に「台詞をさがす」sectionを置き、結果は既存`renderDialogueCard`で描画するため再生・停止・お気に入りの契約を共有する。

### DES-F012-004: 再生速度・音量 [REQ-F012-004]

`AudioController`が設定値（速度は許可リスト、音量は0〜1へ丸め）をsession中だけ保持し、`load()`直後に`defaultPlaybackRate`/`playbackRate`/`volume`を再適用する。
作者ページ・お気に入り・トップ検索に「再生設定」group（select・range・output）を置く。

### DES-F012-005: 今日の一台詞 [REQ-F012-005]

新規`src/ui/daily.ts`がUTC+9固定で暦日keyを作り、FNV-1a32でCatalog順の全台詞から1件を選ぶ。トップに再生・お気に入り可能なカードと作者ページへのlinkを表示する。
基準時刻は試験のため`ApplicationOptions.now`で注入できる。

### DES-F012-006: オフライン対応 [REQ-F012-006]

- build: Vite plugin（`scripts/service-worker-build.mjs`）がproduction buildだけで`dist/manifest.json`（web app manifest）と`dist/sw.js`を出力する。
  `sw.js`へはbundle内容・manifest・起動必須data（catalog・licenses・artwork provenance一式）から計算した版数と、precache一覧を埋め込む。
- service worker（classic script、import/exportなし）:
  - install: `bz-shell-<版数>`へapp shellと起動必須dataを保存し、`skipWaiting`
  - activate: `bz-shell-`で始まる旧版cacheだけを削除し、`clients.claim`
  - 画面遷移はnetwork優先（失敗時に保存済みshell）、`assets/`はcache優先、`content/*.json`はnetwork優先で`bz-data-v1`へ保存、`artwork/`はstale-while-revalidateで`bz-media-v1`へ保存
  - `audio/`は`bz-audio-v1`に保存済みの場合だけcacheから返し、Range要求へ206/416で応答する。未保存の音声はservice workerで保存しない
  - cache照合は`ignoreVary`で行う（module scriptのOrigin header差でhitしない問題を防ぐ）
- 画面側（`src/ui/offline.ts`）: production buildかつsecure contextで`sw.js`を`updateViaCache: 'none'`・scope `/bungo-zundamon/`で登録する。
  お気に入り音声の保存は「お気に入りの音声を保存する」操作で初めて有効化し（`bz-audio-v1`内のmarker）、Catalog順・重複除去で50,000,000 bytes以内を計画し、
  `navigator.storage.estimate()`の空きから10,000,000 bytesを残す範囲で取得する。取得した音声はCatalogのbytes・SHA-256一致を確認してから保存し、
  お気に入りの増減に追従して不要分を削除する。無効化で`bz-audio-v1`を削除する。

### DES-F012-007: 作品データカード [REQ-F012-007]

作品パネルの導入部に、既存Catalogの作者表示名・原著者・作品名・底本・収録台詞数・原典確認日（`fetchedAt`の日本時間日付）を`dl`で表示し、
既存の図書カードlinkと新しい「本文を青空文庫で読む」link（`source.textUrl`）を置く。linkは既存の`aozoraLinkV2`（作者別canonical範囲、https、資格情報・port・query・fragmentなし）で検証し、
`target=_blank`・`rel="noopener noreferrer"`とする。新しい解説文は作らない。

### DES-F012-008: 既存契約・セキュリティ [REQ-F012-008]

- CSPの変更は`worker-src 'none'`→`worker-src 'self'`だけとする。`release-checks.mjs`・`f002-security.mjs`の必須CSPへ`'worker-src': ["'self'"]`を追加し、
  `'none'`・`blob:`・外部origin・`*`を拒否する試験を追加する（CHG-F012-001）。
- 新規module（favorites-transfer・offline・search・daily・render-f012）は端末保存APIの名前を含まず、F002のお気に入りstorage契約（専用key・1 module）を維持する。
- Playwright既存specは`serviceWorkers: 'block'`で従来経路のまま実行し、service worker受入は`tests/e2e/f012-offline.spec.ts`だけがallowへ切り替える。
- 公開routeは既存13件のまま（`?fav=`はqueryでありrouteではない）。

## 3. セキュリティレビュー（DES-F012-006/008）

| 観点 | リスク | 対策・判定 |
|---|---|---|
| worker-src緩和 | 任意scriptをworkerとして実行される | `'self'`だけを許可し、`blob:`・`data:`・外部origin・`*`は静的検査で拒否。登録先は同一originの固定`sw.js`だけ。判定: 許容 |
| service workerの応答改ざん | cacheした古い/不正な応答を返し続ける | 画面遷移・公開dataはnetwork優先、app shellは版付きcacheでactivate時に旧版削除。`sw.js`は`updateViaCache: 'none'`で毎回更新確認。判定: 許容 |
| 音声保存の整合性 | 改ざん・途中切断した音声の保存 | 公開Catalogのbytes・SHA-256と一致したものだけ保存。scope外・別origin・GET以外はservice workerで扱わない。判定: 許容 |
| 端末容量 | 保存領域の圧迫 | 利用者の明示的有効化のみ、50 MB上限、空き容量から10 MBを残す、無効化で全削除。判定: 許容 |
| プライバシー | 外部送信・追跡 | 共有リンク・書き出しに含むのは公開台詞IDだけ。外部送信なし、`referrer`は既存の`no-referrer`。Cookie/form/解析なし。判定: 許容 |
| 取り込みの入力検証 | prototype汚染・巨大入力・不正ID | exact key（`__proto__`等の追加keyを拒否）、サイズ・件数・ID文字種検証、Catalog join後だけ使用。判定: 許容 |
| DOM注入 | 書誌・検索語の描画 | すべてtextContent、検索語は64文字で切り詰めて正規化のみ。innerHTML系sink 0（build時静的検査）。判定: 許容 |
| 外部link | reverse tabnabbing・open redirect | 青空文庫の作者別canonical範囲だけ、`noopener noreferrer`。判定: 許容 |
