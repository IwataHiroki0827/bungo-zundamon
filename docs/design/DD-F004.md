# 関数設計書 F004（宮沢賢治追加3作品・お気に入り）

## 0. 共通型・境界

| 型 | 契約 |
|---|---|
| `ApprovedF004Candidate` | Q-022/Q-023、Approved SRS/QT、既存宮沢identityへ結合済みの3作品候補 |
| `PublishedV030Baseline` | release commit `79d1282…`の公開payloadとcontrol commit `5a1a06a…`のpublished制御状態を分離して検証したbrand型 |
| `ExistingAuthorIdentity` | Catalog実体から再計算した`authorId/name/originalName/slug/identitySha256` exact tuple |
| `BatchCatalogFragment` | `authorContribution`で`introduce`（検証済みauthor/artwork/provenance付き）または`reuse`（`authors: []`）を区別し、`mode=work-preview|final`をbrandで分離する汎用fragment |
| `WorkPreviewCatalog` / `FinalCatalog` | 対応するfragment brandからだけ生成するCatalog。previewをrelease/accepted入力へ、finalを途中受入previewへ相互代入できない |
| `FavoriteStoreV1` | exact `{version:1,dialogueIds:string[]}`。最大5000、Catalog順unique IDだけ |
| `FavoriteDialogueView` | 保存IDを現行Catalogへjoinして得た`dialogue/author/work/audio`の読み取り専用view |
| `FavoritePersistence` | safeな`storageProvider: () => StorageLike`からexact localStorage keyへread/write/removeする境界。getterを含む例外時はmemoryへ縮退 |
| `FavoriteController` | application mountごとに1個。`snapshot/toggle/subscribe/dispose`と永続化・memory縮退を所有し全rendererへ共有 |
| `FavoriteNavigationIntent` | Catalog join済み`authorId/workId/dialogueId`とuser activation identityを持つ一回限りのmemory intent |
| `PersistedBatchPath` | workspace相対POSIXとしてschema検証済みの永続path。絶対pathではない |
| `VerifiedBatchDefinition` | canonical registry descriptorのpath・expected SHA・batch/feature・work order・`authorExpectation`をproduction loaderが再計算してmintするbrand型。caller objectを受けない |
| `VerifiedApprovalBindingPolicy` | canonical policy descriptorのpath・expected SHA・queue/SRS/QT/CHG canonical path・required state・hash規則をproduction loaderが再計算してmintするbrand型 |
| `ApprovedBatchContext` | immutableな`candidate/definition/policy`を束ね、production loaderが検証済みbrandの正規受け渡し経路として返す |

永続pathはworkspace相対POSIX、browser assetは公開root相対POSIXとする。filesystemまたはURL API直前だけ検証済みbaseへ結合する。先頭slash、空segment、`.`、`..`、backslash、scheme、authority、query、fragment、percent encoded separator/control、symlink/junction/reparse pointを拒否する。

## 1. 候補・baseline

### FUN-F004-001: loadAndVerifyBatchCandidate(workspace, definitionRef, expectedDefinitionSha, policyRef, expectedPolicySha) -> Promise<ApprovedBatchContext> [DES-F004-001][DES-F004-011]

definition/policy refはworkspace内canonical allowlist pathだけを受け、component identity・reparse・expected SHA・descriptor exact schemaを再検証する。production loader自身が`VerifiedBatchDefinition`と`VerifiedApprovalBindingPolicy`をmintし、caller提供object、required state、path、`authorExpectation`を受けない。

verified policyが指定するqueue/SRS/QT/CHGをcanonical pathから再読込する。F004 policyではQ-022/Q-023はclosed承認、SRS/QTはApproved、CHGは`in-review`かつQ-023 binding済みであること、document SHA、candidate exact keys、F004 ID、3 work ID/title/order、descriptor batch/feature一致を照合する。CHGの`done`はrelease準備でだけ要求する。Q-017やF003 pathをコードへ固定せず、承認flagや候補objectのcaller注入を許さない。異常は`F004_APPROVAL_MISMATCH`または`CANDIDATE_REGISTRY_INVALID`。

成功時は検証済み`candidate`、mint済み`VerifiedBatchDefinition`、`VerifiedApprovalBindingPolicy`をimmutableな`ApprovedBatchContext`として同時に返す。後続FUN-F004-005/021/033/037はこのcontextからだけbrandを受け取り、descriptorを再構成しない。

### FUN-F004-002: loadPublishedV030Baseline(workspace, pins) -> Promise<PublishedV030Baseline> [DES-F004-002]

`pins`のrelease commit/tag/catalog/dist/artifact/public file tupleと、control commit/F003 published manifest SHAをexact検査する。公開projectionはrelease Git objectから、published controlはcontrol Git objectから読み、現行checkoutから自己生成しない。混同・欠損・hash差は`F004_BASELINE_MISMATCH`。

### FUN-F004-003: verifyPublishedV030Invariant(baseline, candidateTree) -> BaselineInvariantReport [DES-F004-002]

既存content/media assetをpath/bytes/SHAで、Catalogとprovenanceを3作者・9作品・472台詞・463音声のcanonical projectionでexact比較する。application asset差分はF004のDES/FUN/UT/ITへ追跡可能なpath allowlistとsource diffへ照合する。F004 accepted workと承認済みapplication差分以外を列挙し、1件でも不許可ならblockedとする。

### FUN-F004-004: verifyExistingAuthorIdentity(candidate, catalog) -> Result<ExistingAuthorIdentity> [DES-F004-001][DES-F004-007]

candidate authorと既存宮沢authorの`authorId/name/originalName/slug/identitySha256`を再計算してexact比較する。0件、複数件、field差、identity hash差は`F004_AUTHOR_IDENTITY_CONFLICT`。名前の近似一致やIDだけの一致を許可しない。

### FUN-F004-005: createF004BatchManifest(candidate, author, gateRefs) -> BatchManifest [DES-F004-001]

検証済みcandidateとauthorだけを入力に、status `draft`、3 work `pending`、stage artifactなし、4ゲート参照付きmanifestを既存generic templateで作る。work orderとIDはcandidateどおり、author identityは参照だけとし、重複author entryを生成しない。

### FUN-F004-007: freezeF004Source(work, transport, rights) -> Promise<FixedBatchSource> [DES-F004-003]

### FUN-F004-009: sealF004JudgmentSet(workspace, authorization, externalResult) -> Promise<EditorialJudgmentSet> [DES-F004-004]

trusted coordinatorの未使用authorizationとexternalResultのcandidate/input/semantic fieldsを照合する。authorizationは`feature/batchId/workId/reviewRole/producerTaskPath/runId/candidateSet/policy/prompt/tool/nonce/issuedAt/expiresAt`をexact検査し、create-new-only sealと未使用→使用済みcompare-and-swapを同じtransactionで行う。期限切れ・role/work横断・再利用を拒否する。primary、secondary、adjudicatorのproducer/runを分離し、secondaryへprimary artifactを渡さない。

### FUN-F004-010: reconcileF004Judgments(candidates, primary, secondary, adjudication?) -> EditorialResolutionSet [DES-F004-004]

### FUN-F004-011: compileF004SpeechRevisions(approved, revisions) -> SpeechItem[] [DES-F004-004]

display textを保持し、speech revisionのbefore/after/reason/input/output hash chainを連続検査する。循環、飛び越し、別candidate混入を`SPEECH_REVISION_CHAIN_INVALID`で拒否する。

## 3. 音声・容量・atomic受入

### FUN-F004-013: projectBatchArtifactPaths(workspace, manifestIdentity, persistedPaths) -> ResolvedBatchPaths [DES-F004-011]

全batch共通でworkspace相対POSIX pathをschema検証し、component identity/reparseを確認してfilesystem API用絶対pathへ解決する。F003/F004などbatch IDによる分岐を持たない。永続artifactへ絶対pathを戻さない。違反は`BATCH_WORKSPACE_BOUNDARY`。

### FUN-F004-014: planF004VoiceDiff(manifest, reviewedItems, cache, config, paths) -> VoiceDiffPlan [DES-F004-005][DES-F004-011]

review digest、safety report、speech/config hashを再検算し、canonical speech/configからaudio IDを作る。既存実体がhash/bytes/duration/config exactの場合だけhitとする。planのpathはpersisted relative formだけを保持する。

### FUN-F004-015: generateF004VoiceDiff(plan, loopbackClient, diskGuard) -> Promise<VoiceDiffResult> [DES-F004-005]

固定ENGINE/speaker/style/configを実APIと照合し、missだけをwork stagingへ最大同時1で生成する。各write前に残予算とfree bytesを検査し、WAV構造・duration・hashを検証する。失敗時はaccepted/cache/publicを変更しない。

### FUN-F004-016: forecastF004Capacity(input) -> CapacityForecast [DES-F004-005]

追加unique WAV、完全Pages preview、OID重複排除repository、単一object、work driveを整数byteで独立判定する。警告と停止を区別し、算入path/OID/測定時刻/profile hashを結合する。

### FUN-F004-017: measureF004ActualCapacity(workspace, dist, voices, gitAdapter) -> Promise<ActualCapacityReport> [DES-F004-005]

実WAV、完全dist、pack/loose/new/未object化候補、free bytesをsafe pathから実測する。同一OIDを一度だけ数え、work reportをrelease reportへ流用しない。境界超過は`F004_CAPACITY_BLOCKED`。

### FUN-F004-018: prepareF004WorkAcceptance(workspace, manifestPath, workId, evidenceRefs, baseline, preview: BatchWorkPreview) -> PreparedWorkAcceptance [DES-F004-006]

manifest順と直前work acceptedを確認し、canonical allowlistから全原artifactを再読込する。FUN-F004-037のpreview tree/hash、review、speech、safety、voice、capacity、baselineをproduction validatorで再計算し、同一input tupleへ結合する。順序違反は`F004_WORK_ORDER`。

### FUN-F004-019: acceptF004Work(workspace, prepared, expectedManifestSha) -> Promise<BatchManifest> [DES-F004-006]

exclusive lock下でaudio、artifact、manifestをrandom staging/journalへ用意し、file sync、atomic rename、post-read hashで一括昇格する。`accepted`への直接書換えを許さず、既存状態機械を通す。

### FUN-F004-020: recoverF004WorkAcceptance(workspace, journal) -> Promise<RecoveryResult> [DES-F004-006]

journal phase、expected old/new SHA、stage ownerから旧版または完成新版へ収束する。第三者変更、不明owner、hash不一致は隔離し、上書きしない。

## 4. Catalog・表示・お気に入り

### FUN-F004-021: projectBatchCatalogFragment(definition: VerifiedBatchDefinition, manifest, includedWorks, baseline, mode) -> BatchCatalogFragment [DES-F004-007][DES-F004-011]

副作用なしで追加work/dialogue/audio/source/licenseを投影する。`mode=work-preview`は先行accepted workと現在の検証済みstaged work 1件だけをmanifest順で許可し、`WorkPreviewCatalogFragment`を返す。`mode=final`は全manifest work acceptedを必須にし、`FinalCatalogFragment`を返す。両brandは相互代入不可で、previewをaccepted/final入力へ流用できない。

作者modeはcaller値ではなくbaseline identity joinから導出する。join 0件は検証済み新作者identity・artwork・provenanceが完全な場合だけ`introduce`、exact 1件はidentity一致時だけ`reuse`とし`authors: []`、複数件またはidentity差は拒否する。導出modeをApproved binding由来の`definition.authorExpectation`と照合し、F004は`reuse`以外を拒否する。全F004 workのauthorIdが既存authorと一致し、author/artwork/provenance新規entryが0であることを確認する。F003/F004別のCatalog loaderを作らない。

### FUN-F004-022: mergeExistingAuthorCatalog(baselineCatalog, fragment, author) -> WorkPreviewCatalog | FinalCatalog [DES-F004-007]

`fragment: WorkPreviewCatalogFragment`には同じmodeの`WorkPreviewCatalog`、`fragment: FinalCatalogFragment`には`FinalCatalog`を返すdiscriminated overloadとする。previewはmanifest先頭から現在staged workまでの1〜3作品、finalは全3 accepted作品を既存宮沢3作品末尾へmanifest順で追記する。modeと件数・work stateの不一致を拒否し、brandを戻り値まで維持する。他作者projectionをexact維持し、ID衝突、未知author、別作者混入、順序差を拒否する。application sourceの作者・作品分岐を使用しない。

### FUN-F004-023: verifyReusedMiyazawaArtwork(baseline, catalog, provenance) -> ArtworkReport [DES-F004-007]

宮沢画像のpath/bytes/SHA/provenance/creditをbaselineとexact比較し、F004由来の新画像・新provenance・重複creditが0であることを確認する。

### FUN-F004-024: validateF004NoticesAndRuntimeState(catalog, document) -> RuntimeContentReport [DES-F004-008]

3作品の抜粋・原作由来・書誌creditを作者/panel/creditsへ固定text keyからtext node表示する。作者route初期open 0、利用者操作だけで展開、音声controllerのroute停止・同時1・個別エラー隔離を検査する。

### FUN-F004-025: parseFavoriteStore(raw: string | null, catalog) -> FavoriteLoadResult [DES-F004-009]

rawが262144 UTF-16 code unitを超える場合はJSON parseせず破損扱いにする。範囲内だけをexact `{version,dialogueIds}`として検査し、version 1、string ID、ID長1〜128 code unit、既存`DialogueId` validator、最大5000を適用する。Catalog mapへjoinし、未知・重複を除いてCatalog順へ正規化する。本文等の余分field、malformed、未知version、上限超過はreason付き空状態または安全な正規化結果を返し、throwしない。

### FUN-F004-026: createFavoritePersistence(storageProvider: () => StorageLike, catalog) -> FavoritePersistence [DES-F004-009]

providerからstorageを取得するgetter自体をtry境界内で実行し、exact key `bungo-zundamon:favorites:v1`だけをread/write/removeする。保存はcanonical `FavoriteStoreV1`だけとし、getter/read/write/remove例外・quota時はmemory stateへ縮退して`persistence=memory`を返す。他key列挙、Cookie、外部通信を行わない。

### FUN-F004-027: toggleFavorite(state, dialogueId, catalog) -> FavoriteTransition [DES-F004-009]

dialogueIdをCatalog mapへjoinし、有効IDだけを追加/削除してCatalog順unique・最大5000を維持する。buttonの`aria-pressed`、可視ラベル、classを同じtransitionから導出する。audio controllerを呼ばない。

### FUN-F004-028: selectFavoriteDialogueViews(store, catalog) -> FavoriteDialogueView[] [DES-F004-010]

保存IDを現行Catalogへjoinし、Catalog順のauthor/work/dialogue/audio viewを返す。保存文字列を表示値やasset pathとして返さない。未知IDは0件として除外する。

### FUN-F004-029: renderFavoritesRoute(views, audioController: AudioController, favoriteController: FavoriteController, navigation) -> RouteView [DES-F004-010]

共通navigationへ可視かつkeyboard操作可能な`#/favorites`リンクを描画する。route内は作者・作品見出し、台詞、再生、解除、元作品への移動をtext nodeで描画する。元作品の利用者操作からCatalog join済み`FavoriteNavigationIntent`を作り、既存作者hashへ遷移後にDOM参照mapで対象panelを展開してfocusする。intentは一回消費し、直アクセス・再読込・back/forwardでは生成・復元しない。0件時の案内を表示する。route離脱時にaudioを停止し、解除後focusを次項目または空状態見出しへ移す。

### FUN-F004-030: createFavoriteController(storageProvider: () => StorageLike, catalog) -> FavoriteController [DES-F004-009][DES-F004-010]

application mount時に1個だけ生成し、provider getterを含む全storage操作を`FavoritePersistence`のtry境界へ置いて初回snapshotを作る。`toggle`はpure transition後にcanonical保存、`subscribe`はauthor/favorites rendererへ同じimmutable snapshotを通知、`dispose`はlistenerとmemory stateを解放する。storage取得・操作失敗時は同じcontroller内でmemoryへ縮退する。`RenderContext`へcontrollerを必須注入し、rendererからstorageへ直接アクセスさせない。

## 5. security・release

### FUN-F004-031: deriveExpectedF004Routes(catalog, staticRoutes) -> ExpectedRouteSet [DES-F004-012][DES-F004-013]

検証済みCatalogの3作者routeと固定home/favorites/creditsからexact 6 routeを導出し、canonical digestを作る。未知featureはfail-closed、重複・不足・余分routeを拒否する。F004 route allowlistは5 routeを流用しない。

### FUN-F004-032: verifyF004RuntimeSecurity(dist, routes) -> Promise<RuntimeAcceptance> [DES-F004-012]

CSP、危険DOM、外部link/通信、Cookie/form/secret、依存、workflow pinを検査する。storageはお気に入りmoduleのexact key/schemaだけを許可し、保存本文・他key・外部送信を拒否する。4 browser/3 viewport/keyboard/reduced motionで6 route、初期全閉、お気に入り、音声を自動受入する。

### FUN-F004-033: prepareBatchRelease(workspace, definition: VerifiedBatchDefinition, context) -> Promise<ReleasePreparation> [DES-F004-011][DES-F004-013]

generic definitionとmanifestからbatch集合を導出し、F003/F004別のpreview/final commandを使わない。clean source commit、3 work accepted、T-062完了、CHG-F004-001の影響試験完了と`done`、baseline、権利predeploy、容量actual、security、UT/IT/QTをcanonical artifactから再検証する。FUN-F004-021/022の`FinalCatalogFragment → FinalCatalog`だけを最終統合へ許可し、preview brandを拒否する。既公開v0.3.0の再deploy可能なcommit/artifact ID/digest/deployment IDをrollback descriptorへ固定し、F004だけをpublicへatomic統合する。

### FUN-F004-034: verifyF004ReleaseCandidate(cleanCheckout, tuple) -> Promise<ReleaseVerification> [DES-F004-013]

tracked publicを変更せず再buildし、catalog/content tree/dist、6 route digest、hosted artifact、権利、容量、全試験を同一candidate tupleへ結合する。release commitとcontrol baselineを区別して照合する。

### FUN-F004-035: recordPublishedF004(workspace, manifestPath, expectedSha, context, approval, deployment, smoke, deployDisabled) -> Promise<BatchManifest> [DES-F004-013]

ゲート④、release tuple、deployment、公開6 route、宮沢6作品、初期open 0、お気に入り隔離context、Catalog/画像/Range音声/CSP smoke、deploy無効化が一致した場合だけpublishedへ遷移する。lock、reparse/hash再検査、journal、sync、atomic renameを必須にし、同値は冪等、別値は競合停止する。

### FUN-F004-036: rollbackF004Deployment(descriptor, failedDeployment, adapter) -> Promise<RollbackResult> [DES-F004-013]

ゲート④前に固定したv0.3.0のcommit/artifact ID/digest/deployment IDを再検証し、F004 smoke失敗時だけ既知正常artifactを再deployする。復旧後にv0.3.0の495 files、catalog/dist SHA、5 route、画像、音声Rangeを再smokeする。rollback descriptorと異なるartifact、caller指定URL、未知digestを拒否する。

deploy変数を有効化する前にcanonical release journalを`deploy-disable-pending`へatomic write・file syncし、repository/variable/commit/release tuple/owner/expected SHAを固定する。pre-arm完了を再読込検証できない限りenable/deployを呼ばない。

release処理は成功・deploy失敗・smoke失敗・rollback失敗の全経路で独立した`finally`処理を呼び、deploy変数を無効化してAPI応答だけでなくread-back `false`を確認する。確認後だけexpected journal SHA付きcompare-and-swapで`closed`へ遷移する。無効化API/read-back失敗またはrelease親process/端末停止時はpre-armed pending journalが残り、closed evidenceなしでpublished遷移を許さない。

同FUNの独立cleanup entrypoint `recoverPendingDeployDisablement(workspace, journalPath, expectedJournalSha, adapter)`は起動時または別processからpending journalを走査し、repository/variable identity、journal owner、release tuple、expected SHAを再検証する。無効化を冪等実行してread-back `false`とcleanup evidenceを記録し、CASでclosedへ遷移する。fault解除前はpendingを維持し、解除後だけreleaseを閉じる。

### FUN-F004-037: prepareBatchWorkPreview(definition: VerifiedBatchDefinition, baseline, acceptedWorks, pendingWork, artifacts) -> Promise<BatchWorkPreview> [DES-F004-006][DES-F004-007][DES-F004-011]

検証済みgeneric definition、固定baseline、先行accepted work、現在の検証済みstaged pending work 1件、canonical artifactからCatalog/public/dist previewを構築する。FUN-F004-021を`mode=work-preview`で呼び、FUN-F004-022の`WorkPreviewCatalogFragment → WorkPreviewCatalog` overloadだけを使用する。F003/F004別script、作者・作品名分岐、caller指定author modeを許さない。preview tree hashとbaseline invariantをFUN-F004-018の受入tupleへ渡し、preview自体はpublic/accepted treeを変更しない。最終統合は`FinalCatalogFragment → FinalCatalog`だけを使用する。
