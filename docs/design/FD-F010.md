# 機能設計書 F010（梶井基次郎3作品追加）

## 1. 設計方針

- 承認候補registry・汎用CAS・4ゲート参照（`src/content/batch.ts`、`batch-candidate.ts`）

- phase前後の実測差分によるwrite健全性事後検証（CHG-F005-072、`src/content/f005-postcondition.ts`・`f005-postcondition-write.ts`。feature非依存の汎用実装）

- 長大候補分割（QA No.11相当）: F007で発見・F008/F009で踏襲したVOICEVOX synthesis約1,335文字超500エラーへの対応（F007/F008/F009ローカル抽出層での600文字閾値句点分割）の**実装は行わない**。DOMAIN-F010.md §3.1の実測でF010候補の最大単一候補長は133文字（Ｋの昇天）であり、600文字閾値の1/4以下、失敗境界1,335文字の1/10以下である。F008と同様の「非発動見込み」ケースだが、F010は既存F007ローカル抽出層（`src/voice/generation.ts`・`src/voice/client.ts`は無変更）が持つ句点分割ロジック自体は将来の再抽出時の安全側機構として存在を維持しつつ、**F010固有の分割wiringは実装しない**（F009のようにF010専用の分割関数を新設・複製する必要はない）。正式抽出時に実測で600文字超候補が確認された場合に限り、F007/F008/F009と同一手法を追加実装する。
- ディスク容量（QA No.14相当）: 2026-08-24時点で約79.79 GiB前後の空きがあり、絶対量floor（5 GiB）を大きく上回るため追加の予防整理は不要。実装フェーズでも重い処理前の`Get-PSDrive C`点検は継続する。

## 3. 原典・抽出・レビュー

### DES-F010-004: 権利適格性と原典固定 [REQ-F010-005][REQ-F010-006]

選定時とpredeploy時に、既存`ProductionAozoraTransport`（F002〜F009が使用するHTTPS exact allowlist・DNS public IP確認・接続IP pin・redirect/proxy/retry禁止のtransport）だけを用いて公式拡充CSV・作家ページ・図書カードを取得し、人物/作品著作権なし、役割=著者、翻訳者なし、公開中、新字新仮名、author/work/URL一致を確認する。VOICEVOX・ずんだもんの各利用規約へ無料・広告なし・課金なし・スポンサーなし・非公式の用途分類と必須creditを適用し、`decision: allow`だけを取得日時・URL・raw SHA・接続証跡付きでrelease commit/runへ結合する。差分・未判定・transport異常はfail-closedとする。

XHTML（`424_19826.html`／`419_19702.html`／`411_19633.html`）はexact URL、raw bytes、charset、本文selector、取得日時、SHA-256、底本、入力者、校正者、更新日を作品別`SourceRecordV2`相当へ固定する（`proofreader`はnon-null値のみを使用。3作品とも入力=j.utiyama、校正: 檸檬=野口英司、Ｋの昇天=野口英司、愛撫=高橋美奈子）。predeploy観測はrelease commitと結合し、選定時との差分・期限切れ・欠落を停止条件とする。DOMAIN-F010.mdで実際に取得済みのraw SHA-256（檸檬`5e3e8a10842d7bea38106c953e30c353c295af9b0126abbf3f933b06f4b62a17`・Ｋの昇天`acb638b4448f94973c5f92c8bcdd7c0bf035cf8547d71446fd8e63e525509233`・愛撫`f9425cae78bf2bda7b0eed75079a37fd19b2962ca35d06e34ccc5d305043eccc`）は選定時snapshotの参照値とし、公開直前の再取得時に同一かどうかを実測で確認する（一致を前提にせず改めて検証する）。

### DES-F010-005: 未定義entity・gaiji検出（常時有効）と決定的抽出 [REQ-F010-007]

原典rawは変更せず、raw SHA-256を先に検証する。既存の未定義named entity検出手順（`preflightF00NXhtml`/`normalizeF00NAozoraXhtmlEntities`と同型の標準5種entity allowlist検査）を選定時と公開直前の独立snapshotで実行し、対象3作品に未定義entityが0件であることを確認する（DOMAIN-F010.md §5で実測確認済み）。

**gaiji要素の候補内非混入検証はF009で確立済みの機構をそのまま踏襲する**。DOMAIN-F010.md §5のとおり檸檬の地の文には`<img class="gaiji">`要素が1件実在する（「闊」の異体字、候補内には0件該当を選定時に確認済み）。F009で新設された`detectF009GaijiElements`/`verifyNoGaijiWithinCandidates`と同型の関数を、F010は新規に`detectF010GaijiElements(rawText)`（`<img\b[^>]*class="gaiji"[^>]*>`相当の要素を走査し、byte offset集合を返す）と`verifyNoGaijiWithinCandidates`（F009のsignatureをF010の`F010CandidateSet`型に合わせて再定義した`verifyF010NoGaijiWithinCandidates`）として`f010-source.ts`へ実装し、選定時と公開直前の独立snapshotの両方で、gaiji出現位置と候補の`rawTokenRange`の重なりが0件であることを機械的に検証する。1件でも重なりが検出された場合はfail-closedで当該作品を`pending`に留める。F010はF008の「該当なし」ケースのように検出手順を無効化することはせず、F009同様に検出手順を条件分岐なしで常時有効なまま適用する。既存の`normalizeSpeechText`（`processing.ts`）が持つ`/[〓※�]/u`検査（speechText確定時の残存gaiji検出）はfeature非依存のまま無変更で適用され続け、F010はこの経路にも条件分岐によるスキップを追加しない。

固定原典のexact XHTML 1.1外部DOCTYPE宣言だけをnetwork/filesystem resolverなしで許し、internal subset、他DOCTYPE、ENTITY、XInclude、外部schema/stylesheetをアクセス前に拒否する。深さ・node・属性・text上限内だけを解析し、候補ID・順序・表示文を決定的に生成する。同じ入力2回で候補集合のcanonical hashが一致しない場合は非決定的として停止する。

**長大候補分割は本DESの適用外**（下記1点を明示する）: DOMAIN-F010.md §3.1が実測したとおりF010の最大単一候補長は133文字（Ｋの昇天）であり、600文字の句点分割閾値に遠く達しない。F009の`splitOverlongF009Candidates`のようなF010専用複製は新設しない。既存F007ローカル抽出層で確立した句点分割ロジック自体は将来の再抽出に備えて温存されるが、F010固有の新規実装・wiringは行わない（REQ-F010-019は非機能・非発動見込みとして扱う）。

### DES-F010-006: 独立二重判定 [REQ-F010-008]

全候補をprimary/secondaryが互いの結果を見ずに判定する。既存`editorial-independent.ts`（F002〜F009が使用する汎用モジュール）の`registerEditorialAuthorizations`・`sealAndValidateEditorialJudgmentSet`・`reconcileIndependentJudgments`・`verifyEditorialCompleteness`・`loadAndVerifyEditorialJudgmentSets`をそのまま用い、`candidateSetSha256/policySha256/promptSha256/toolSha256/nonce`を含む一回限りのauthorizationで判定を封印する。不一致digestが確定した場合だけ第三裁定（adjudicator）authorizationを発行し、それ以前の裁定を拒否する。最終`pending: 0`まで音声stageへ渡さない。合計かぎ括弧候補概算39件・発話文字概算1,026文字はF006（62件・2,412文字）・F009（106件・3,714文字）より大幅に少なく、F001〜F009の既存8作者バッチの中で最も判定作業量が少ないバッチとなる見込みである。

### DES-F010-008: 単一候補安全性・差分音声・容量事後検証 [REQ-F010-011][REQ-F010-012]

単一候補の安全性判定・差分音声生成は既存`src/voice/generation.ts`の`planVoiceDiff`・`authorizeVoiceDiffPlan`・`generateVoiceDiff`・`verifyVoiceCompleteness`をそのまま用いる。固定VOICEVOX tuple（ENGINE `0.25.2`、speaker UUID、style ID `3`、style名`ノーマル`、24 kHz/mono/16 bit PCM）はF002以来の既存configをF010向けにcanonical複製し、承認済み台詞だけを差分生成する。既存同一audio IDは実体hash・bytes・duration・config一致時だけ再利用する。単一候補は正規化後500 code point以下、推定120,000 ms以下、`44 + ceil(durationMs × 48)`かつ5,760,044 bytes以下を満たす場合だけ生成対象とする。DOMAIN-F010.md §3.1の実測最大候補長133文字はこの上限を大幅に下回るため、上限判定は事実上非発動が見込まれるが、判定ロジック自体は他featureと同様に無条件で適用する。
