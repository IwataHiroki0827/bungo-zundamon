# 関数設計書 F005（夏目漱石3作品追加）

## 1. 共通契約

- 永続pathはabsolute、drive、UNC、device、extended-length、ADS、backslash、空・dot segment、percent encoded separator、control、Windows予約名、末尾dot/space、case/Unicode衝突を拒否する。trusted root内のregular fileをvolume/file ID付きhandleで開き、symlink、junction、reparse point、hardlinkを拒否し、rename前後でidentityを再検証する。
- production関数はcaller提供の`pass`、`approved`、SHA、件数を信用せず、canonical artifactを再読込して再計算する。
- 例外の公開値は固定error codeと安全なdetailだけとし、raw本文、OS path、stack、secret、外部応答本文を含めない。
- JSONはUTF-8、key順・配列順を固定し、SHA-256の対象bytesを一意にする。永続更新はexpected SHA、random staging、fsync、atomic rename、post-read検証を使う。
- `WorkPreview*`と`Final*`はbrandを分離し、型assertionやcaller flagで相互変換しない。

主要interfaceを次に固定する。

- `VerifiedApprovalBindingPolicy`: control commit完全SHA、canonical artifact path/SHA、許可queue/document version、内部固定application diff policy。
- `ApprovedBatchContext`: policy digest、Q-027〜Q-031、SRS/QT/CHG bytes/SHA、candidate/baseline/gate参照を検証済みbrandで保持する。
- `F005WorkSnapshot`: workId、card/XHTML各`url/fetchedAt/rawBytes|rawPath/rawSha256/transportEvidence`。
- `SourceRecordV2`: snapshot参照を失わず`charset/selector/edition/inputter/proofreader/updatedAt`を追加する。`Proofreader = NonEmptyString | null`。
- `EntityNormalizationResult`: algorithm、raw bytes/SHA、offset/context、replacement count、processed bytes/SHA。
- `CapacityForecastV3`/`CapacityActualV3`: 6区分、算入path/OID/hash、時刻、initial/minimum free、predicted/peak live bytes、phase journal SHA。
- `CapacityRecorder`: `beginPhase/endPhase/observeMutation/close`を持ち、guard観測と各呼出しをfsync済みjournalへ追記する。
- `WorkAcceptanceJournalV3`: owner、phase、各pathのold/new SHA、staged path、evidence refs、closed容量journal SHA、actual report SHA。payload昇格とmetadata finalizeを一つの論理transactionとして表す。
- `ReleasePreparation`: gate①〜③、candidate commit、FinalCatalog、test/security/rights/capacity evidenceの検証済みbrand。
- `DataDrivenWorkNoticeV1`と`ArtworkProvenanceV4`は既存F003 notice、F002 artwork schemaを変更せず追加する。

## 2. Definition・baseline・manifest

### FUN-F005-001: loadVerifiedF005Definition(workspace) -> Promise<ApprovedBatchContext> [DES-F005-001][DES-F005-002]

FUN-F005-045だけがmintしたrequirement policyと、FUN-F005-048だけが再読込してmintした`VerifiedImplementationRegistryControl`を内部取得する。approval snapshotの`content/batch-definitions/F005.json`、snapshot専用`content/batch-candidates/F005.json`、`content/approval-policies/F005.json`、binding evidence、Q-027〜Q-031、Approved SRS/QT、CHGを再読込し、専用registryのF005候補が一意でdefinitionの3作品・順序・author identity・approval bindingとexact一致する場合だけ結合する。統合後共有registry SHAはimplementation controlと一致させ、caller path/commit/SHAやmutable descriptorを使わない。

### FUN-F005-002: loadV040Baseline(git, context: ApprovedBatchContext) -> Promise<V040Baseline> [DES-F005-001]

完全SHAへ解決した固定Git objectと`content/baselines/F005-v0.4.0.json`からCatalog、content/media、public tree、release evidence、published batchを読む。public 694 files/229844709 bytes、dist 697 files/229935951 bytes、catalog/dist/artifact SHA、3作者・12作品・674台詞・662音声を分離検証する。

### FUN-F005-003: verifyV040Projection(context, baseline, candidateTree) -> BaselineInvariantReport [DES-F005-001]

既存projectionをexact比較する。許可application差分は承認済みpolicyの内部定数から導き、caller入力を受けない。

### FUN-F005-004: verifyNatsumeIdentity(context, baselineCatalog) -> VerifiedNewAuthor [DES-F005-002]

`000148/夏目漱石/なつめそうせき/natsume-soseki`とidentity hashを再計算し、baseline join 0件、全author ID/name/slug/artworkとの衝突0を確認する。join 1件以上、identity差、別作者workは`F005_AUTHOR_IDENTITY_CONFLICT`。

### FUN-F005-005: createF005Manifest(workspace, context: ApprovedBatchContext, author) -> Promise<BatchManifest> [DES-F005-002]

contextからだけ`000799 → 001076 → 001104`を全て`pending`、4ゲート参照付きで作成する。既存manifestが同一canonical bytesなら冪等、別内容なら`F005_MANIFEST_CONFLICT`。caller指定のwork順、初期state、expectedAbsentを受け取らない。

## 3. 権利・原典・抽出

### FUN-F005-006: collectF005SourceSnapshot(transport, context, phase, trustedClock) -> Promise<F005SourceSnapshot> [DES-F005-003]

公式originだけを取得し、全A/AAAA public・peer pin・Host/SNI/certificate、exact status/content-type/charset、encoded/decoded cap、timeoutを検査する。mapped/special address、redirect、proxy、decompression bomb、partial responseを拒否する。上限はarchive/card/XHTML/規約各8,388,608 bytes、展開CSV 33,554,432 bytes。URL、時刻、raw bytesまたはsafe path、SHA、HTTP/TLS/DNS/peer evidenceを保存する。

### FUN-F005-007: evaluateF005RightsAndUsage(snapshot, usageProfile) -> RightsUsageDecision [DES-F005-003]

人物/作品権利なし、役割著者、翻訳者0、公開中、新字新仮名をexact判定する。用途profileは無料・広告なし・課金なし・スポンサーなし・非公式とし、VOICEVOX/ずんだもん規約の全条件とcreditを評価する。全て許可時だけ`decision="allow"`、差分・未知・未判定は`decision="blocked"`と理由codeを返す。productionはblockedを`F005_USAGE_NOT_ALLOWED`として停止する。

### FUN-F005-008: parseF005SourceRecord(snapshot: F005WorkSnapshot, expectedWork) -> SourceRecordV2 [DES-F005-003]

snapshotのURL、取得時刻、raw bytes/path/SHAを保持したまま書誌を追加する。`000799`の欄欠落だけnullを許し、他作品null、空文字、推測値を拒否する。

### FUN-F005-009: normalizeAozoraXhtmlEntities(rawBytes, sourceRecord, policyVersion) -> EntityNormalizationResult [DES-F005-004]

3作品すべてに結果を返す。`000799/001076`はrawを変更しないpassthrough variant（replacement 0、raw/processed SHA一致）、`001104`は固定2件を置換するentity variantとする。いずれもprocessed bytesを保存・再読込し、workId付き`processed: RawArtifactRef`へ結合する。

### FUN-F005-010: extractF005DialogueCandidates(normalization: EntityNormalizationResult, source, extractorVersion) -> CandidateSet [DES-F005-004]

`normalization.processed`をsafe handleから再読込してSHAを照合し、Shift_JIS fatal decode後にUTF-8 bytes化する。SAX preflightはXML宣言と、改行・空白をcanonical化したexact `<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.1//EN" "http://www.w3.org/TR/xhtml11/DTD/xhtml11.dtd">`だけを許すが、DTD resolverを実装せずnetwork/filesystem accessを行わない。internal subset、他DOCTYPE、ENTITY宣言、標準5種以外のnamed entity参照、XInclude、外部schema/stylesheetを拒否し、resource counter通過後だけDOM parseする。

## 4. レビュー・読み・notice

### FUN-F005-011: issueF005ReviewAuthorizations(coordinator, producer, candidateSet, workId, primary, secondary, promptTemplate, audience, expiresAt) -> ReviewAuthorizationSet [DES-F005-005]

### FUN-F005-013: buildF005SpeechRevisions(reconciliation, revisionEntries) -> SpeechRevisionSet [DES-F005-005]

display textを不変にし、speech textだけへbefore/after/reason/revision/input/output SHA chainを適用する。候補外revision、循環、hash断絶、原文改変は`F005_SPEECH_REVISION_INVALID`。

### FUN-F005-014: extractVerifiedShumiNotice(cardSnapshot, catalogNotice) -> VerifiedWorkNotice [DES-F005-005][DES-F005-010]

公式card rawから表現注意を抽出し、text/source URL/raw SHA/notice SHAを再計算してCatalog値と照合する。自己申告値同士だけの一致、HTML注入、欠落、複数候補、文言差は`F005_NOTICE_INVALID`。
