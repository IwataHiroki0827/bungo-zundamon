## 3. 原典・抽出・レビュー

### DES-F011-004: 権利適格性と原典固定 [REQ-F011-005][REQ-F011-006]

選定時とpredeploy時に、既存`ProductionAozoraTransport`（F002〜F010が使用するHTTPS exact allowlist・DNS public IP確認・接続IP pin・redirect/proxy/retry禁止のtransport）だけを用いて公式拡充CSV・作家ページ・図書カードを取得し、人物/作品著作権なし、役割=著者、翻訳者なし、公開中、新字新仮名、author/work/URL一致を確認する。VOICEVOX・ずんだもんの各利用規約へ無料・広告なし・課金なし・スポンサーなし・非公式の用途分類と必須creditを適用し、`decision: allow`だけを取得日時・URL・raw SHA・接続証跡付きでrelease commit/runへ結合する。差分・未判定・transport異常はfail-closedとする。

XHTML（`637_13341.html`／`628_14895.html`／`4718_13223.html`）はexact URL、raw bytes、charset、本文selector、取得日時、SHA-256、底本、入力者、校正者、更新日を作品別`SourceRecordV2`相当へ固定する。**二ひきの蛙は校正者が2名併記される**（もりみつじゅんじ・鈴木厚司）ため、`proofreader`フィールドはnon-null単一値だけでなく**複数値を配列で保持できるcanonical schema**を用いる（手袋を買いに=伊藤祥、ごん狐=浜野智の単一値ケースと二ひきの蛙の複数値ケースの両方を同一schemaで扱う。QA-F011 No.7）。入力者は手袋を買いに=大野晋、ごん狐=林裕司、二ひきの蛙=めいこ。predeploy観測はrelease commitと結合し、選定時との差分・期限切れ・欠落を停止条件とする。DOMAIN-F011.mdで実際に取得済みのraw SHA-256（手袋を買いに`73d4ba057c8a2beb5a32623c3cad7c7f60d06bcb086c74b11a7a85290b71943e`・ごん狐`b5349b05e15045ce567769ccce400c176c7657ede7fcd65eacc898c5c4c552b0`・二ひきの蛙`e3cd583604bfb050767863b5cbdad48d732a8296c90eeddebde2e19ca568cfcc`）は選定時snapshotの参照値とし、公開直前の再取得時に同一かどうかを実測で確認する（一致を前提にせず改めて検証する）。

### DES-F011-005: 未定義entity・gaiji検出（常時有効）と決定的抽出（分割なし） [REQ-F011-007]

原典rawは変更せず、raw SHA-256を先に検証する。既存の未定義named entity検出手順（`preflightF00NXhtml`/`normalizeF00NAozoraXhtmlEntities`と同型の標準5種entity allowlist検査）を選定時と公開直前の独立snapshotで実行し、対象3作品に未定義entityが0件であることを確認する（DOMAIN-F011.md §5で実測確認済み）。

**gaiji要素の候補内非混入検証はF009/F010で確立済みの機構をそのまま踏襲する**。DOMAIN-F011.md §5のとおり3作品とも全文走査で`<img class="gaiji">`要素が0件である（F009=2作品、F010=1作品で実在が確認されたのと異なり、F011は「全文で0件」という初めてのケース）。F009/F010で新設された`detectF00NGaijiElements`/`verifyNoGaijiWithinCandidates`と同型の関数を、F011は新規に`detectF011GaijiElements(rawText)`（`<img\b[^>]*class="gaiji"[^>]*>`相当の要素を走査し、byte offset集合を返す）と`verifyF011NoGaijiWithinCandidates`（F010のsignatureをF011の`F011CandidateSet`型に合わせて再定義）として`f011-source.ts`へ実装し、選定時と公開直前の独立snapshotの両方で、gaiji出現位置と候補の`rawTokenRange`の重なりが0件であることを機械的に検証する。1件でも重なりが検出された場合はfail-closedで当該作品を`pending`に留める。**F011は「gaijiが実測0件だから検出手順を実装しない」という判断を取らない**。F009/F010同様に検出手順を条件分岐なしで常時有効なまま適用し、正しく「0件」を報告できることを実装フェーズのUT/ITで確認する。既存の`normalizeSpeechText`（`processing.ts`）が持つ`/[〓※�]/u`検査（speechText確定時の残存gaiji検出）はfeature非依存のまま無変更で適用され続け、F011はこの経路にも条件分岐によるスキップを追加しない。

固定原典のexact XHTML 1.1外部DOCTYPE宣言だけをnetwork/filesystem resolverなしで許し、internal subset、他DOCTYPE、ENTITY、XInclude、外部schema/stylesheetをアクセス前に拒否する。深さ・node・属性・text上限内だけを解析し、候補ID・順序・表示文を決定的に生成する。同じ入力2回で候補集合のcanonical hashが一致しない場合は非決定的として停止する。

**長大候補分割は本DESの適用外**（下記1点を明示する）: DOMAIN-F011.md §3.1が実測したとおりF011の最大単一候補長は228文字（手袋を買いに）であり、600文字の句点分割閾値に達しない。F009の`splitOverlongF009Candidates`のようなF011専用複製は新設しない。既存F007ローカル抽出層で確立した句点分割ロジック自体は将来の再抽出に備えて温存されるが、F011固有の新規実装・wiringは行わない（REQ-F011-019は非機能・非発動見込みとして扱う）。`extractF011DialogueCandidates`は最外側全角かぎ括弧候補の単純抽出のみを行い、分割ロジックを一切持たない設計とすることをここで明示的な設計判断として定める（他候補が将来増えても再修正が要らないよう、条件分岐で回避するのではなく分割関数自体を実装しない）。

## 4. 音声・容量・受入
