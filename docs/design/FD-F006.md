# 機能設計書 F006（中島敦3作品追加）

## 1. 設計方針

F006は公開済みv0.5.0を固定baselineとし、5人目の作者として中島敦と「山月記」「名人伝」「弟子」を順次追加する。F006はF003（太宰治、既存2作者へ3人目を追加）と同型の「新規作者1人・3作品」構造であり、F005で新設されたETW常時監視・native guard機構（`f005-native-guard.ts`、`native/f005-guard/`、CHG-F005-036〜071の限定分岐群）は一切使用しない。F005はCHG-F005-072で常時監視を事後検証へ置換し、実際のv0.5.0公開（`docs/evidence/release/RELEASE-F005.md`、CHG-F005-083）もF001〜F004実績の汎用release経路（`scripts/verify-project.mjs` + GitHub Actions `PAGES_DEPLOY_ENABLED`/`PAGES_DEPLOY_COMMIT`ゲート）で行われた。F006はこの実績path、すなわち

- 承認候補registry・汎用CAS・4ゲート参照（`src/content/batch.ts`、`batch-candidate.ts`）
- 独立二重レビュー（`src/content/editorial-independent.ts`）
- 差分音声・容量forecast（`src/voice/generation.ts`、`src/voice/budget.ts`）
- 作品単位atomic受入（`src/content/batch-acceptance.ts`のpromoteVerifiedWorkArtifacts）
- phase前後の実測差分によるwrite健全性事後検証（CHG-F005-072、`src/content/f005-postcondition.ts`・`f005-postcondition-write.ts`。F005-prefixだが workspaceRoot/roots を引数に取る汎用実装であり、値は一切F005固有ではない）
- 汎用artwork provenance（`src/notices/artwork-provenance.ts`のArtworkProvenanceV3/ArtworkManifestIdentity）に、REQ-F006-016が要求するdHash64近似判定だけをF005由来のpure関数（`computeDHash64V1`、`verifyPngjsLockfileIntegrity`、いずれも入力がpng bytesのみの汎用utility）で追加する
- 汎用release経路（`scripts/verify-project.mjs`、`recordPublishedBatch`、`PAGES_DEPLOY_ENABLED`/`PAGES_DEPLOY_COMMIT`ゲート）

をそのまま再利用し、新規に定義するのは中島敦固有の author identity・3作品registry・catalog統合・独自画像provenance・v0.5.0固定baseline pinの5点に限定する。これらはいずれも「exact値がfeatureごとに異なるため既存モジュールを直接呼べない」箇所であり、F003→F004→F005で確立済みの「featureごとに専用pinモジュールを1本作る」パターン（`published-baseline.ts`のF002 pin、`f004-baseline.ts`のF004 pin、`f005-catalog.ts`のF005 4作者merge）をF006向けに新設するだけで、application codeへ作者名・作品名による分岐は追加しない。

QA-F006の確定回答により、F006はF005が導入した次の分岐を必要としない。

- entity正規化（QA No.3): 対象3作品のXHTMLに未定義entityは検出されていないため、allowlist正規化コードパスは適用しない。ただし選定時・公開直前の両方で検出手順自体は実行し、1件でも検出されればfail-closedで停止する（新規正規化ルールをF006側で追加しない）。
- 作品固有注記UI（QA No.4): 図書カードに公式注意書きが存在しないため、`DataDrivenWorkNoticeV1`相当のnotice UIをF006向けには生成しない。公開直前再確認で新設が見つかった場合はfail-closedで停止する。
- `proofreader: null`（QA No.5): 3作品とも校正者欄記載ありのため、既存の`Proofreader = NonEmptyString | null`型は変更しないが、F006データではnull分岐を発動させない。

承認済みQ番号（Q-F006の該当closed item）・Approved SRS-F006/QT-F006のpath/SHAは`docs/evidence/requirements/F006-approval-binding.json`へ固定し、既存`loadAndVerifyClosedApproval`がcanonical queue item projection hashとbinding artifact実体hashを再計算した`VerifiedClosedApproval`だけを後続へ渡す。一致した1候補だけを既存`selectApprovedBatchCandidateAndCreateTemplate`（または`createBatchManifestFromApprovedContext`）で`content/batches/F006/batch.json`の`draft`へmaterializeし、山月記→名人伝→弟子の順に3 workを`pending`で開始する。F006向けの新規application exportやID分岐は作らない。

## 3. 原典・抽出・レビュー

### DES-F006-004: 権利適格性と原典固定 [REQ-F006-005][REQ-F006-006]

選定時とpredeploy時に、既存`ProductionAozoraTransport`（F002〜F005が使用するHTTPS exact allowlist・DNS public IP確認・接続IP pin・redirect/proxy/retry禁止のtransport）だけを用いて公式拡充CSV・作家ページ・図書カードを取得し、人物/作品著作権なし、役割=著者、翻訳者なし、公開中、新字新仮名、author/work/URL一致を確認する。VOICEVOX・ずんだもんの各利用規約へ無料・広告なし・課金なし・スポンサーなし・非公式の用途分類と必須creditを適用し、`decision: allow`だけを取得日時・URL・raw SHA・接続証跡付きでrelease commit/runへ結合する（`evaluateF005RightsAndUsage`・`evaluateF005PolicyClauses`を汎用utilityとして再利用）。差分・未判定・transport異常はfail-closedとする。

XHTML（`624_14544.html`／`621_14498.html`／`1738_16623.html`）はexact URL、raw bytes、charset、本文selector、取得日時、SHA-256、底本、入力者、校正者、更新日を作品別`SourceRecordV2`へ固定する（`parseF005SourceRecord`・`buildF005SourceProvenance`を汎用parserとして再利用、`proofreader`はnon-null値のみを使用）。predeploy観測はrelease commitと結合し、選定時との差分・期限切れ・欠落を停止条件とする。

### DES-F006-005: 未定義entity検出と決定的抽出 [REQ-F006-007]

原典rawは変更せず、raw SHA-256を先に検証する。既存の未定義entity検出手順（`collectF005SourceSnapshot`・`rehydrateF005SelectionSnapshot`・`rehydrateF005PredeploySnapshot`が内包するpreflight）を選定時と公開直前の独立snapshotで実行し、対象3作品に未定義entity・`gaiji_list`問題が0件であることを確認する。1件でも検出されればfail-closedで当該作品を`pending`に留め、F005確立済みのversion付きexact allowlist正規化手順（`normalizeAozoraXhtmlEntities`）を必要な場合にだけ再利用対象とする。F006側で新しい正規化ルールは追加しない。

固定原典のexact XHTML 1.1外部DOCTYPE宣言だけをnetwork/filesystem resolverなしで許し、internal subset、他DOCTYPE、ENTITY、XInclude、外部schema/stylesheetをアクセス前に拒否する。深さ・node・属性・text上限内だけを解析し、既存`extractF005DialogueCandidates`が候補ID・順序・表示文を決定的に生成する。同じ入力2回で候補集合のcanonical hashが一致しない場合は非決定的として停止する。

### DES-F006-006: 独立二重判定 [REQ-F006-008]

全候補をprimary/secondaryが互いの結果を見ずに判定する。既存`editorial-independent.ts`（F002〜F004が使用する汎用モジュール）の`registerEditorialAuthorizations`・`sealAndValidateEditorialJudgmentSet`・`reconcileIndependentJudgments`・`verifyEditorialCompleteness`・`loadAndVerifyEditorialJudgmentSets`をそのまま用い、`candidateSetSha256/policySha256/promptSha256/toolSha256/nonce`を含む一回限りのauthorizationで判定を封印する。不一致digestが確定した場合だけ第三裁定（adjudicator）authorizationを発行し、それ以前の裁定を拒否する。最終`pending: 0`まで音声stageへ渡さない。中断時は`recoverEditorialJudgmentTransaction`で回復する。

### DES-F006-007: 読み上げ補正 [REQ-F006-009]

display textは原文のまま保持し、旧語・固有名・外来語の読み補正を既存`applySpeechRevisions`（`src/content/f003-reuse.ts`。F003以来F004でも再利用されている汎用関数）のbefore/after/reason/revision/hash chainへ記録する。候補の余分・欠落・重複・pendingを0としたreconciliation digestを後続stageへ固定する。

## 4. 音声・容量・受入

### DES-F006-008: 単一候補安全性・差分音声・容量事後検証 [REQ-F006-011][REQ-F006-012]

単一候補の安全性判定・差分音声生成は既存`src/voice/generation.ts`の`planVoiceDiff`・`authorizeVoiceDiffPlan`・`generateVoiceDiff`・`verifyVoiceCompleteness`をそのまま用いる。固定VOICEVOX tuple（ENGINE `0.25.2`、speaker UUID、style ID `3`、style名`ノーマル`、24 kHz/mono/16 bit PCM）はF002以来の既存configをF006向けにcanonical複製し、承認済み台詞だけを差分生成する。既存同一audio IDは実体hash・bytes・duration・config一致時だけ再利用する。単一候補は正規化後500 code point以下、推定120,000 ms以下、`44 + ceil(durationMs × 48)`かつ5,760,044 bytes以下を満たす場合だけ生成対象とする。

容量forecastは既存`forecastCapacity`・`measureGitRepository`・`verifyActualCapacity`（`src/voice/budget.ts`、F002〜F004実績のETWに依存しない汎用実装）を用い、REQ-F006-012が定める追加WAV・Pages artifact・source repository・単一Git object・作業ドライブの各区分をbyte単位で判定する。

REQ-F006-012・REQ-F006-017が求める「宣言外pathの書込みが0件である」証明（書込み健全性）は、SRS §3.1が明示するとおりCHG-F005-072で確立した事後検証方式をそのまま継続利用する。native guardやETW常時監視は新設せず、既存`f005-postcondition.ts`（`scanF005Workspace`・`foldF005Declarations`・`verifyF005Postconditions`・`normalizeF005DeclaredPath`）と`f005-postcondition-write.ts`（`writeF005TemporaryFile`。排他作成+fsync+読み戻しSHA照合）を、追跡対象root `content`/`data`/`public`（`F005_TRACKED_ROOTS`は値そのものが汎用でF006にもそのまま適用できる）に対してそのまま呼び出す。phase開始時に`scanF005Workspace`でbaseline snapshotを取り、phase完了後に再走査した`actual`との差分が宣言済みmutation集合とexact一致することを`verifyF005Postconditions`で検証する。いずれか不成立ならfail-closedとし、raw pathを出さない固定codeで停止する。

### DES-F006-009: 作品単位atomic受入 [REQ-F006-013]

山月記→名人伝→弟子の順にだけ`pending → extracted → reviewed → budget-approved → voiced → accepted`へ進める。受入は既存`promoteVerifiedWorkArtifacts`（`src/content/batch-acceptance.ts`）をそのまま用い、caller作成の`pass`値を信用せず、canonical allowlist pathからprimary/secondary/adjudication、safety、音声、容量、DES-F006-002のbaseline原artifactを再読込・再計算したbranded evidenceだけを使う。work artifactのcanonical保存先・作業staging・exclusive lock・expected manifest/tree hash・random staging・journal・file sync・atomic rename・postwrite hash・bounded retryは既存契約をそのまま継承する。process停止後は既存journalベースの回復（`batch-production.ts`の`recoverBatchSourceArtifactPromotion`および`promoteVerifiedWorkArtifacts`内部journal）から旧版または完成新版へ決定的に回復し、第三者変更を上書きしない。

## 5. 公開UI・権利表示・安全設計

### DES-F006-010: Catalog統合・中島敦route・作品固有注記省略 [REQ-F006-010][REQ-F006-014]

v0.5.0時点のCatalog（schema 2.1.0、4作者・15作品、`completionStatus`/`notices[]`フィールド）へ中島敦authorと3作品を追記する専用統合モジュール`f006-catalog.ts`を新設する。構造は`f005-catalog.ts`の`mergeNewAuthorCatalog`・`deriveF005RouteSet`と同型（baseline join 0件・author/work/asset ID非衝突を検証し、既存4作者15作品のserialized projectionをexact維持したまま末尾追記する）だが、exact値（baseline authors数`4`→`5`、works数`15`→`18`、`batchId: 'F006'`、`authorId: '000119'`）がfeatureごとに異なるためモジュール本体は複製せず新規に定義する。application sourceへ作者名・作品名による分岐は追加しない。

QA-F006 No.4の確定回答により、対象3作品の図書カードに公式注意書きは存在しないため、`DataDrivenWorkNoticeV1`相当のnotice UIをF006の3作品向けには生成しない（`notices: []`のまま）。公開直前検査で図書カード「作品について」欄の新設注記が見つかった場合はfail-closedで当該作品を`pending`に留め、F005確立済みの注記UI実装パターンを再利用するまで追加しない。

統合後は5作者・18作品となり、公開routeはCatalogの5作者slugと固定home/favorites/creditsから`#/`、既存4作者route（`akutagawa-*`/`miyazawa-*`/`dazai-*`/`natsume-soseki`）、`#/authors/nakajima-atsushi`、`#/favorites`、`#/credits`のexact 8件を導出する。route setを手書きallowlistへ二重定義せず、重複・不足・余分・未知slugを拒否する。

### DES-F006-011: 初期全閉・単一音声・お気に入り契約の維持 [REQ-F006-015]

既存の単一AudioControllerとお気に入りstore（`bungo-zundamon:favorites:v1`）を無変更で再利用する。全dialogueとの1対1 control、`aria-pressed`、自動再生0、ユーザー操作前の音声取得0、同時再生1、route・作者・台詞切替時のpause/currentTime=0/src解除、古いevent世代の無視を維持する。保存IDはplain JSONのexact schema・件数・長さ・文字種を既存検証で確認し、Catalog join後だけURL/selector/DOM/pathに使う。中島敦route・3作品の追加はこの契約に対して新規分岐を要求しない。

### DES-F006-012: 中島敦独自作者画像とdHash provenance [REQ-F006-016]

作者画像は参照画像なしで独自生成し、参照入力をexact `[]`とする。既存の汎用`ArtworkProvenanceV3`/`ArtworkManifestIdentity`schema（`src/notices/artwork-provenance.ts`、batchId/authorId/outputPathをmanifest identityから受け取る汎用schema）へ、REQ-F006-016が要求するdHash64近似判定を追加した専用sealモジュール`f006-artwork.ts`を新設する。schema自体はF003以来汎用のため直接再利用するが、exact final image path（`content/batches/F006/public-files/artwork/nakajima-zundamon.png`等）と既存4作者画像との比較対象数（4件）はfeature固有のため、`f005-artwork.ts`の`sealF005ArtworkProvenance`/`verifyF005ArtworkAgainstCatalog`と同型の新規関数として定義する。

PNG decodeとdHash計算そのものは既存のfeature非依存pure関数`verifyPngjsLockfileIntegrity`・`computeDHash64V1`（`f005-artwork.ts`。入力はpng bytesのみで中島敦固有値を持たない）をそのまま呼び出す。既存4作者画像とのbyte一致、またはdHash64-v1（EXIF/alpha/BT.601・9×8 bilinear、bit順・hex表現固定）のHamming距離8以下を拒否する。machine review（`reviewerKind='project-factory-agent', producerTaskPath, runId, modelClass, imageSha256, policySha256, promptSha256, toolSha256, decision, reviewedAt, artifactSha256`）は既存`loadAndVerifyTrustedArtworkMachineReview`・`validateArtworkProvenance`で検証する。

## 6. セキュリティ・公開

### DES-F006-013: セキュリティ・自動品質・段階release [REQ-F006-017]

runtimeはtext node描画、同一origin asset、既存CSPを維持し、`innerHTML`・inline handler・`eval`・外部TTS・Cookie・favorite以外のstorage・form・analyticsを使わない。phase差分対象の全pathは既存`resolveSafeWorkspaceFile`でreparse point非該当・hardlink数1・identity一致を再検査する（DES-F006-008の事後検証契約と同じ境界）。既存security checker・offline Pages builder（frozen lockfile、build時network 0、Actions最小権限、`persist-credentials:false`、`uses:`40桁commit SHA pin）をそのまま再利用する。secret scan対象はtracked/untracked release入力・workflow・生成dist・upload artifact manifestとし、値を記録せず種類・件数だけを証跡化する。

Playwright既存project・既存test IDを不変baselineとして保持し、F006必須case（`#/`、既存4作者route、`#/authors/nakajima-atsushi`、`#/favorites`、`#/credits`のexact 8 route、画像200、local/hosted WAV Range 206）を追加してskip 0で通す。
