# 機能設計書 F004（宮沢賢治追加3作品・お気に入り）

## 1. 設計方針

F004は公開済みv0.3.0を固定baselineとし、既存作者の宮沢賢治へ「オツベルと象」「雪渡り」「カイロ団長」を順次追加する。F003までの候補承認、原典固定、独立二重レビュー、差分音声、作品単位atomic受入、Catalog統合、exact releaseを再利用する。

同一作者追加では、F004 fragmentに作者を再定義しない。承認候補のauthor identityが既存Catalogとexact一致することを先に検査し、fragmentは`authors: []`と追加workだけを持つ。既存宮沢画像の実体・由来・creditを再利用し、新規画像を生成しない。

お気に入りは全公開台詞の既存安定IDを端末内へ保存する。保存値はuntrustedなID集合として扱い、現行Catalogへのjoinに成功した台詞だけをtext nodeで描画する。アカウント、外部同期、共有、分析送信を追加しない。

固有値はcandidate、manifest、source、review artifactへ置き、application sourceへ作者名・作品名による条件分岐を追加しない。永続artifactのpathはworkspace相対POSIX、filesystem API境界だけで検証済み絶対pathへ解決する。F003だけを特別扱いするpath投影は共通関数へ置き換える。

## 2. 候補・baseline・原典

`content/batch-candidates.json`へF004 candidateを追加する。candidateは`batchId=F004`、`feature=F004`、既存宮沢identity、次の3 workを固定順で持つ。

| order | workId | title |
|---:|---|---|
| 1 | `000466` | オツベルと象 |
| 2 | `045679` | 雪渡り |
| 3 | `001918` | カイロ団長 |

Q-022/Q-023のclosed approval、Approved SRS/QT、各document SHAをapproval bindingへ固定する。CHG-F004-001は`in-review`かつQ-023へbinding済みであることをmanifest作成条件とし、影響試験完了前の`done`を要求しない。production loaderはqueue・binding・document実体をworkspaceから再読込して検証し、caller提供の承認済みflagを信用しない。release準備では別途、CHG-F004-001の全影響試験完了と`done`を必須にする。

承認候補からだけ`content/batches/F004/batch.json`を`draft`、3 workを全て`pending`、4ゲート参照付きで作る。既存Catalogから再計算した宮沢identityとcandidate identityが`authorId/name/originalName/slug/identitySha256`でexact一致しなければ作成しない。重複author、重複work、順序差、未知fieldを拒否する。

### DES-F004-004: 決定的抽出と独立レビュー [REQ-F004-007][REQ-F004-008][REQ-F004-009]

本文selector配下をDOM token化し、最外側全角`「...」`だけを抽出する。同一source hash・tool versionからcandidate ID、source anchor、順序、display textを決定的に生成し、本文外、壊れた括弧、単独`『』`を理由code付きで除外する。

全候補をprimaryとsecondaryが互いの出力を見ずに文脈付き判定し、semantic fieldsが一致したものだけを確定する。不一致は別実行のadjudicatorが裁定するまで`pending`とし、音声生成へ渡さない。authorizationは`feature/batchId/workId/reviewRole/producerTaskPath/runId/candidateSet/policy/prompt/tool/nonce/issuedAt/expiresAt`をtrusted coordinator記録とexact結合し、未使用から使用済みへのcompare-and-swapとartifact sealを同じtransactionで行う。期限切れ・role横断・work横断の再利用を拒否する。文学本文を命令ではなくuntrusted dataとして扱う。

display textは原文を保持し、speech textだけをbefore/after/reason/hash chain付き`SpeechRevision`で補正する。candidateの余分・欠落・重複・pendingを0にしたreconciliation digestを後続へ固定する。

## 3. 音声・容量・作品受入

### DES-F004-005: 単一候補安全性・差分音声・段階容量 [REQ-F004-011][REQ-F004-012]

v0.3.0既存音声から固定configで校正したprofileを検証し、approved speechを生成前に次の全境界へ通す。

| 区分 | 停止条件 |
|---|---:|
| speech length | `> 500` Unicode code point |
| estimated duration | `> 120000` ms |
| estimated WAV | `> 5760044` bytes |
| F004追加unique WAV | `> 104857600` bytes |
| Pages artifact | `> 786432000` bytes |
| source repository | `>= 1000000000` bytes |
| single Git object | `>= 104857600` bytes |
| work drive | `freeBytes < base + max(67108864, ceil(base/10))` |

Pagesは`>=524288000`、repositoryは`>=750000000`で`pass_with_warning`とし、停止とは区別する。追加WAV、Pages、repository、object、work driveをforecastとactualで別々に測り、actualをforecastで代用しない。

VOICEVOX ENGINE `0.25.2`、speaker UUID、style ID `3`、style名`ノーマル`、scale、24 kHz/mono/16 bitの既存tupleをexact再利用する。canonical speech/config由来audio IDが既存実体のhash・bytes・duration・configと一致する場合だけ再利用し、missだけをloopback ENGINEへ最大同時1で生成する。review/safety未承認、失敗、欠損、孤立を0にする。

### DES-F004-006: 指定順の作品単位atomic受入 [REQ-F004-013]

`000466 → 045679 → 001918`の順に`pending → extracted → reviewed → budget-approved → voiced → accepted`へ進める。直前work未accepted、順序違反、途中stage欠落を拒否する。

受入はcanonical allowlist pathからsource、review、reconciliation、speech revision、safety、voice completeness、capacity actual、baseline content/distを再読込し、schema、input tuple、実体SHA/bytesを再計算したbranded evidenceだけを使う。caller作成の`pass`値は受けない。

exclusive lock、expected manifest/tree hash、random staging、journal、file sync、atomic rename、post-read hash、bounded retryを使用し、音声・work artifact・manifestを一括昇格する。停止後はjournalと所有hashから旧版または完成新版へ決定的に回復し、第三者変更を上書きしない。

## 4. Catalog・UI・お気に入り

### DES-F004-007: 同一作者Catalog mergeと画像再利用 [REQ-F004-003][REQ-F004-004][REQ-F004-014][REQ-F004-016]

F004 fragmentは`authors: []`とaccepted workだけを持ち、各workの`authorId`は既存宮沢IDを参照する。統合器は既存author identityをexact検証した後、宮沢の既存3作品末尾へF004順で3作品を追記する。他作者は各3作品のまま維持する。work/dialogue/audio IDの衝突、別作者参照、未accepted work、未知authorを拒否する。

既存宮沢画像のpath・bytes・SHA・provenance・creditをv0.3.0 projectionとexact比較し、F004側にauthor/artwork/provenanceの新規entryを許可しない。`batch-public.ts`の同一author mergeを共通契約として使用し、作者・作品固有のapplication exportや条件分岐を作らない。

### DES-F004-008: 注意表示・初期全閉・単一音声UX [REQ-F004-010][REQ-F004-015]

3作品の作者画面、作品panel、creditsへ、括弧発話の抜粋であり全文朗読・要約ではないこと、題材・表現は原作由来であることを固定text keyからtext nodeで表示する。青空文庫、底本、入力/校正、VOICEVOX、非公式表示を既存generic rendererへ追記する。

全作者routeは遷移・直アクセス・再読込・back/forward後に`details.work-panel[open]`を0件とし、利用者操作時だけ展開する。既存単一Audio controllerを再利用し、ユーザー操作前の音声取得0、同時再生1、route切替時のpause/currentTime=0/src解除、古いeventの無視、404の個別隔離を維持する。

### DES-F004-009: お気に入り状態と端末内永続化 [REQ-F004-018][REQ-F004-019][REQ-F004-021]

お気に入りidentityはCatalogの既存`dialogue.dialogueId`だけを使用し、DOM順や表示文から再生成しない。各台詞にbuttonを配置し、未登録/登録を`aria-pressed=false|true`、固定可視ラベル、状態classで一致させる。pointerとEnter/Spaceで同一toggleを呼び、お気に入り操作から音声再生を呼ばない。

永続形式はlocalStorage exact key `bungo-zundamon:favorites:v1`、canonical JSON `{version:1,dialogueIds:string[]}`、最大5000 IDとする。読込rawはJSON parse前に262144 UTF-16 code unit以下を検査し、超過時はparseせず破損扱いにする。保存前に文字列、ID長1〜128 code unit、既存`DialogueId` validator、重複、件数を検査し、Catalog順でunique化する。保存内容に本文、作者名、音声path、日時、任意metadataを含めない。

起動時は保存IDを現行Catalogのdialogue mapへjoinし、存在するIDだけを保持する。未知ID、重複ID、未知field、未知version、malformed JSON、上限超過は安全な正規化または空状態へ回復し、同じkeyだけを置換する。localStorageの読込・書込・削除例外やquota failureでは閲覧・再生を止めず、当該ページ寿命のmemory stateへ縮退し、利用者へ非阻害の状態説明を出す。

`FavoriteController`はapplication mount時に1個だけ生成し、初回読込、snapshot、toggle、subscribe、canonical保存、memory縮退、disposeを所有する。author rendererとfavorites rendererへ同じcontrollerを`RenderContext`から注入し、画面ごとの独立状態やstorage直接操作を禁止する。

### DES-F004-010: 作者横断お気に入りroute [REQ-F004-020][REQ-F004-021]

hash route `#/favorites`を追加し、共通navigationへ可視かつkeyboard操作可能な「お気に入り」リンクを置く。現行Catalog順の登録台詞だけを作者・作品見出しとともに表示する。各項目から作者routeの対象作品へ移動でき、既存Audio controllerによる単一再生と、その場での登録解除を提供する。

元作品への明示的な利用者操作時だけ、Catalog join済み`FavoriteNavigationIntent {authorId,workId,dialogueId,activationId}`をmemoryでrouterへ渡す。既存作者hashへ遷移後、rendererがCatalogから得たDOM参照mapで対象panelを展開しsummary/台詞へfocusする。保存IDをselectorへ連結しない。intentは1回消費して破棄し、直アクセス・再読込・back/forwardには復元しないため初期全閉を維持する。0件時は登録方法と端末内保存であることを案内する。

route rendererへ渡すのはCatalog join済み`FavoriteDialogueView`だけとし、保存IDや保存文字列をHTMLとして描画しない。route変更時は既存音声を停止し、登録解除後はfocusを次項目または空状態見出しへ決定的に移す。F004追加台詞もCatalogへ現れた時点から同じ処理で登録でき、個別分岐を持たない。

## 5. 共通基盤・セキュリティ・release

### DES-F004-011: 汎用batch path・runtime tooling [REQ-F004-002][REQ-F004-006][REQ-F004-011][REQ-F004-013][REQ-F004-014]

F003固有scriptはbatch ID・manifest pathを引数で受けるgeneric commandへ移し、F004は検証済みconfig dataだけを渡す。candidate、Catalog fragment、work preview、final integration、release CLIはcanonical descriptorのpath・expected SHA・batch/feature・required stateをproduction loaderが再検証してmintした`VerifiedBatchDefinition`と`VerifiedApprovalBindingPolicy`だけを入力にする共通loader/commandへ統合する。caller提供のdefinition/policy objectを信用しない。

作者の`introduce|reuse`はcaller指定ではなく、baselineとのidentity joinから導出する。0件は検証済み新作者画像・provenanceを伴う`introduce`、exact 1件は`reuse`、複数またはidentity差は拒否する。`VerifiedBatchDefinition.authorExpectation`はApproved文書bindingから検証し、F004は`reuse`以外を拒否する。

Catalog fragment projectorは副作用なしで、`work-preview`と`final`をbrand型で分ける。previewは先行accepted workと現在の検証済みstaged work 1件だけをmanifest順に含め、受入判定へhashを渡す。finalは全manifest work acceptedを必須にする。previewをaccepted/final fragmentとして流用できない。`batch-runtime.ts`の`manifest.batchId === 'F003'`によるvoice diff path投影を廃止し、全batchで`projectBatchArtifactPaths(workspace, manifestIdentity, persistedRelativePaths)`を使用する。

永続JSON/YAMLへ絶対path、drive letter、backslashを保存しない。workspace相対POSIX pathをschema検証し、filesystem API直前だけ`resolveWorkspacePath`で絶対化する。空segment、`.`、`..`、先頭slash、scheme、authority、query、fragment、percent encoded separator/control、symlink/junction/reparse、workspace外component identityを拒否する。writerとreader、forecastとvoice、previewとacceptは同一path fixtureを共有する。

### DES-F004-012: セキュリティ・4 browser自動受入 [REQ-F004-015][REQ-F004-017][REQ-F004-018][REQ-F004-019][REQ-F004-020]

runtimeはtext node、同一origin asset、既存CSPを維持し、`innerHTML`、inline handler、`eval`、外部TTS、Cookie、form、analyticsを使用しない。localStorageはお気に入りmoduleのexact keyだけに限定し、保存値をURL、selector、DOM、asset pathへ直接渡さない。外部linkはcanonical HTTPS allowlistと`rel="noopener noreferrer"`を必須にする。

security checkerは専用keyのversioned schemaアクセスだけを許可し、他storage key、保存本文、外部送信を拒否する。frozen lockfile、build時network 0、Actions最小権限、`persist-credentials:false`、全`uses:`40桁SHA pin、tracked/untracked/dist/upload manifestのsecret scan、依存Critical/High 0を維持する。

Chromium、Firefox、WebKit、Android相当、390×844・844×390・1440×900、keyboard、reduced motionで`#/`、3作者、`#/favorites`、`#/credits`の6 routeを自動試験する。初期open 0、toggle、再読込永続化、破損/未知version/quota、音声単一性、back/forwardを含む。手動・実機・目視・聴取・手動スクリーンリーダーを必須証跡にしない。

### DES-F004-013: exact candidate段階release [REQ-F004-001][REQ-F004-005][REQ-F004-012][REQ-F004-017][REQ-F004-020]

3 work acceptedかつお気に入り実装・全自動試験PASS後にsource commitを固定し、clean checkoutでF004だけを既published batchへ統合する。release commit、catalog/content tree/dist SHA、runtime route digest、hosted run/artifact/digest、権利predeploy、容量actual、UT/IT/QTを同一tupleへ結合する。caller供給のPASSではなくcanonical artifactを再読込して再計算する。

ゲート④承認前に既公開v0.3.0のcommit/artifact ID/digest/deployment IDと再deploy可能性をrollback descriptorへ固定する。承認後だけmainへfast-forwardし、既存GitHub Pagesへ1回段階deployする。公開6 route、宮沢6作品、他作者各3作品、初期open 0、お気に入りempty/toggle/reload、Catalog、画像、追加音声Range、CSP・外部通信smokeを通す。お気に入りsmokeは隔離browser contextのsite dataだけを操作し、実利用者データを必要としない。

deploy変数を有効化する前に、canonical release journalを`deploy-disable-pending`としてatomic write・file syncし、repository/variable/commit/release tuple/owner/expected journal SHAを固定する。smoke失敗時は固定rollback descriptorの既知正常artifactだけを再deployし、v0.3.0の5 route/Catalog/音声Rangeを再smokeして復旧を確認する。成功・失敗・rollback成否にかかわらず`finally`相当の独立処理でdeploy変数を無効化する。無効化APIとread-back `false`の確認後だけ、expected SHA付きcompare-and-swapでjournalを`closed`へ遷移する。

release親process/端末がどの時点で停止してもpre-armed journalが残る。起動時および別processの独立cleanup entrypointはpending journalを走査し、repository/variable identityと所有tupleを再検証して無効化を冪等に再開する。closed evidenceがない限りmanifestをpublishedへ遷移せず停止・通知する。全F004 smokeかつjournal closed後だけmanifestを同じrelease tupleでpublishedへatomic遷移する。同一値は冪等、別値は競合停止する。
