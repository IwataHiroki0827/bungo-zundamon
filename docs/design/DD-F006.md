# 関数設計書 F006（中島敦3作品追加）

## 0. 再利用方針

F006は「新規作者1人・3作品追加」という構造がF003と同型であり、F005が導入したETW常時監視・native guard機構（`f005-native-guard.ts`、`native/f005-guard/`）は使わない。CHG-F005-072以降にF005自身が確立した「phase前後の実測差分による事後検証」と、実際のv0.5.0公開（CHG-F005-083）で採用された汎用release経路は、値がfeatureに依存しない汎用実装であるため直接再利用する。

以降の各`FUN-F006-*`は、DESごとの追跡用論理IDである。多くは実装として新規コードを書かず、既存関数をそのまま呼び出す（本文に既存関数名を明記する）。値（authorId・workId・release commit・catalog SHA・既存作者画像枚数等）がfeatureごとに異なるために既存モジュールを直接呼べないもの（baseline pin・author/work registry・catalog統合・route導出・artwork provenance、計7件）だけを新規コードとして定義する。実装フェーズでは、再利用する既存関数のJSDocへ`@des DES-F006-xxx @fun FUN-F006-xxx`を追記する（F003〜F005で確立済みの複数タグ蓄積規約、例: `batch-candidate.ts`の関数群）。
