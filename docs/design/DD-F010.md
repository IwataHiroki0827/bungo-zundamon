# 関数設計書 F010（梶井基次郎3作品追加）

## 0. 再利用方針

F010は「新規作者1人・3作品追加」という構造がF006〜F009と同型であり、F005が導入したETW常時監視・native guard機構は使わない。CHG-F005-072以降に確立した「phase前後の実測差分による事後検証」と、F001〜F009実績の汎用release経路は、値がfeatureに依存しない汎用実装であるため直接再利用する。

以降の各`FUN-F010-*`は、DESごとの追跡用論理IDである。多くは実装として新規コードを書かず、既存関数をそのまま呼び出す（本文に既存関数名を明記する）。値（authorId・workId・release commit・catalog SHA・既存作者画像枚数・gaiji出現位置等）がfeatureごとに異なるために既存モジュールを直接呼べないもの（baseline pin・author/work registry・source/entity/gaiji抽出・薄い受入ラッパー・catalog統合・route導出・artwork provenance、計5ファイル）だけを新規コードとして定義する。新規コードは既存命名規則（`src/content/f010-*.ts`・`scripts/f010-*.ts`）に限定し、F001〜F009が依存する共有汎用モジュールは一切変更しない。実装フェーズでは、再利用する既存関数のJSDocへ`@des DES-F010-xxx @fun FUN-F010-xxx`を追記する。

F010は新規に定義する5ファイル（`f010-baseline.ts`・`f010-source.ts`・`f010-acceptance.ts`・`f010-catalog.ts`・`f010-artwork.ts`）以外で、F009が新設した`splitOverlongF009Candidates`型の長大候補分割関数は**複製しない**（DES-F010-005・DES-F010-015参照、REQ-F010-019は非機能・非発動見込み）。
