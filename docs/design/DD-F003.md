# 関数設計書 F003（太宰治コンテンツ追加）

## 0. 共通型・path契約

| 型 | 契約 |
|---|---|
| `BatchCandidateRegistry` | `schemaVersion, candidates[]`。candidateのbatch/feature/author/work/order/URL/approval refを一意に保持 |
| `ApprovedBatchCandidate` | registryの固有値と`VerifiedClosedApproval`のfeature/target/SRS SHA/QT SHAが一致した汎用の検証済み候補 |
| `VerifiedClosedApproval` | canonical queue item projection hash、SRS/QT path+SHA、binding evidence SHAをworkspace実体からproduction loaderが再計算したbrand型 |
| `ReviewRunAuthorization` | trusted ProjectFactory coordinatorがartifact外で発行するrole/task path/run/候補/policy/prompt/tool/nonce。未使用/使用済みをatomic管理 |
| `EditorialJudgmentSet` | header `authorizationId, role, runId, candidateSetSha256, policySha256, promptSha256, toolSha256, sealedAt, artifactSha256`と全判定。producer task/judge roleはtrusted authorizationから導出し、artifactに自己申告させない |
| `EditorialJudgment` | `candidateId, decision, reasonCode, speaker, sourceAnchor, inputSha256`。run固有metadataはset headerだけに置く |
| `EditorialResolution` | semantic fields一致または第三裁定、primary/secondary/adjudication hash、reconciliation digest、final decisionを持つ |
| `VoiceEstimateProfileV2` | F002固定releaseの151 unique WAV/config/source setから校正した秒/文字、`safetyFactor>=1`、実測誤差、PCM条件、全hash。許容相対誤差は0.20 |
| `CandidateSafetyReport` | `candidateId, speechSha256, profileSha256, configHash, codePoints, estimatedDurationMs, estimatedWavBytes, limits, result` |
| `PublishedBaselineBundle` | 固定F002 release commit・catalog/content/dist SHAを信頼起点に、F001/F002の2作者・6作品・213台詞と全既存asset/refを検証した集合 |
| `ReleasePreparationContext` / `ReleaseBuildContext` / `ReleaseCandidateArtifactBinding` | F002 production型をexact keysのまま再利用する。route set digestは`ReleaseRuntimeArtifact` 2.0.0の`runtimeAcceptanceRef/runtimeAcceptanceSha256`へ入れ、payload SHAに結合する |
| `FixedBatchSource` | 既存`SourceRecord`、`AozoraMetadata`、body selector、各artifact SHAを束ね、既存source schemaを破壊せず固定原典を表現する |

workspace保存pathはPOSIX相対表現にし、filesystem API直前だけ検証済みworkspace絶対pathへresolveする。公開asset pathは公開root相対POSIX表現にし、browserでは既存`resolvePublicAssetV2`だけが検証済み`document.baseURI`またはVite base `/bungo-zundamon/`へ結合する。結果は同一originかつbase配下でなければならない。先頭slash、空segment、`.`、`..`、backslash、scheme、authority、query、fragment、percent encoded separator/control、symlink/junction/reparse pointを拒否する。生成側と消費側は同じpath fixtureを通す。

## 1. 候補・baseline

### FUN-F003-001: validateBatchCandidateRegistry(value: unknown) -> Result<BatchCandidateRegistry> [DES-F003-001]

top-level exact keys `schemaVersion/candidates`、candidate exact keys `batchId/feature/author/works/approvalBinding`、author/work/approvalの各exact keys、schema version、一意batch ID、URL/path/orderを検査する。candidate registryから公開状態を直接生成できるfieldを許さない。writerはexpected SHA、canonical JSON、temporary file、sync、rename、post-read hashを必須とする。異常は`CANDIDATE_REGISTRY_INVALID`、`CANDIDATE_DUPLICATE`、`CANDIDATE_PATH_UNSAFE`。

### FUN-F003-002: loadAndVerifyClosedApproval(workspace, queuePath, expectedQueueSha, bindingEvidence) -> Promise<VerifiedClosedApproval> [DES-F003-001]

canonical queueをworkspace境界・component identity・reparse・expected SHA付きで読み、closed itemの`id/type/status/target/target_mode/answer/approved_at` canonical projection hashを再計算する。`docs/evidence/requirements/F003-approval-binding.json`のqueue item hashと`documents[{path,sha256}]`をApprovedなSRS/QT実体へ照合し、binding artifact自身のSHAも検査する。caller供給のapproval objectを受けない。

### FUN-F003-003: selectApprovedBatchCandidateAndCreateTemplate(registry, approval: VerifiedClosedApproval, feature, gateRefs) -> BatchManifest [DES-F003-001]

registry authorは既存`BatchAuthor` exact keysを持ち、identity SHAをcanonical author fieldsから再計算する。verified approvalのqueue ID/item SHA/SRS SHA/QT SHAと一致する一意候補を選ぶ。既存generic`createNextBatchTemplate`を再利用し、status `draft`、registry順のworkを全て`pending`、stage/artifactなし、4ゲート参照付きのimmutable値を作る。F003向けapplication exportを作らない。

### FUN-F003-004: loadAndVerifyPublishedBaseline(workspace, pinnedRelease) -> Promise<PublishedBaselineBundle> [DES-F003-002]

`pinnedRelease`はF002 commit `84c985f…`、catalog SHA `1d001aac…`、content build SHA `09652af7…`、dist SHA `c60431bd…`のexact値である。`git show`相当のread-only adapterでそのGit objectと固定hashのbaseline descriptorから2作者・6作品・213台詞、全path/bytes/SHA/referenceを復元する。候補checkoutの現行publicからdescriptorを生成しない。F003混入、欠損、reparse、hash差は`PUBLISHED_BASELINE_MISMATCH`。

### FUN-F003-005: verifyPublishedInvariant(baseline, candidateTreeOrDist) -> InvariantReport [DES-F003-002]

work preview、統合tree、distのF001/F002投影をbaselineとexact比較する。比較対象・入力tree SHA・結果を結合し、不一致なら`blocked`、修復はしない。

## 2. 権利・原典・抽出

### FUN-F003-006: observeBatchBibliography(candidate, phase, context) -> Promise<BatchWorkRightsObservation> [DES-F003-003]

F002の`ProductionAozoraTransport`だけで公式CSV・作家ページ・図書カードを取得し、権利、役割、翻訳者、公開、文字遣い、author/work/URLをmanifest全作品で照合する。戻り値はbatch-levelの`BatchWorkRightsObservation`とする。userinfo/query/fragment/任意port、private/reserved IP、redirect/proxy/retry、サイズ/時間超過をtransportで拒否する。`predeploy`ではrelease commit/run IDを必須とする。

### FUN-F003-007: fixBatchSource(work, transport, expectedBibliography) -> Promise<FixedBatchSource> [DES-F003-003]

exact XHTML URLのraw bytes、HTTP/meta/書誌charset一致、fatal decodeを既存`SourceRecord`、底本・入力・校正・更新日を既存`AozoraMetadata`、本文selectorと全hashをwrapperへ保持してatomic固定する。既存SourceRecordへ未知fieldを追加しない。URL/ID混線、decode異常、selector欠落は既存sourceを保持して停止する。

### FUN-F003-008: extractOuterDialogueCandidates(source, extractorVersion) -> CandidateSet [DES-F003-004]

本文tokenから外側`「」`だけを走査し、source hash・anchor・order由来IDを決定的に生成する。本文外、壊れた括弧、単独`『』`は理由code付きexcluded recordにする。同じ入力2回のcanonical hash不一致は`EXTRACTION_NON_DETERMINISTIC`。

## 3. 独立編集判定・読み上げ

### FUN-F003-009: sealAndValidateEditorialJudgmentSet(workspace, authorization: ReviewRunAuthorization, externalResult) -> Promise<EditorialJudgmentSet> [DES-F003-005]

ProjectFactory coordinatorが別agentへ生成させたschema JSONだけを受ける。authorizationはartifact外のtrusted coordinator storeから読み、externalResult自己申告のidentityを信用しない。authorizationのrole/task/run/nonce/candidate/policy/prompt/toolと全candidate exact join、source anchorを検証し、create-new-onlyでatomic sealする。同じtransactionでauthorizationをusedへ遷移し再利用を拒否する。primary/secondary/adjudicatorのauthorization ID・task path・runを相互に別とし、secondary authorizationはprimary outputを入力refに持てない。

### FUN-F003-010: reconcileIndependentJudgments(candidates, primary, secondary, adjudication?) -> EditorialResolutionSet [DES-F003-005]

共通`candidateId/inputSha256`を照合し、`decision/reasonCode/speaker/sourceAnchor`が一致すれば確定する。run固有metadataは一致対象にしない。不一致は同一input hashかつ別identity/runの第三裁定がなければ`pending`とする。裁定は既存artifactを改変せず新規artifactとして参照する。出力reconciliation digestをreviewed stageへ結合する。

### FUN-F003-011: verifyEditorialCompleteness(candidates, resolutions) -> ReviewCompletenessReport [DES-F003-005]

全candidateをapproved/rejectedへ1対1でjoinし、pending・余分・欠落・理由なしを集計する。全て0の場合だけ`pass`。題材語だけを理由にした自動除外reason codeを禁止する。

### FUN-F003-012: applySpeechRevisions(approved, revisions) -> SpeechItem[] [DES-F003-006]

display textを変更せず、連続revisionのbefore/after、理由、入力/output hashを照合して最終speech textを作る。飛び越し・循環・別candidate混入は`SPEECH_REVISION_CHAIN_INVALID`。

### FUN-F003-013: forecastCandidateSafety(item, calibratedProfile) -> CandidateSafetyReport [DES-F003-006]

正規化speech textをUnicode code pointで数え、F002固定releaseの151 unique WAV/config/source setから作った`VoiceEstimateProfileV2`をexact schema/hash検証する。全数値はfinite safe number、`secondsPerCharacter>0`、`safetyFactor>=1`、推定/実測bytesは正数とする。`abs(actual-estimated)/estimated`を再計算して記録値と一致かつ`<=0.20`を必須にする。durationは`ceil(codePoints × secondsPerCharacter × safetyFactor × 1000)`、WAVは`44 + ceil(durationMs × 48)`。上限+1、過小/非有限profileはblocked。

## 4. 音声・容量

### FUN-F003-014: planVoiceDiff(manifest, safeItems, cacheIndex, config) -> VoiceDiffPlan [DES-F003-007]

review reconciliation digestと、各候補の`candidateId/speechSha256/profileSha256/configHash/limits/result`を再検算してplan digestへ結合する。F003 voice configはF002 releaseのconfigをcanonical複製し、source path/hashとexact tupleが一致するものだけを使う。canonical speech/configからaudio IDを作り、実体hash・bytes・duration・configが一致する既存audioだけをhitとする。

### FUN-F003-015: generateVoiceDiff(plan, loopbackClient, stage, diskGuard) -> Promise<VoiceDiffResult> [DES-F003-007]

固定ENGINE/speaker/style tupleを実APIと照合し、generation直前にreview/safety/config tupleを再検算してからmissをwork専用stagingへ最大同時1で生成する。各write前に残音声予算と必要空きを再検査し、WAV構造・duration・hashを検証する。失敗時はstagingを破棄しcache/public/accepted sourceを変更しない。

### FUN-F003-016: forecastCapacity(input) -> CapacityForecast [DES-F003-007]

追加音声、完全Pages preview、Git OID重複排除repository、単一object、work driveを整数byteで別判定する。作業ドライブrequiredは`base + max(67108864, ceil(base/10))`。警告のみは`pass_with_warning`、1停止区分で`blocked`。

### FUN-F003-017: measureActualCapacity(workspace, distPreview, voiceResult, gitAdapter) -> Promise<ActualCapacityReport> [DES-F003-007]

実WAV、完全dist、pack/loose/new object、未object化候補、free bytesを安全pathから再計測する。同一OIDは1回、候補blobは保守加算する。work reportをrelease reportへ流用せず、candidate/commit/dist SHAへ結合する。

### FUN-F003-018: verifyVoiceCompleteness(review, voiceResult, acceptedSources) -> VoiceCompletenessReport [DES-F003-007]

approved候補とaudioを全件joinし、未承認生成、失敗、欠損、孤立、重複owner、hash/config不一致を0にする。共有audio IDは同一speech/configの場合だけ許可する。

## 5. atomic受入・公開統合

### FUN-F003-019: prepareWorkAcceptance(workspace, manifestPath, workId, evidenceRefs, baseline) -> PreparedWorkAcceptance [DES-F003-008]

既存F002 discriminated evidence契約を汎用化する。exact pathは`content/batches/{batch}/work-artifacts/{work}/reviews/{primary,secondary,adjudication}.json`、同work rootの`review-reconciliation.json/candidate-safety.json/voice-completeness.json/capacity-actual.json/baseline-content.json/baseline-dist.json`だけを許可する。原artifactを再読込し、schema/tool/input hashと実体path/SHA/bytesを各production validatorで再計算したbranded typeだけを使う。manifest順、直前work accepted、全hash chainを検査し、caller供給の`pass`値は受けない。

### FUN-F003-020: promoteVerifiedWorkArtifacts(workspace, prepared, expectedManifestSha) -> Promise<BatchManifest> [DES-F003-008]

exclusive lock下でaccepted audio・証跡・manifestをrandom stagingとjournalへ用意し、sync・rename・postwrite hashで一括昇格する。manifestを`accepted`へ直接飛ばさず既存状態機械へ証跡付きで渡す。

### FUN-F003-021: recoverWorkAcceptance(workspace, journal) -> Promise<RecoveryResult> [DES-F003-008]

journal phase、expected old/new SHA、所有stage identityから旧版または完成新版へ収束する。文学的未完flagを処理状態へ使用しない。第三者変更・不明owner・hash不一致は隔離して停止する。

### FUN-F003-022: buildIntegratedPublicTree(baseline, publishedBatches, activeCandidate, mode) -> Promise<IntegratedTree> [DES-F003-009]

F001/F002 publishedとactive candidateをbatch順に統合し、author/work/dialogue/audio/provenance/license/artworkの参照と実体を検証する。既存`batch-public.ts`のF002固定introducedByBatch/artwork条件をmanifest identityへ汎用化する。Catalog 2.1.0の`completionStatus/notices[]`をfragmentへ運び、author identity衝突、別作者work混入、未accepted work、未published batch混入を拒否する。

### FUN-F003-023: validateWorkNoticesAndCredits(catalog, publicTree) -> NoticeReport [DES-F003-009]

Catalog loader、work validator、作品一覧、作品画面、creditsのgeneric notice rendererを通し、`completionStatus/notices[]`とprovenanceを同一origin実体へjoinする。表示文字列は固定`textKey`辞書からtext nodeで生成する。external source linkは用途別canonical HTTPS allowlist型だけを受け、`noopener noreferrer`を強制する。必要routeに1件でも欠ければblocked。

### FUN-F003-024: verifyArtworkProvenance(provenance, manifestIdentity, inputs, output) -> ArtworkReport [DES-F003-009]

F002 schema 2.0.0はread-only互換で維持し、F003 schema 3.0.0はmanifest由来`batchId/authorId/outputPath`と`machineReview`を検証する。machine reviewのagent task/run/model/image/policy/prompt/tool/hashをtrusted coordinator記録と照合し、humanReviewなしを許す一方、machineReview欠落を拒否する。allowlist入力、prompt/recipe/provider/version/license/credit、全hashと公開outputを照合する。

## 6. runtime・release

### FUN-F003-025: transitionAudioAcrossRoute(controller, nextRoute, nextDialogue?) -> AudioState [DES-F003-010]

route/作者/台詞変更で現audioをpauseし、currentTimeを0へ戻し、src解除してgenerationを更新する。古いeventはgeneration不一致で無視し、対象台詞の404等だけをerrorへ隔離する。

### FUN-F003-026: verifyRuntimeSecurityAndRoutes(dist, expectedRoutes) -> Promise<RuntimeAcceptance> [DES-F003-011]

F002 security checkerとoffline builderを直接再利用し、CSP、危険DOM API、外部link、通信、Cookie/storage/form、secret、依存脆弱性、frozen lockfile、Actions最小権限、`persist-credentials:false`、全`uses:`40桁SHA pinを検査する。secret scanはtracked/untracked release入力、workflow、dist、upload manifestを対象に値を保存しない。期待routeはcatalogから導出しroute set digestへ固定し、全作者routeの初期`details.work-panel[open]`が0件であること、keyboard展開、4 browser・3 viewport・reduced motionを通す。

### FUN-F003-027: prepareRelease(workspace, context) -> Promise<ReleasePreparation> [DES-F003-012]

exact clean source commit、全work accepted、固定`PublishedBaselineBundle`不変、predeploy権利、容量、securityをproduction validatorで検査し、対象candidateだけを統合したpublicをatomic昇格してrelease commit候補を返す。他の未published batchは拒否する。

### FUN-F003-028: verifyReleaseCandidate(cleanCheckout, tuple) -> Promise<ReleaseVerification> [DES-F003-012]

F002の`ReleasePreparationContext/ReleaseBuildContext/ReleaseCandidateArtifactBinding`をexact keysのまま再利用する。`ReleaseRuntimeArtifact`をschema 2.0.0へversion upし、payload exact keysに`runtimeAcceptanceRef/runtimeAcceptanceSha256`を追加する。tracked publicを変更せず再構築し、route set digestを含む`RuntimeAcceptanceEvidence`を再計算してref/hashとpayload全体を`payloadSha256`へ結合する。content build/tree、dist、run/artifact ID、hosted artifact digest、全QT、権利・容量証跡を同じtupleへ結合する。

### FUN-F003-029: recordPublishedBatch(workspace, manifestPath, expectedManifestSha, context, approval, deployment, smoke, deployDisabled) -> Promise<BatchManifest> [DES-F003-012]

ゲート④、release context、artifact digest、deployment、catalog由来route set、catalog/artwork/audio smoke、deploy変数無効化が完全一致する場合だけpublished情報を記録する。exclusive lock、component identity/reparse/hash再検査、expected old/new SHA、journal、file sync、atomic rename、post-read hashを必須にし、既published同一値は冪等、別値はconflict。
